# 투자원장 데이터 매핑·마이그레이션 설계서 (20단계 A) — 설계와 합성 시험만, 실제 데이터 이전 0

## 1. 현재 실제 기능 (코드·시험으로 확인)
- **엔진**(`invest/ledger.js`): 매수·매도·배당·분할·종목코드 변경·입금·출금. 이동평균 원화 원가, 수수료는 매수 시 원가에 포함, 매도 수수료·세금은 매도대금에서 차감, USD 거래는 거래별 환율 필수.
- **분할**은 수량에 비율을 곱하고 원가는 그대로(시험: 10주 100원 → 2:1 분할 → 15주 원가 750 확인). **입출금**은 현금흐름만 기록하고 손익에 영향 없음.
- **미지원(표시도 미지원):** 환전 거래, 계좌 간 이동, 정정·취소 이력(`cancel` 유형은 거부됨), 세금 자동 계산.
- **계좌 독립성:** 같은 종목코드도 계좌별로 따로 계산(시험 확인).
- **앱 연결 상태:** 실제 앱에서는 위험관리 → 🧪 원장 시범(합성 데이터)만 연결. 실제 보유·가계부 `v5_ledger`와는 연결 없음. `v5_ledger`는 월별 가계부이며 투자 거래 원장이 아님.

## 2. 필드 매핑표 (읽기 전용 분석, 모듈 `has/migration-sim.js`의 `FIELD_MAP`)
| 앱 보유(`v5_gen/dom/ov/pen`) | 원장 | 상태 |
|---|---|---|
| ticker, name | ticker, name | 직접 |
| quantity | 기초 수량 | 직접(보유 수량만 알 수 있음) |
| avgPrice | 기초 평균단가 | 근사(수수료 포함 여부 불명) |
| (없음) | 원화 취득원가 | 원화 계좌는 수량×평균단가, 해외는 현재 환율 근사 |
| (없음) | 매수일·거래 이력·수수료·세금·매수 시 환율 | **없음 → "이력 미확인"** |
| (없음) | 실현손익·배당 누계 | **없음 → 0이 아니라 "이력 미확인"** |
| currentPrice | (원장 필드 아님) | 가격은 미검증 표시 대상 |
- 보유 잔고로 과거 매수·매도를 만들어 채우지 않는다. 이전은 "기초잔액(opening-balance)" 한 줄이며 그 시점부터의 거래만 원장이 계산한다.

## 3. 합성 시험으로 검증한 오류 시나리오
중복 거래 id · 초과 매도 · 매수 전 매도 · 존재하지 않는 날짜(2026-02-30) · USD 환율 누락 · 취소/정정 유형 · 종목코드 변경 후 부분 매도 · 부동소수점 소액(0.1·0.2·0.3) · 분할 후 매도 · 해외 배당 원천징수·환율 · 같은 계좌 중복 종목·중복 보유 id · 수량 0 보유(제외) · 평균단가·환율 없음(원가 계산 불가 표시). 모두 계산을 거부하거나 "계산 불가/이력 미확인"으로 표시하며 값을 만들어내지 않는다.

## 4. 이전 미리보기 (합성 전용)
실제 앱 원장 시범 화면에 "기존 보유 → 원장 이전 미리보기(합성 보유 · 저장 안 함)" 카드. 입력은 코드에 고정된 합성 보유 3건뿐이고 실제 보유는 읽지 않음. 쓰기 0건 표시. 실제 보유를 읽는 이전 화면은 **승인 A 이후**.

## 5. 영구 저장·백업 확장안 (제안만)
- 새 키 `has_ledger_v1`(JSON: `{format:'has-ledger', schemaVersion:1, events:[…], openings:[…]}`). **이번 단계 저장 0.**
- 백업 v6 확장: 선택 필드 `ledger`를 추가하되 **없어도 v6로 읽힘**(하위 호환). 구버전 앱은 모르는 필드를 무시하므로 복원 실패 없음. 기존 `JSON_KEYS` 허용 목록에 키 추가 시 구 앱이 거절하는지 호환 시험 필요(18단계 `docs/ledger-backup-compat-stage18.md` 참조).
- 복원 정책: 원장 부분이 손상되면 **전체 복원 중단**(부분 적용 금지)이 기본, 사용자가 "원장 제외 복원"을 명시 선택하면 계좌 데이터만 복원. 복원 전 사본 저널(`kst.portfolio.restoreJournal`)은 원장 키도 포함하도록 확장.
- 롤백: 이전 직전 전체 백업 + 복원 저널. 이전 취소 시 `has_ledger_v1`만 삭제하고 기존 키는 불변.

## 6. 승인 게이트(승인 A) 요청서 양식
목적 · 대상 데이터(어느 계좌, 몇 종목) · 위험(원가 근사 오차, 이력 미확인) · 비용 0원 · 시험(합성 → 사본 데이터 → 미리보기 → 확정 3단계) · 되돌리기(직전 백업+저널) · 승인 전후 차이(승인 전: 원장 시범만, 실제 기록 변경 0). 승인 문구 예: "승인 A: 일반계좌 종목 N개 기초잔액으로 `has_ledger_v1` 생성, 백업 v6 선택 필드 추가".
