# 백업 스키마 확장 설계 (16단계 작업 C) — **설계만, 적용은 승인 ② 이후**

현재 상태: 기존 앱 데이터(localStorage `v5_*`)와 백업 v6 형식·저장 경로는 **한 글자도 바꾸지 않았다**. 실험실의 초안 저장은 별도 키 `kst.lab.s16.draft` 하나뿐이다.

## 1. 기존 데이터와 신규 기록의 차이
| 구분 | 기존(v6) | 신규(제안) |
|---|---|---|
| 내용 | 보유 종목·수량·평단 등 "현재 상태" | 거래 로그(매수·매도·배당·환전) + 투자판단 기록 |
| 손익 | 상태값 기반 | 거래 로그가 충분할 때만 계산, 부족하면 "계산 불가" |
| 식별 | 종목 단위 | 거래 ID(tradeId) 단위 |
| 계좌 | 앱 구조에 따름 | 계좌 라벨(accountId) 필수, 계좌 간 합산은 명시적일 때만 |

## 2. 제안 구조 (v6 위에 선택 필드로 추가, v6 필수 필드는 불변)
```
backup.ext = {
  extVersion: 1,
  trades:   [{ tradeId, accountId, ticker, side, qty, price, currency, fxRate?, fxDate?, tradedAt, fee?, note? }],
  theses:   [{ thesisId, ticker, createdAt, reason, exitCondition, reviewAt }],
  checksum
}
```
- `ext`가 없거나 `extVersion`을 모르면 **무시**한다(구버전 앱·구 백업 모두 그대로 동작).
- 외화는 `currency`+`fxRate`(+기준일)를 거래에 같이 저장, 환산값은 저장하지 않고 계산 시 산출 → 환율이 없으면 "계산 불가".

## 3. 마이그레이션·롤백
1. 적용 전: 사용자 원본 백업을 읽기 전용으로 내려받아 SHA256 기록(원본 보존).
2. 시험 사본에서만 `ext` 생성 → 복원 시험 → 바이트 비교(`ext` 제외 부분 동일해야 통과).
3. 롤백: 신규 키/`ext` 삭제 후 원본 백업 복원. `v5_*`를 건드리지 않으므로 삭제만으로 원상태.
4. 승인 ② 전에는 운영 데이터에 쓰지 않는다.

## 4. 충돌·누락 규칙
- **중복 tradeId**: 내용이 같으면 하나로 병합, 다르면 둘 다 보존하고 "충돌" 표시 후 사용자가 선택(자동 덮어쓰기 금지).
- **누락 거래**: 매도 수량이 누적 매수 수량을 넘으면 해당 종목 손익 "계산 불가"(15단계 원장 규칙과 동일).
- **기기 교체**: 내보내기 파일 → 새 기기에서 가져오기. 가져오기 전 현재 데이터를 자동 백업 파일로 저장 안내.
- **내보내기/복원 실패**: 저장 실패 시 이전 상태 유지(실험실 초안 저장과 같은 write-then-verify).
- **세금**: 해외 양도세는 추정치 표시, 국내·연금 세금은 검증 전 계산하지 않음.

## 5. 시험 계획(승인 후)
복원 왕복 동일성, 구 백업+신 앱, 신 백업+구 앱, 충돌 ID, 부분 손상 파일, 용량 초과.
