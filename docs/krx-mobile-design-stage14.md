# KRX 공식 종목정보 — 휴대폰 안전 조회 구조 비교와 UX (14단계)

KRX 종목정보 API는 **종목 신원(이름·시장·ISIN) 확인용이며 주가 API가 아닙니다.** 이번 단계는 설계·합성 시험뿐이며 서버·키·실호출은 0입니다. 외부 인프라가 필요한 항목은 아래 "미실행 제안"으로만 둡니다.

## 구조 비교 (3안)
| 기준 | A안 휴대폰 Termux 로컬 실행 | B안 PWA 버튼 → 비공개 서버 중계 | C안 서버 없이 본인 기기 처리 |
|---|---|---|---|
| 키 보관 | 폰 앱 저장소(Termux). 폰 분실·백업 유출 위험 | **서버 비밀 저장소**(브라우저에 키 없음) | C-1: PC에서 1회 실행 후 **요약 파일만** 폰으로 → 폰에 키 없음 / C-2: 브라우저에 키 입력 → 키 노출·XSS 위험 |
| 비용 | 0원 | 서버 비용 있음(별도 승인 전 생성 금지). 참고: Cloudflare Workers 무료 플랜은 하루 10만 요청·요청당 CPU 10ms·변수/비밀 64개(2026-10-29 공식 문서 확인), 관리자 인증 구성 비용은 **미확인** | 0원 |
| 폰 편의성 | 낮음(터미널·Node 설치·명령 입력) — 일반 경로로 강요 금지 | **높음**(버튼 1개) | C-1 보통(PC 1회 필요) / C-2 높음이나 위험 |
| 유지보수 | 폰별 환경 차이, 업데이트 부담 | 서버·인증·로그 관리 필요 | 낮음 |
| 이용조건 | 개인 키 본인 사용 | 키가 서버에 있음 — 공공누리 4유형의 재배포·변경금지 준수 설계 필요 | C-2: 브라우저 직접 호출의 **CORS 허용 여부 미확인**, 키 URL 노출 가능 |
| 판정 | 선택 사항 | **최종 권고 구조** (승인·인프라 후) | **당장의 안전한 우회로는 C-1**, C-2 비권고 |

Termux는 공식 설치처가 F-Droid·GitHub이고 Google Play 판은 "deprecated"(비공식 포크)라는 개발자 공지를 확인했습니다([termux-app #4000](https://github.com/termux/termux-app/discussions/4000)). 따라서 A안은 설치 난이도와 신뢰 문제로 기본 경로에서 제외합니다. (Termux에서 이 도구가 실제로 돌아가는지는 시험하지 못했습니다 — **미확인**.)

**권고**: ① 목표 구조는 B안(관리자 인증 + 서버 비밀 저장소 + 호출 상한 3회 + 감사 로그). ② B안이 승인·구축되기 전에는 C-1(PC에서 `tools/krx-live-runner.cjs` 1회 → `krx-share.cjs summary` 결과만 폰으로)로 진행. 서버·비용은 **승인 전 미생성**, B안의 상세 인증 방식은 15단계 승인 항목입니다.

## 구현된 것: 관리자 전용 모바일 조회 모의 흐름 (`mobile-lab/`, 기본 OFF)
- 운영 앱·서비스워커·매니페스트에서 참조하지 않으며 `noindex`, CSP `connect-src 'none'`(페이지가 어떤 서버에도 연결 불가). 배포하지 않음(이 브랜치 안의 시험용 폴더).
- 흐름: 잠금(비관리자 차단) → 기준일·최대 호출(1~3) 입력 → **확인 화면**(대상 주식 73+ETF 5·기준일·호출 상한·중단 조건·"신원 확인용" 고지) → 확인 체크 → 승인하고 실행 → 진행 → 결과 요약. 클릭해도 **합성 응답만** 처리(실제 요청 0회).
- 안전장치: 관리자 세션 형식·만료(최장 30분) 검사, 승인(approvedBy=user·기준일 일치·한도·만료일 필수), 중복 클릭·단계 전환 직후 0.7초 탭 무시, 자동 재시도 없음, 일부 실패 시 남은 한도 안에서만 이어하기, 실제(비합성) transport 코드 수준 거부, 새로고침 시 다시 잠금.
- **판정 규칙은 CLI와 같은 코드**: `kr-radar/*.js`(runPlan·compareCandidates·toStates)를 `tools/build-mobile-lab.cjs`로 그대로 묶어 쓰며, 번들이 소스와 일치하는지·모바일 합계 == CLI 합계인지를 시험이 확인합니다.
- 결과·요약에는 종목 코드·이름·ISIN·원본 응답·키·URL이 없습니다(시험으로 확인).

## 데이터 상태 4단계 (섞지 않음)
`합성 시험` / `공식 종목 신원 검증` / `실제 시세 확인` / `실제 감시 활성`. 각 항목에 기준일·출처·조회 시각·실패 이유를 표시하며, 오래됨(4일 초과)·출처/기준일 없음·실패·미래 날짜는 `DATA_UNAVAILABLE`, 신호는 `HOLD`(최신처럼 표시하지 않음). 신호 점수는 "백테스트 미검증 가설". 합성·모의는 실제 집계에 들어가지 않습니다.

## 미실행 제안 (외부 인프라·비용 필요 → 15단계 승인 항목)
1. B안 서버 구축: 호스팅·관리자 인증 방식·비밀 저장소·접근 로그. 비용·약관 검토 후 순태씨 승인 필요.
2. 실제 KRX 조회(≤3회, 기준일 지정) — 키 저장 방식 결정 후.
3. 추가 후보: GitHub Actions 수동 실행 + 저장소 비밀값(미검토·미검증, 공개 저장소 로그 노출 위험 때문에 비권고).
