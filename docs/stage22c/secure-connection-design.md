# 안전한 인증·조회 연결 설계 — 실제 연결 미구현

## 현재 구현 경계
`providers/kis-auth-plan-stage22c.cjs`는 인증 경로/메서드의 합성 계획만 만든다. 키·토큰 입력이나 토큰 발급 기능은 없다. `kis-readonly-stage22c.cjs`는 승인 후보10개의 일봉 조회 계획 두 종류만 허용한다. 임의 호스트·URL·메서드·TR·통화·수정주가 인자·추가 필드를 허용하지 않는다. 요청계획은 모두 `syntheticOnly: true`다. HTTP 클라이언트·전송 함수·스케줄러·앱 연결이 없다. 주문·잔고 API나 계좌번호 필드는 추가하지 않았다.

공식 [보안 공지](https://www.truefriend.com/main/customer/notice/Notice.jsp?cmd=TF04ga000002&currentPage=1&num=41158)는 키가 주문·잔고 조회에도 사용되는 중요 정보라고 설명한다. **조회 전용 코드는 증권사 차원의 조회 전용 키를 뜻하지 않는다.** 개인 고객용 약관의 키 위임 금지를 고려하여, 향후 사용자 소유 실행 환경과 비밀 저장소 방식의 허용 여부부터 확인한다. ChatGPT·GitHub·브라우저에 키를 올려 연결하는 흐름을 만들지 않는다.

## 향후 승인된 실행기의 필수 경계
1. 개인 약관·저장·대조·무료 권리와 KIS의 허용 인증 환경을 문서로 확정한다. 별도 결정 없이 서비스 신청·계좌 개설을 하지 않는다.
2. 승인된 사용자 전용 비밀 저장소에서 별도 프로세스 메모리로만 주입한다. 저장소 이름·권한·기기 이전·복구 방법을 먼저 검토한다. 환경변수/CLI/파일에 평문을 자동 복사하는 구현은 현재 없다.
3. 인증기는 고정 인증 경로만, 시세 실행기는 고정 두 조회 경로만 전송한다. 두 모듈이 토큰 원문을 로깅하지 않도록 분리한다. 공용 주문 SDK·계좌 기능·임의 URL·리다이렉트·범용 프록시를 제공하지 않는다. OS/네트워크 정책과 목적지 고정은 배포 시 추가 구현·검증해야 한다.
4. 브라우저에는 허용된 정규화 가격/검증 상태만 전달하고 키·토큰·헤더·원응답을 보내지 않는다. 현재 앱에는 어떤 데이터도 전달하지 않는다.
5. 인증을 포함한 모든 전송 직전에 요청 장부 예약을 영구 반영한다. 네트워크 실패·타임아웃·프로세스 중단도 차감한다. 자동 토큰 갱신·리다이렉트·라이브러리 숨은 재시도·추가 페이지를 금지한다. 승인된 동작만 각각 예약한다.

## 요청 장부 구현
`request-budget-stage22c.cjs`: 전체40회, 인증 최대2회, 총 재시도8회, 요청 연쇄 재시도2회. 실패 또는 타임아웃 상태인 동일 작업만 재시도 가능하다. 성공·대기·중복·다른 종목 재시도는 거부한다. 재시도 조언은 전송이 아니며 새 예약 없이 호출할 수 없다. 상태는 reserved → ok/error/timeout, 실패 횟수 환불 없음. 날짜 변경·재시작으로 초기화하지 않는다.

`file-budget-store-stage22c.cjs`: 명시적으로 지정된 절대 경로, 신규 파일만 wx 생성, 0600, CAS 리비전, 잠금파일, fsync/원자적 이름변경, 기록 축소·변조 거부. 장부 불능·충돌·깨짐·남은 잠금은 실패로 닫는다. 미완료 예약도 계속 차감한다. 키·토큰·헤더·응답·가격·투자기록을 장부에 넣지 않는다. 장부는 향후 실행기 전용 신뢰 디렉터리의 단일 파일을 재사용해야 하며, 삭제·다른 경로 생성·전체 승인 예산 초기화는 금지한다. 저장소 소유자에 의한 임의 파일 삭제나 악성 OS까지 방어하는 구현은 아니다. 실제 동시 프로세스 경합·전원 장애·다중 호스트 환경은 미검증이다.

현재 전체40회 검증은 합성 장부에 대한 것이다. 다른 공급자까지 연결하면 동일 승인 전체 예산에 포함하도록 중앙 실행기가 연결해야 한다. 공급자별 별도40회를 배정하면 안 된다. 현재 모듈에 실전송 기능이 없으므로 실호출 예산은 사용하지 않았다.

## 응답과 오류
기존 stage22 정규화기에 위임하여 합성 표시·종목/거래소/통화/시간대 바인딩·양수 종가·해당 거래일·중복 날짜·거래일/장마감 문맥을 검사한다. 공급자 오류 메시지 원문을 결과로 복사하지 않는다. 401/403 즉시 중단, 제한/서버 오류는 기존 bounded retryAdvice와 장부를 모두 충족할 때만 재시도 계획을 제공한다. 429의 미확인/과도한 대기·횟수 초과는 중단한다. 향후 실제 응답 바인딩에는 검증된 전송 경로·마스터·달력·신뢰 가능한 수신시각이 필요하다. 합성 envelope의 플래그를 실가격 인증으로 사용할 수 없다.

기업행위 확인·독립 종가 대조·확정 시점이 불명확하면 보류한다. 합성 데이터는 항상 투자 판단 불가다. 기존 가격 신뢰도 관문을 수정하거나 완화하지 않았다. 비수정 종가가 일치해도 split-adjusted 투자 신호 요건을 충족하지 않는다.

## 기존 데이터 보호
신규 코드는 별도 Node 모듈로만 추가했다. HTML·HAS 저장소 구조·키·투자 원장·백업 스키마·인증은 변경하지 않았다. 파일 장부 시험은 OS 임시 디렉터리에서 수행하고 제거한다. 실제 사용자 브라우저나 투자자료에 접근하지 않았다. 기존 평문 인증·브라우저 저장 위험은 해결했다고 주장하지 않는다. 비밀 저장소 전환·기기 이전·암호화 복구는 후속 별도 승인 범위다.
