# 모바일 단독 시세 조회 — KIS 연결 상세 설계 (23단계)
작성 2026-11-05 · **설계 문서. 클라우드 자원 생성 0, 실전 API 호출 0, 키 접촉 0.** 채택 여부는 사용자 승인과 KIS 확인 후 결정(아래 §6).

## 0. 목표와 제약
- 갤럭시 앱만으로 국내·해외 보유종목 시세 조회·새로고침(PC 실행·파일 복사·명령어 없음).
- 모든 가격에 출처·기준일·기준시각·종류(실시간/지연/종가/미확인)를 표시. 조회 실패가 투자기록을 바꾸지 않음. 마지막 검증 가격과 현재 가격 구분. 환율 출처·적용시각 명시.
- 키·토큰은 HTML·JS 소스·localStorage·URL·GitHub·백업에 넣지 않음. 약관 제5조②(키 제3자 대여·위임·양도·누설 금지), 제5조③(시세는 본인이 직접 개발한 프로그램 등 개인 업무에 한해 사용, 제3자 제공 금지)를 지킴.
- 기존 PC 실행형 도구(`tools/kis-quote-runner.cjs`)는 보조 시험 도구로 보존.

## 1. 구조 후보 비교
| 안 | 방식 | 키 위치 | 장점 | 위험·미확인 | 판단 |
|---|---|---|---|---|---|
| A | 앱(브라우저)이 KIS를 직접 호출 | 브라우저/폰 | 서버 불필요 | 키가 폰·앱에 노출(제5조② 위반 소지), 브라우저 직접 호출 허용 여부(CORS) 미확인, 주문 가능 키 노출 | **불가** |
| B | **개인 전용 HTTPS 중계**(서버리스 함수, 예: Cloudflare Workers) | 서버리스의 암호화된 비밀값 | 앱에는 키 없음, 헤더 인증·호출 제한·허용 경로 고정 가능, 설정 자유도 높음 | 키가 외부 클라우드에 보관됨 → 약관 제5조② 해당 여부 **미확인**, 가입·배포 필요, 무료 한도·약관 **미확인** | **유력 후보(조건부)** |
| C | 사용자 구글 Apps Script 웹앱을 중계로 사용(기존 앱이 이미 보유 가격에 사용자 GAS를 씀) | 스크립트 속성(사용자 구글 계정) | 새 업체 없음, 비용 0 | 웹앱은 요청 헤더를 읽지 못해 인증 비밀을 URL·본문에 실어야 함(기존 JSONP 패턴과 같은 약점), 응답 지연·실행 한도, GAS 발신 IP가 변동되어 KIS가 IP 제한을 두면 사용 불가(**IP 제한 여부 미확인**) | 차선 |
| D | 집에 상시 켜 둔 기기(PC·미니PC)에 중계 + 터널 | 집 기기 | 키가 집 밖으로 나가지 않음 | 항상 켜 둘 기기·터널 필요(순태씨 부담 큼), 가용성 낮음 | 비권장(모바일 단독 목표와 거리) |
| E | 제3자 시세 중개 서비스 | 해당 업체 | 간편 | 시세 약관·재배포, 유료 가능, 키 문제 | 이번 범위 아님 |

## 2. 후보 B의 설계(채택 시)
```
갤럭시 앱(HAS PWA) ──HTTPS + 개인 인증 토큰(헤더)──▶ 개인 중계 ──KIS 키·토큰(서버 보관)──▶ KIS 오픈API
        ▲ 표시: 출처·기준일·시각·종류                      ▲ 허용 경로 2개만(토큰, 국내 현재가)
```
- **중계가 하는 일(전부)**: ① KIS 접근토큰 발급·캐시(24시간 유효, 분당 1회 초과 발급 제한 보도는 비공식이므로 캐시 필수) ② 허용된 종목코드(보유·관심 목록 범위)에 대해 현재가 조회 ③ 응답을 아래 **시세 계약 JSON**으로 정규화 ④ 호출 간 간격·종목 수·분당 한도 제한 ⑤ 실패 시 오류 코드만 반환.
- **하지 않는 일**: 주문·계좌·잔고·체결 호출(코드에 경로 자체가 없음, 정적 시험 필요), 키·토큰·계좌번호를 응답·로그에 출력, 시세 저장·재배포.
- **인증**: 중계 접근 토큰은 시세 조회만 가능하고 KIS 키와 무관하게 폐기·재발급 가능. 앱에서는 localStorage에 둘 수 있으나(폰 분실·XSS 위험은 남음) **KIS 키는 절대 앱에 없음**. 허용 출처(CORS)를 앱 주소로 제한, 분당 요청 상한, 토큰 주기적 교체. (Cloudflare Access 같은 추가 인증은 가입·정책이 필요해 이번 범위에서 검토만.)
- **시세 계약 JSON**(`has/quote-model.js`의 `normalize`가 받는 형태): `{ticker, market:"KR"|"US", price, currency, kind:"realtime|delayed|close|unknown", asOfDate, asOfTime, fetchedAt, source, verification:"unverified", synthetic:false}`. 공급자가 모르는 값은 null → 앱이 `미확인`으로 표시. 중계는 `verification`을 `independent-verified`로 올릴 수 없다(순태씨 대조로만).
- **캐시·한도**: 앱 새로고침 최소 간격 60초, 중계는 종목당 30~60초 응답 캐시, 한 번 새로고침에 종목을 순차 조회(한도는 공식 FAQ의 초당 10건을 넘지 않게 초당 1~2건). 하루 호출 수 상한과 초과 시 차단.
- **실패 처리**: 중계/KIS 오류·점검시간(약관 제13조: 점검시간 조회값이 실제와 다를 수 있음)이면 앱은 직전 값을 "최신이 아님"으로 표시, 평가는 마지막 검증가(추정)로 표기, 투자기록은 읽기 전용이라 변경 없음(`has/quote-model.js` 시험 완료).

## 3. 위험 검토
| 항목 | 내용 | 완화 |
|---|---|---|
| 주문 권한 | 실전 키는 주문까지 가능(약관 제3조 적용범위에 매매주문 포함). 중계·키가 침해되면 주문 위험 | ① 중계 코드에 주문 경로 없음+정적 시험 ② **시세 전용으로 신청한 별도 소액 계좌의 키 사용 가능 여부를 KIS에 문의**(키는 "계좌의 App Key"라고 안내됨) ③ 포털의 주문 제한·IP 제한 설정 유무 확인(미확인) ④ 키 재발급 절차 숙지 |
| 키 보관 | 약관 제5조②·제17조(고의·과실 유출 시 회사 면책) | 키는 중계의 암호화 비밀값에만. 앱·GitHub·백업·ZIP·채팅 금지(기존 비밀값 검사 유지) |
| 약관 해석 | 클라우드 중계가 "제3자에게 누설·위임"에 해당하는지, 시세를 중계 서버가 거치는 것이 "개인 업무" 범위인지 | **KIS 고객센터/VOC에 서면 확인 후 채택**(미확인) |
| 비용 | 무료 요금제 범위 내 가정. 한도·약관은 확인하지 못함 | 결제수단 등록 없이 무료 한도 내에서만, 초과 시 차단 |
| 시세 정확성 | 현재가 응답에 기준일·지연 여부가 있는지 확인 못함. 해외주식 시세는 별도 신청·지연 가능성(미확인) | 기준일·종류는 '미확인'으로 표시, 신호·조언에는 독립 대조 전까지 사용 금지(`usableForSignals`) |
| 환율 | KIS에서 USD/KRW를 어떻게 받을지 미확인 | 출처·적용시각 없으면 "근사" 표시(`fxView`), 별도 공급자는 승인 B 절차로 검토 |
| 가용성 | KIS 점검, 중계 장애 | 마지막 검증가 구분 표시, 재시도 없음·수동 새로고침 |
| 데이터 재배포 | 제5조③ 제3자 제공 금지 | 시세를 저장소·공개 페이지·타인 앱에 올리지 않음(`.gitignore`), 개인 기기 표시 한정 |

## 5. 확인 필요 목록(미확인)
1. 클라우드 중계가 약관 제5조②③에 위배되는지(KIS 서면 확인)
2. 시세 전용 별도 계좌·키 사용 가능 여부, 주문 제한·IP 제한 설정 존재 여부, 키 재발급 메뉴
3. 국내 현재가 응답의 기준일·지연 정보, 해외주식 시세의 신청 요건·지연·비용, 환율 제공 여부
4. 서버리스 무료 한도·약관·결제수단 요구 여부
5. 약관 제18·19조, 공식 호출 한도의 현재 값(FAQ는 2022 게시)
