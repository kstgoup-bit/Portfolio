# 한국 공식 상장목록 확보·오프라인 검증 안내 (9단계)

확인일 2026-10-29. 이번 단계에서도 **공식 검증은 0종목**입니다. 키 발급과 API 호출은 하지 않았고, 아래 절차는 순태씨가 직접 진행할 때의 안내입니다.

## 1. 공식 출처와 확인된 조건
[금융위원회_KRX상장종목정보](https://www.data.go.kr/data/15094775/openapi.do) (공공데이터포털, 원문 수정일 2026-10-28)
- 응답 항목: 기준일자, 단축코드, ISIN코드, 시장구분, 종목명, 법인등록번호, 법인명
- 이용허락: 공공누리 제4유형(출처표시·상업적 이용금지·변경금지). 제3자 무단 제공·재배포는 상업 여부와 무관하게 금지
- 인증: 서비스키 필요, 개발·운영 활용신청 자동승인(프로젝트 키 또는 개인 키 선택)
- 트래픽: 개발계정 10,000건, 운영계정은 활용사례 등록 후 증량. 초과 시 에러코드 22
- 갱신: 기준일 +1영업일 13시 이후(금요일 자료는 월요일). 같은 페이지에 '실시간'과 '일 1회'가 함께 적혀 있음

## 2. 이 데이터만으로 못 하는 일 (확인된 사실)
- 응답 항목에 **거래정지·관리종목·상장폐지·우선주 구분이 없습니다.** 코드·종목명·시장구분 존재 여부만 대조할 수 있고, 적격성(제외/보류)은 다른 공식 근거가 더 필요합니다.
- ETF는 이 데이터의 대상인지 원문에 없어서, ETF 5개는 [금융위원회_증권상품시세정보](https://www.data.go.kr/data/15094806/openapi.do) 같은 별도 출처로 확인해야 합니다(미확정).
- '변경금지' 조건이 파일을 패키지 형식으로 변환·보관하는 것을 어디까지 허용하는지 원문에 없습니다. 순태씨가 약관을 읽고 판단해야 합니다.

## 3. 오프라인 입력 절차
1. 공공데이터포털에서 직접 활용신청해 서비스키를 받습니다. **키는 채팅·코드·ZIP·저장소 어디에도 넣지 마세요.**
2. 순태씨 PC에서 기준일 목록을 CSV로 저장합니다. 헤더는 `기준일자,단축코드,ISIN코드,시장구분,종목명` (예시: `kr-radar/examples/listing-sample.csv`, 가상 데이터)
3. 패키지 변환: `node tools/kr-listing-pack.cjs <csv> <out.json> <제공기관> <데이터명> <https출처> <조회일> <이용허락 기록>` — 원본 파일 SHA-256, 행 수, 기준일을 자동 기록합니다.
4. 대조: `node tools/kr-listing-verify.cjs <out.json> [오늘날짜]` — 읽기 전용이며 저장하지 않습니다.
5. 결과 확인: matched / mismatch / not-found, 그리고 패키지 오류 목록.

## 4. 대조 규칙 (8단계 규칙 보존)
- 코드·종목명·시장구분이 정확히 같을 때만 일치(퍼지 매칭 없음)
- 기준일 10일 초과, 해시·행 수 불일치, 미래 날짜, 비https 출처, 이용허락 기록 누락 → 전체 차단
- 목록 안 중복 코드는 모호로 처리해 어떤 후보도 일치시키지 않음
- 우선주·스팩·리츠·ETN 의심 이름은 개별주로 인정하지 않고 보류
- 시장구분 표기(예: `유가증권`)나 `A` 접두 코드는 **번역하지 않고** 해당 행을 오류로 보고합니다. 임의 변환으로 일치시키지 않기 위해서입니다.
- 일치해도 활성 감시가 아닙니다. 적격성 상태 확인, 시세 권리 확정, 가격 검증을 거쳐야 합니다.

## 5. 부족 27개
공식 목록이 적법하게 확보된 뒤에만 보충 후보를 제안합니다. 지금은 73개 + ETF 5개 그대로이며 임의 종목을 만들지 않았습니다. 개별주와 ETF는 목록·기준을 분리합니다.
