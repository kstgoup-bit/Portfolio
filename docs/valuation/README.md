## 신규 구현

1. `has/valuation-engine.js`: 네트워크·저장소·DOM 없는 순수 계산 엔진.
2. `has/valuation-lab.html/js/css`: 빈 상태로 시작하는 오프라인 화면. 가상 예시를 명시적으로 선택하거나 출처 포함 JSON을 붙여 넣습니다. 기존 보유정보·키를 읽지 않습니다.
3. `has/valuation-fixtures.js`: 기술·금융·반도체·산업재·적자 성장·ETF의 **발명된** 입력. 실제 기업명/시세 분석이 아닙니다.
4. `has/valuation-integration.js`: 기존 watch engine 연결 API, 6주제 근거 검토 패킷, 기존 복귀 시뮬레이터용 수동 범위 전달.
5. `has/advisor-panel.js`: 분석실로 가는 내부 링크 1개 추가. portfolio_v5.html은 그대로입니다.

### 구현 지표

- PER, Forward PER, PBR, PEG
- ROE, ROIC, 영업이익률, 순이익률
- 매출·EPS·FCF 전년동기 성장률
- 영업현금흐름, FCF, FCF 마진, FCF 수익률
- 부채비율, 순부채, 이자보상배율
- 금융 자본규제 대비 여유, 적자기업 현금 소진 여력
- 과거 PER·동종업계 PER 범위/중앙값 상대 비교
- 52주 고점 대비 하락률, 동일 기간 시장 대비 상대 수익률, VIX
- ETF NAV 대비 프리미엄/할인과 연간 총보수
- 출처 있는 실적/전망/정상화 EPS 또는 주당 순자산·FCF에 **명시적 입력 배수**를 적용한 가치 추정 범위, 하한 대비 안전마진

PER·PBR의 기본 재료(EPS·주당 순자산)는 입력 관측값입니다. 재무제표에서 이를 자동 수집하거나 주식 수 변화·분할·희석을 보정하는 수집기는 아직 없습니다. DCF 모델도 이번 초기 구현에는 없습니다. 역사·동종업계 비교는 사용자가 동등 기준의 표본을 준비해야 하며 자동 수집하지 않습니다.

### 세 평가의 독립성

- 기업 품질: 업종별 지표·가중치와 경쟁우위/경영/논리/악재 원인 근거를 확인합니다. 주가와 VIX 변경은 품질 점수를 바꾸지 않습니다. 필수 지표가 없으면 나머지 지표로 가중치를 재배분하지 않고 점수를 보류합니다.
- 가격 매력도: 보수적 범위·안전마진을 계산합니다. 품질 점수를 적정주가로 변환하지 않습니다.
- 시장 심리: 낙폭·상대 수익률·VIX를 별도 표시합니다. 낙폭만으로 매수검토를 만들지 않습니다.
- 업종 가중치/70점 기준/위험 임계치는 **초기 연구 가설**이며 검증된 투자전략이 아닙니다. 정성 판단도 입력자가 준비한 근거이며 AI가 경쟁력을 독립 조사했다는 뜻이 아닙니다.
- 완전한 자료에서도 정량 가설 기준이 낮으면 이를 데이터 누락이라고 부르지 않고 기업 품질 추가 검토로 보류합니다.
- 다섯 출력: 입력된 공시 사실, 계산값, 규칙 해석, 불확실성/반대 시나리오, 투자자 확인사항. 외부 LLM 호출은 없습니다.

### 가격·재무 안전 장치

- 출처·기준일·단위·통화·회계기간·실적/추정·검증 상태 필수. JSON의 검증 표시는 입력자의 선언이며 엔진 자체의 외부 원문 검증이 아닙니다.
- 미래 날짜, 불가능한 날짜, 오래된 가격/실적, 숫자 문자열, 무한대, 단위 불일치 거부. 조회일만 새로 붙여 오래된 실적을 최신으로 보이지 않게 합니다.
- 분기 ×4로 PER을 만들지 않습니다. 음수/0 EPS·자본·이자비용의 나눗셈 왜곡을 피합니다. 전년동기 기초값이 0/음수이면 성장률을 보류합니다.
- 일시/특별손익 표식이 있으면 정상화 가정과 설명 없이는 가치 추정을 하지 않습니다.
- 금융: 일반기업 FCF/ROIC 대신 PBR·ROE·입력된 관할 자본기준. 반도체: 정상화 EPS와 업황 근거. 산업재: 수주 근거. 적자 성장기업: 현금 소진/성장의 질, 배수 적정가치는 보류. ETF: 개별 기업 지표를 표시하지 않고 NAV·구조·보유자산 검토.
- 분할 검토가격은 자동 10/20/30% 할인 방식이 아닙니다. 서로 다른 실적 스트레스, 보수적 배수, 시장 위험 완충 이유, 무효화 조건 3개가 입력되고 품질 조건이 충족될 때만 계산합니다. 미래 가격이나 주문가가 아닙니다.

- KIS: 기존 runner/설계는 있지만 최신 stage28 인계문서가 중계 방식 미채택과 GAS 유지 방침을 명시합니다. 실제 키 조회·토큰 발급·시세/계좌 호출을 하지 않았습니다.
- Gemini: 기존 앱의 별도 서술 자문 기능은 그대로입니다. 신규 엔진에서 호출하거나 개인정보를 전달하지 않았습니다.
- 신규 비용 0, 신규 API 호출 0. 재무 데이터의 자동 수집/이용권 검증은 다음 단계입니다.

## 검증과 한계

검증 상세는 `VERIFICATION.md`와 동봉 로그를 참고하세요. 모바일 360/390/430 및 PC 1280 시험 코드는 준비했으나 이 환경의 Chromium이 socket 권한 오류로 시작하지 못했습니다. 따라서 모바일 화면 배치, 실제 갤럭시, 시각 캡처, 실제 뒤로가기를 검증 완료라고 하지 않습니다. DOM 수준의 반복·잘못된 입력·XSS·초기화·저장소 불변 동작은 별도로 검증했습니다.

최신 stage47/48 근거·복귀 모듈의 실제 원본을 확보하기 전에는 자동 통합하지 않습니다. 현재 연동 API는 수동 검토 패킷이지 실제 복귀 계산의 완료가 아닙니다. 실제 세금·수수료·환율·전술적 투자 실패·계속 보유 기회비용은 기존 시뮬레이터의 입력/계산 검증이 추가로 필요합니다.
