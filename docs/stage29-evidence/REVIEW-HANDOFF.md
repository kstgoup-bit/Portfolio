# 클로 후속 검토 안내

이 자료는 사용자가 전달할 개발 검토용입니다. 실제 키 입력·조회·배포·main 반영 승인이 아닙니다. 기준은 원격 `2b7e3fb8b92f8b068880ec6fb0afdb3fdfe1a5cb`, 전체 트리 `d75747127248c4c15025fab0de6447554fa111a0`입니다. ZIP의 VERIFICATION.json에서 최종 로컬 커밋과 트리를 확인하세요.

1. `changes.patch`를 정확한 기준 트리에 적용하고 최종 트리가 맞는지 확인해 주세요. 현재 원격이 더 진행됐다면 변경을 덮어쓰지 말고 차이를 먼저 검토하세요.
2. 핵심 확인: 재무·논리·가치·경쟁력·비중·비용·재진입 중 하나가 없으면 축소 보류, 잘못된 종목·기간·조정 기준 거부, 10%는 점검 기준, 자기 자신을 비교지수로 사용 금지, 10년 상승을 단기 패턴으로 해석하지 않음.
3. 읽기 전용 연결의 정상 합성 예시는 기존 엔진까지 도달해야 합니다. 같은 JSON을 실제 모드로 바꾸면 미검증·판단 보류·활성 0이어야 합니다. 합성이라는 선언만으로 실제 출처를 인증할 수 없다는 한계는 유지하세요.
4. 저장소 합성 시험: 부분 손상·중복 ID/JSON 키·초과 크기·원문 변경 시 add/addReview가 원문을 덮어쓰지 않아야 합니다. 기존 투자원장과 백업 형식 차이는 없어야 합니다. 여러 탭 동시 쓰기의 원자적 보장은 아직 없습니다.
5. 종가 검토: 알려진 휴장, 미등록 출처/버전/범위, 정정 미확정, 근거 없는 final, URL/해시를 통한 자기 인증, 기존 공개 함수 우회를 모두 보류해야 합니다. 실제 자료 통과를 위해 단순 trusted 플래그를 추가하지 마세요.
6. 24단계 브라우저 시험은 예상 해시와 화면 상태를 기다리도록 바꿨습니다. 여기서는 Chromium을 실행하지 못했으므로 가능한 독립 환경에서 별도 검증이 필요합니다. DOM 통과와 모바일 레이아웃 통과를 구분해 주세요.

허용 회귀 명령은 `node tools/valuation-regression.cjs`입니다. 환경의 jsdom 의존성이 필요합니다. 변경 기능 집중 명령은 package.json의 `test:stage29-evidence`, `test:close-evidence`입니다. 네트워크를 시도하는 기존 제외 시험을 이 검토의 성공 수에 합산하지 마세요.
