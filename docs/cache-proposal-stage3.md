# PWA 캐시 분석·독립 개선안

운영 `service-worker.js`·manifest는 수정하지 않았다. 기존 워커는 네트워크 실패 시 요청 종류와 무관하게 마지막에 portfolio_v5.html을 돌려준다. JSON/JS에 HTML이 반환되어 JSON 파싱 또는 스크립트 구문 오류가 날 수 있다. 캐시명 날짜는 워커 실행 시 결정되므로 날짜 변경만으로 매일 자동 설치된다고 보장할 수 없다. 활성화는 자기 이름을 제외한 모든 캐시를 삭제하므로 다른 캐시까지 지울 위험이 있다.

`tests/cache-policy.test.cjs`는 운영 워커 코드를 VM에서 읽고 네트워크/캐시를 모의하여 JSON 요청의 HTML 대체를 재현한다. 실제 브라우저 캐시는 건드리지 않는다.

`experimental/cache-policy.cjs`는 실행 가능한 독립 정책 제안이다. **앱에서 참조/등록하지 않으며 서비스 워커 파일 자체도 아니다.** 같은 출처의 쿼리 없는 GET 탐색·정적 파일만 올바른 MIME과 정상 응답일 때 캐시한다. JSON·외부 API·비밀 쿼리는 캐시하지 않는다. 오프라인 JSON/JS 미캐시는 HTML 대신 503 application/json 오류를 반환한다. 탐색만 정확히 일치하는 캐시 HTML 또는 오프라인 안내를 사용한다. 정리 대상은 자기 네임스페이스만 고른다.

독립 시험 5개로 원본 문제 재현, 개선안의 비HTML 오류, HTML 복귀, 데이터/비밀 쿼리/타출처 캐시 제외, 타 앱 캐시 보존을 확인한다. 배포용 워커로 채택하려면 버전 매니페스트·자산 무결성·단일 릴리스 원자 갱신·오프라인 안내 UI·기존 캐시 이전/보존·실제 Android 설치 갱신 시험과 별도 승인이 필요하다. JSON 오류 응답의 content-type만으로 JS가 유효해지지는 않으므로 스크립트 미캐시는 명확한 실패로 취급한다.
