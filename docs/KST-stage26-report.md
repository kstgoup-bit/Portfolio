## 3. color 오류 (제1과제)
- **위치/경로**: `renderDashboard()`(portfolio_v5.html) 전체 수익률 막대 준비부 — `colorRanks[0..2].color`.
- **원인**: `colorRanks`는 “자산이 있는(평가액>0) 계좌” 목록인데 “전체” 막대의 그라데이션 색을 **항상 상위 3개 계좌가 있다고 가정**하고 `[1]`·`[2]`를 읽음. 자산 계좌가 1~2개면 undefined → 예외.
- **재현 조건(정확)**: 일반·ISA·해외·연금 중 자산 있는 계좌가 **1개 또는 2개**일 때만(0개·3개·4개는 정상). 16개 조합 중 10개에서 발생. main에서도 동일.
- **영향(숨겨져 있던 것)**: 예외로 `renderDashboard`가 중단되어 **시장별 요약(자산 비중 원형, 수익률 막대, 계좌 카드)이 아예 그려지지 않음**(수정 전 `#mktSummary` 높이 0, 자식 0 — 캡처 `docs/evidence-stage26/color-fix-before-2accounts-390.png`).
- **수정**: `[0,1,2].map(i => colorRanks[Math.min(i, colorRanks.length-1)].color)` — 부족한 색은 마지막 색으로 채움(1줄). 정상(3개 이상) 입력의 결과는 이전과 동일. 오류를 숨기지 않음(try/catch 아님).
- **회귀시험**: `tests/color-regression-stage26.cjs` — 계좌 조합 16가지 × (오류 0·막대 캔버스 실제 그려짐·원형·카드 수). **수정 전 코드로 6/16, 수정 후 16/16.**
- **부수 효과**: 수정으로 대시보드가 끝까지 그려지면서 앱이 스스로 쓰는 캐시(v5_benchHist)가 1~2계좌 사용자에게도 생김(3개 이상 사용자는 원래 그랬음). 이를 사용자 원장 비교에서 제외하도록 `mobile-stage20` 시험의 저장소 비교 목록을 조정(내용 약화 아님, 앱 자체 캐시 제외 원칙은 24단계와 동일).

## 6. AI 참모 데이터 정확성 (제4과제) — `tests/ai-accuracy-stage26.cjs` (13/13)
앱 자신의 함수(calcGroup·getDepositAmount·잔고 규칙)와 참모 화면을 대조:
- 환율, 계좌별 평가금액(해외 USD×환율), 전체 자산, 종목별 비중, 상위 종목 표시, 현금 합계·비중 — **일치**
- 의도적 차이 2가지를 명시·검증: ⓐ 참모의 전체 자산은 CMA 포함(앱 머리말 총액은 CMA 제외; 차이=CMA 금액, 화면에 “예수금·CMA 포함” 표기 추가) ⓑ 공격·방어: 참모는 예수금·CMA를 방어로 계산, 앱 창·방패 막대는 예수금을 종목 role(기본 창)대로 계산 → 시험 자료에서 앱 창 82.5% vs 참모 공격 52.8%(화면에 규칙 설명 있음)
- **결함 발견·수정**: CMA만 기록되고 계좌 예수금이 없을 때 현금 비중을 전체처럼 보여 주던 문제 → `cashMissingAccounts` 추가, “일부만 기록됨(예수금 없는 계좌: …)” 표시와 데이터 부족 위험 항목, 단위시험 3개
- 환율 칸이 범위 밖(100)이면 환율 경고·비중 미상·판단 보류(앱은 100을 그대로 계산에 쓰는 차이 — 참모가 더 보수적)
- 시세: 앱 입력가는 “확인된 시세가 아님”으로 표시, 검증 시세 없으면 전부 판단 보류, 읽기 전용 확인(저장 문자열 불변), 수량 0·평단 없음·손상 계좌도 판단 보류·오류 없음
