# 국장 데이터 계약 (설계, 외부 호출 없음)

구현은 `kr-radar/adapters.js`의 검증 함수와 합성 어댑터뿐이다. 실제 어댑터는 의도적으로 만들지 않았고(`createRealAdapter`는 항상 오류), 키·HTTP 클라이언트·저장소 접근이 없다.

## 가격 계약 `validatePriceBar`
종목코드, 거래일(KST), 정규장 종가, **종가와 같은 수정 기준의 52주 고가**, 수정 기준(`adjusted-consistent`), 분할·배당 처리, 거래량·거래대금, 상장주식수·유통주식, 거래상태(`normal/halt/delisted/unknown`), 벤치마크(KOSPI·KOSDAQ·업종), 조회시각, 지연(분), 출처 이름·https URL, 이용권 참조.
거부 조건: KST 아님, KRW 아님, 정규장 아님, 수정 기준 혼합, 알 수 없는 거래상태, 음수 지연, 출처 누락, 비 https.

## 공시 계약 `validateDisclosure`
접수번호(14자리), 종목코드, 공시일(KST), 구분(`original/correction`), 정정 시 대체 대상(`supersedes`), 연결/별도, 회계기간 표기·종료일, 감사의견, 배당, 자사주 취득, **실제 소각 완료 여부**, 최대주주·지배구조, 관리종목 등 이슈, 출처 URL.
정정공시는 원본 접수번호를 `supersedes`로 가져야 하며, 정정으로 대체된 근거는 점수 계산에서 무효 처리된다.

## 공시와 가격은 별개
공시 데이터(재무·지분·주주환원)와 가격 데이터(시세)는 공급 경로·권리·지연이 다르다. 한쪽의 이용권이 다른 쪽을 보장하지 않는다.

## 합성 어댑터
`createSyntheticAdapter({bars, filings})`는 계약을 검증한 뒤 깊은 복사본만 돌려준다. 네트워크를 쓰지 않는다는 것을 시험이 `fetch` 차단 상태에서 확인한다.
