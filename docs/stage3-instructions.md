## 1. 작업 목적과 최우선 순위

2단계에서 만든 **로컬 MVP를 유실 없이 계승**하고, (1) GitHub 독립 개발 브랜치 안전 반영, (2) **일반계좌를 포함한 포트폴리오 전체 백업·복원 결함 수정**, (3) 실제 데이터 연동을 위한 공급자 검증 및 **제한적 실데이터 파일럿**을 추진한다. 실제 데이터 접근이나 공급자 이용 조건을 검증할 수 없다면 연결을 강행하지 말고 검증 보고서까지만 작성한다.

**절대 금지:** `main` 변경·병합, GitHub Pages/운영 배포, 서비스 워커 운영 갱신, 실제 휴대폰 데이터 변경, 실거래·자동매수, 비밀키 커밋, 외부 유료 서비스·클라우드 자원 생성 또는 과금 승인 없는 사용.

## 3. 착수 전 검증 및 작업 중단 조건

1. GitHub 연결로 저장소를 읽고 최신 `main` SHA 및 파일 목록을 검증한다. ZIP의 `delivery.json`, 패치와 `source/`의 무결성·출처를 점검한다. 패치 적용 전후 변경 파일 목록을 기록한다.
2. 2단계 산출물을 **새 독립 브랜치** `work/kst-value-radar-stage3-20261029`에서만 이어간다. 이미 같은 이름이 존재하면 덮어쓰지 말고 새 고유 이름을 사용한다.
3. GitHub 연결이 쓰기 작업에 403을 반환하면 권한 범위와 실패 동작을 기록한다. **개인 액세스 토큰을 사용자에게 채팅으로 요구하지 않는다.** 승인된 GitHub 연결 재설정 방법을 안내하고, 원격 업로드 없이 로컬 커밋·패치·ZIP로 작업을 전달한다. 권한 실패를 우회해 `main`에 기록하지 않는다.
4. 기준선 차이, 패치 충돌, 실제 데이터 손상 위험이 확인되면 무리하게 진행하지 말고 문제·대안을 보고한다.

## 4. A — GitHub 개발 브랜치 반영

- 가능하면 2단계 코드를 독립 브랜치에 안전하게 복원하고, 3단계 수정 사항을 추가 커밋으로 분리한다.
- 원격 업로드가 가능할 때만 **Draft PR**을 만들고, 대상은 `main`으로 표시하되 **병합 금지**. PR에는 운영 배포 금지, 미연결 기능, 시험 결과와 데이터 보호 조건을 명시한다.
- 원격 업로드 불가 시 **재현 가능한 전체 소스 ZIP + 적용 패치 + 기준 커밋 + 로컬 커밋 SHA + 실행 지침**을 제공한다.
- `portfolio.html`, 운영 `manifest.json`, 운영 `service-worker.js`는 필요성 검증과 별도 승인 없이는 수정하지 않는다.

## 5. B — 기존 포트폴리오 백업·복원 결함 수정 (필수)

2단계 보고서에서 `exportData()`와 `importData()`가 **일반계좌 `genStocks`를 누락**한다는 결함이 확인됐다.

- 기존 일반·ISA·해외·연금 보유 종목, 평단, 수량, 거래 기록 및 관련 설정의 실제 저장 키·자료 구조를 코드로 확인한다. 문서의 키 목록만 믿고 가정하지 않는다.
- 기존 백업 파일과의 **하위 호환성**을 유지하면서 일반계좌 데이터가 내보내기·가져오기 왕복에서 정확히 보존되도록 수정한다.
- 새 백업의 스키마 버전, 포함 데이터 범위, 누락/손상 데이터 검증, 중복/병합/덮어쓰기 정책을 명시한다. 가능하면 **복원 전 자동 백업, 복원 미리보기, 취소·되돌리기**를 구현한다. 구현이 어렵다면 원본을 손상시키지 않는 실패 처리와 구체적인 대안을 제시한다.
- 브라우저 저장 공간 부족, 잘못된 JSON, 미래 버전, 빈 계좌, 다중 계좌, 한글/특수문자, 대량 거래, 기존 구버전 백업을 시험한다.
- **실제 사용자 계좌 데이터는 읽거나 서버에 전송하지 않는다.** 합성 데이터로 테스트하며, 기존 앱의 보유 종목·거래 내역이 초기화되는 코드가 없는지 확인한다.
- 레이더 설정 백업(`kst.radar.state`, `kst.radar.preRestore`)과 전체 포트폴리오 백업의 경계를 명확히 표시한다.

## 6. C — 실제 데이터 공급자 검토 및 제한적 파일럿

- `docs/data-provider-design.md`를 출발점으로 실제 주가 공급자 2~3곳을 비교한다: 미국 주식·ETF 커버리지, 52주 수정고가, 종가의 분할·배당 조정 여부, SPY/업종 ETF 3개월 동일 기간 비교, 데이터 지연, 일일 호출 한도, 200종목 운영 가능성, 상업/개인 사용 라이선스, 비용, 장애 대응, API 키 보관.
- **무료·유료 요금과 이용약관은 확인한 출처·조회일을 적는다.** 확인하지 못한 값은 미확인으로 둔다.
- 공급자 확정·과금·서버 구축은 사용자 승인 전에는 하지 않는다. 안전하고 약관상 허용되는 공개·무료 데이터가 검증될 때만 **최대 5개 티커의 읽기 전용 파일럿**을 별도 어댑터로 수행할 수 있다. 실제 조회한 종목·기준일·출처·성공/실패를 정확히 보고한다.
- 실제 데이터와 데모 데이터를 UI와 저장 구조에서 엄격히 분리한다. 날짜·시간대·통화·수정가격 여부·출처가 불명확하면 하락률과 점수를 표시하지 않는다. 공급자 장애·호출 한도 초과는 '평가 불가'로 표시한다.
- AI 정성 점수는 근거 문서·반대 근거·검증일이 없는 한 계산하지 않는다. 현재 16개 후보를 무근거로 '검증 완료' 처리하거나 200개 감시를 가동했다고 주장하지 않는다.

## 7. D — 레이더 품질 및 보안 보완

- 2단계의 점수(경쟁력25·성장/재무20·과잉반응15·밸류20·악재일시성10·촉매10), -20/-30/-35/-45% 하락 신호, SPY 대비 -15%p·업종 대비 -10%p 기준은 유지한다. 기준 변경은 근거·변경 영향·시험을 기록한다.
- 금융기업 및 고성장기업의 별도 적격성 검사, 위험 플래그 우선 처리, 데이터 결측 시 평가 불가 원칙을 유지한다.
- 기존 Gemini·Alpha Vantage 키가 `localStorage`에 평문으로 저장되는 위험을 **별도 보안 과제로 명시**한다. 기존 키를 추출하거나 소스·로그·PR에 기록하지 않는다. 키 관리 개선은 호환성 영향 평가와 사용자 승인 후 진행한다.
- 기존 서비스 워커의 오래된 HTML 및 JSON/JS에 HTML을 대체 반환하는 문제를 분석하고 **개선안과 독립 시험**을 작성한다. 운영 워커 변경은 금지한다.
