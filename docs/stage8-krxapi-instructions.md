# KST 투자관리시스템 8단계 — 금융위원회 KRX상장종목정보 API 보완 개발 지시서

작성일: 2026-10-29
대상: Claude(클로) 개발 작업
성격: 기존 「KST 투자관리시스템 8단계 개발 지시서」의 **추가 지시**. 기존 지시서와 충돌하면 더 엄격한 보존·보안·무배포 원칙을 적용한다.

## 1. 참고자료와 확인된 사실

첨부 자료: `금융위원회_KRX상장종목정보_활용자가이드.docx` (24쪽). 사용자가 공공데이터포털에서 해당 API의 활용 승인 화면을 제시했다. 실제 인증키는 전달하거나 소스에 포함하지 않는다.

가이드에 명시된 API:
- 서비스명: `금융위원회_KRX상장종목정보`
- 서비스: `GetKrxListedInfoService_V2`
- 기능: `getItemInfo_V2`
- 호출 주소: `https://apis.data.go.kr/1160100/GetKrxListedInfoService_V2/getItemInfo_V2`
- REST GET, XML/JSON 지원. `serviceKey` 필수, `numOfRows`, `pageNo`, `resultType`, `basDt` 등 선택적 요청 변수.
- 주요 응답 필드: `basDt`, `srtnCd`, `isinCd`, `mrktCtg`, `itmsNm`, `crno`, `corpNm`; 페이지 정보 `totalCount`, `numOfRows`, `pageNo`; 성공 여부 `resultCode`, `resultMsg`.
- 요청 `numOfRows`는 10,000건 초과 시 최대 10,000건으로 제한. 전체 조회 시 지연 가능하므로 페이지 분할·기준일 제한 고려.
- 갱신은 일 1회, 실시간이 아니며 보유기관의 영업일 데이터를 다음 영업일 오후 1시 이후 개방한다고 안내.
- **우선주 정보는 제공되지 않는다고 명시**. 외국법인 국내 법인등록번호는 없을 수 있음.
- 이용허락: 공공누리 제4유형(출처표시·비상업적 이용·변경금지). 가이드는 상업 여부와 관계없이 제3자 무단 제공 및 재배포 금지, 상업적 사용 시 KRX Data Marketplace 유료 구매 필요라고 별도 명시.

위 내용은 제공된 활용가이드에 근거한다. 데이터의 정확한 범위·계약 해석·가공 또는 캐시 허용 범위는 이 문서만으로 확정하지 말 것.

## 2. 작업 선행 조건

1. 기존 8단계 지시서대로 7단계 소스의 GitHub 업로드와 Draft PR 생성 여부를 **실제 원격 커밋·브랜치·PR로 확인**한다. 미확인 상태라면 원격에 업로드됐다고 보고하지 않는다.
2. 8단계 개발 브랜치는 확인된 7단계 커밋에서 분기한다. 기존 5·6·7단계 브랜치와 main은 변경하지 않는다.
3. 이번 보완 작업은 8단계 개발 브랜치에 추가하거나, 이미 8단계가 완료됐다면 별도의 후속 작업 브랜치에서 수행한다. 기준 커밋과 변경 범위를 보고한다.
4. 실제 API 호출, 실키 입력, 유료 구독, 외부 공개 및 운영 배포는 **사전 별도 승인 전 금지**한다.

## 3. 구현 범위

### A. 공식 종목정보 공급자 어댑터 — 비활성 상태

- `GetKrxListedInfoService_V2/getItemInfo_V2` 규격을 사용하는 공급자 인터페이스·응답 파서·스키마 검증기를 설계한다.
- 기본 동작은 **OFF / fixture-only**. 가이드의 예시 응답과 자체 합성 데이터를 이용한 오프라인 테스트만 실행한다.
- `resultCode` 성공 여부, 누락 필드, 날짜 형식, 중복 코드, 비정상 시장구분, 응답 페이지 수 불일치, 빈 응답, XML/JSON 파싱 실패, 속도제한·권한 오류를 처리한다.
- `srtnCd`의 `A` 접두 형태와 화면에 표시할 6자리 종목코드의 관계를 명시적으로 정규화하고, 원본 코드·ISIN·시장·기준일을 별도로 보존한다. 임의 코드 추론 금지.
- 종목명 변경, 기업행위, 시장 이전, 상장폐지, 거래정지 여부는 이 API만으로 모두 검증할 수 있다고 주장하지 않는다.

### B. 국내 레이더 후보 검증

- 기존 한국 주식 후보 73종목과 별도 ETF 5종목의 원본 목록을 변경하지 않고 대조 도구를 추가한다.
- 공식 응답과 일치한 경우에만 `verified`, 불일치·누락·권한제약은 `pending`, 별도 확인된 제외 사유는 `excluded`로 기록한다.
- 검증 로그에 종목코드·종목명·시장·ISIN·기준일·출처·응답 해시·검증 규칙·결과를 남기되, **원본 응답 전체의 저장·재배포는 이용조건 검토 전 제한**한다.
- 후보 100종목 목표는 유지하되, 부족한 27종목을 임의 추가하거나 공식 검증됐다고 보고하지 않는다. 공식 자료와 적법한 보완 근거가 확보된 종목만 추가한다.
- 우선주·ETF·리츠·스팩·외국법인 등은 서비스 제공 범위와 별도 확인 필요 여부를 구분한다. 특히 우선주는 API 미제공 대상으로 처리한다.

### C. 시세 데이터와의 엄격한 분리

- 본 API는 **상장종목의 식별정보 확인용**이며, 현재가·OHLC·52주 고가·거래량·수정주가·실시간 매수/매도 신호 공급자로 사용하지 않는다.
- 미국·한국 시세 공급자 검토는 기존 8단계 지시서에 따라 별도 진행한다.
- 시세 미확보·지연·권리 미확인 시 투자 판단은 `HOLD / DATA_UNAVAILABLE`로 표시하고, 실데이터 기반 분석이라고 표현하지 않는다.

### D. 이용허락·보안 검토

- 가이드 13~14쪽 이용허락과 제3자 재배포 금지, 상업 이용 조건을 개발 보고서에 그대로 정리한다.
- 개인의 내부 검증용 API 조회, 정규화 결과 저장, 데이터 변형, GitHub 커밋, 브라우저 배포가 각각 허용되는지 **확정되지 않은 항목으로 분리**한다. 필요 시 데이터 제공기관·KRX에 질의할 질문 목록을 작성한다.
- 공개 GitHub 저장소, GitHub Pages/PWA HTML·JS, 테스트 스냅샷, 로그, ZIP에 실제 `serviceKey` 또는 원본 데이터 대량 추출물을 포함하지 않는다.
- 향후 실제 API를 사용할 경우 인증키는 비공개 서버 측 환경변수 또는 승인된 비밀 저장소에서만 다루는 구조를 제안한다. 프런트엔드에 직접 키를 삽입하지 않는다.
- 가이드의 예시 값은 테스트용 문서 예시임을 표시하고 실제 조회 결과로 오인하지 않도록 한다.

## 4. 자동시험 및 수용 기준

- 기존 단계의 259개 단위시험 및 모바일 25묶음은 **기존 보고 기준**이며, 현재 브랜치에서 재실행해 실제 통과 수와 실패 수를 별도로 보고한다.
- 추가 시험: 정상 JSON/XML, 인증키 누락(합성), Unauthorized/Forbidden, 429 또는 호출량 제한, 비정상 기준일, `totalCount` 페이지 불일치, 빈 데이터, 중복 코드, 코드 접두부, ISIN 불일치, 우선주 미제공, 시장구분 변경, ETF 분리, 10,000건 페이지 상한, stale data, 데이터 권리 미확인.
- 가짜 데이터만으로 통과한 테스트를 공식 상장종목 검증 성공이나 실제 가격 감시 성공으로 표현하지 않는다.
- 실제 조회를 수행하지 않았다면 `공식 API 실조회 0회`, `실제 공식 검증 0종목`, `실제 활성 시세 감시 0종목`으로 정확히 기재한다.

## 5. 절대 금지사항

- `main` 변경·병합, 운영 GitHub Pages/PWA 배포, 실제 투자기록·localStorage·백업·복원 로직 변경.
- 실제 API 인증키 요청·공개·커밋, 사용자 승인 없는 실제 API 호출 또는 유료 서비스 생성.
- 공공데이터 원본의 제3자 무단 제공·재배포, 라이선스 미확인 데이터를 공개 ZIP에 포함.
- 실제 매매·자동주문·증권사 계좌 연결.
- 73개 후보를 100개 공식 검증으로 허위 표시하거나 API가 주가를 제공한다고 주장하는 행위.
