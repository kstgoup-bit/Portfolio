- `main` 수정·병합, 운영 배포, 운영 서비스워커 변경, 유료 가입·결제, 서버·Cloudflare 등 외부 자원 생성/변경, 인증키 발급·입력·저장, 실제 API 호출, 자동매매는 **금지**한다.
- 사용자 투자기록, 매수·매도 이력, 백업·복원 데이터의 형식 및 저장 경로를 임의로 변경하지 않는다. 기존 데이터 보호가 우선이다.
- 이번 지시서는 **코드 구현 및 오프라인·합성 시험 승인**이며, 실조회 또는 인프라 개설 승인이 아니다.

## 2. 제품 방향 — 휴대폰이 기본, PC는 선택

사용자는 삼성 갤럭시에서 홈 화면에 설치한 KST PWA를 주로 사용하며 PC 사용은 드물다. 다음을 합격 기준으로 삼는다.

1. 투자현황·곡소리/환호성 후보·종목 검증 상태·가격 갱신 상태·백업 기능을 **휴대폰만으로 이해하고 조작**할 수 있어야 한다.
2. 일반 사용자에게 터미널, Node.js, PowerShell, 파일 경로 입력을 요구하지 않는다.
3. 터치 조작, 360/390/430px, 뒤로가기, 새로고침, 오프라인 상태, 화면 회전, 글자 확대, 설치형 PWA 복귀 흐름을 시험한다.
4. 데이터의 상태를 `합성 시험`, `공식 종목 신원 검증`, `실제 시세 확인`, `실제 감시 활성`으로 엄격히 구분한다. 상태별 기준일·출처·조회 시각·실패 이유를 표시한다.
5. 데이터가 없거나 오래되면 `DATA_UNAVAILABLE` 또는 `HOLD`로 표시하며 매수·매도 신호를 생성하거나 기존 신호를 최신인 것처럼 보여주지 않는다.

## 3. 작업 A — KRX 공식 종목정보 조회의 모바일 안전 경로

### A-1. 설계 비교 및 선택

아래 3안을 보안·비용·휴대폰 편의성·유지보수·데이터 이용조건 관점에서 비교하고, **실제 서버 생성 없이** 가장 안전한 권고안을 보고한다.

- A안: 휴대폰의 Termux 등 로컬 실행. 가능 여부와 키 보호·설치 난이도를 설명하되 기본 사용자 경로로 강요하지 않는다.
- B안: 인증된 관리자만 누르는 PWA 버튼 → **비공개 서버 측 중계/실행기** → 공식 API. 키는 서버 측 비밀 저장소에만 두며 브라우저·HTML·JS·GitHub·로그·URL에 노출하지 않는다. 단, 서버와 비용은 별도 승인 전까지 만들지 않는다.
- C안: 외부 서버 없이 사용자가 본인 기기에서 처리할 수 있는 안전한 대체 경로. 브라우저의 API 키 직접 호출은 CORS·키 노출·서비스 약관 문제가 있어 무조건 안전하다고 가정하지 않는다.

### A-2. 구현 범위

- **기본 OFF인 관리자 전용 모바일 조회 화면/모의 흐름**을 독립 개발·시험한다. 운영 PWA에 공개·배포하지 않는다.
- 버튼 예시: `공식 종목정보 확인` → 조회 대상/기준일/최대 3회 호출 안내 → 명시적 승인 확인 → 진행 상태 → 결과 요약. 이번 단계에서는 클릭해도 **합성 응답만** 처리하며 실제 외부 요청은 0회다.
- 비로그인/비관리자 접근, 승인 누락, 만료 승인, 중복 클릭, 네트워크 끊김, 타임아웃, 401/403/429, 빈 응답, 잘못된 JSON/XML, 중단 후 재개를 시험한다.
- 기존 `tools/krx-live-runner.cjs`, `--preflight`, `--rehearsal`, `krx-share.cjs`와 동일한 신원 검증 규칙을 재사용하거나 차이를 문서화한다. 중복 구현으로 판정 불일치가 생기지 않도록 한다.
- 응답 원본·개인키·인증 토큰·상세 종목목록이 외부로 전송되지 않도록 보호한다. 결과 공유는 비밀값 제거 요약과 스키마 필드명만 허용한다.
- KRX 종목정보 API는 **종목 신원 확인용이지 주가 API가 아님**을 화면과 보고서에 명시한다.

### A-3. 실제 호출 승인 게이트

- 13단계 현재 국내 후보 주식 73개, ETF 5개 별도. 공식 검증 0개, 실호출 0회. 임의로 VERIFIED를 부여하지 않는다.
- 실제 조회는 **사용자의 후속 명시적 승인**, 인증 방식·비용·약관·키 저장 방식 검토, 접근 제어 확인 후 별도 단계에서만 한다.
- 실호출을 나중에 승인하더라도 최초 상한은 1~3회이며 승인 범위·기준일·중단 조건을 화면에 표시한다. 자동 재시도는 하지 않는다.

## 4. 작업 B — 실제 시세 공급자 파일럿 준비

- 미국 후보: MSFT, GOOGL, AVGO, VRT, JPM. **합성 데이터 기반**으로 공급자 인터페이스·매핑·오류 처리를 검증한다. 실제 조회·유료 구독은 금지한다.
- 한국 후보: 공식 신원 검증 완료 전에는 실거래 종목 파일럿을 확정하지 않는다. ETF 5개도 주식 73개와 구분한다.
- 미국 Twelve Data 및 한국 공식 주가 공급자의 데이터 권리·표시 가능 범위·수정주가·분할·배당·52주 고점·휴장일·시차·갱신 주기를 검토한다. 미확인 항목은 `미확인`으로 명시한다.
- 주가 공급자 장애, 값 누락, 지연, 거래정지, 잘못된 통화/거래소, 시차 오류, 이중 공급자 불일치 때 투자 신호를 중단한다.
- **종목 신원 검증 수, 실제 시세 확인 수, 실제 활성 감시 수는 각각 따로 집계**한다. 합성·모의 데이터를 실제 감시 수에 포함하지 않는다.
- 곡소리/환호성 판단의 과거 백테스트와 실거래 적합성이 검증되지 않았다면 투자 판단 정확성을 주장하지 않는다.

## 5. 작업 C — 모바일 품질과 기록 보호

- 기존 단위시험 **450/450** 및 모바일 **25/25** 재현. 실패 시 원인·재현 절차·수정 내역을 남긴다.
- 360/390/430px, 세로/가로, 터치 영역, 폰트 확대, 스크롤, 메뉴 복귀, Android 시스템 뒤로가기, PWA 재시작·오프라인·온라인 복귀, 이중 탭·중복 제출을 시험한다.
- 모바일에서 종목 검증 상태, 시세 기준일, 오류·중단 안내를 명확히 볼 수 있는지 점검한다.
- **실제 갤럭시 실기기 검증은 개발자가 원격 자동시험만으로 했다고 주장하지 않는다.** 사용자용 5~10분 점검 체크리스트를 작성하고 미실시를 표시한다.
- 합성 투자 계좌를 사용하여 매수·매도 기록, 기존 데이터 업그레이드, 백업→복원, 손상 백업 거부, 저장 실패 롤백, 오프라인 재시작, 중단 복구를 시험한다.
- 비밀정보 스캔, 의존성 취약점 검사, `main`/운영 파일/서비스워커/백업 모듈 변경 여부를 확인한다.
- 모바일 UI 프로토타입이 기존 공개 PWA에 노출되거나 비인증 상태로 열리지 않도록 접근 경계 및 기본 OFF 시험을 수행한다.

## 6. 개발 수행 순서

1. GitHub 원격 접근·13단계 브랜치/HEAD 확인. 접근 불가 시 개발을 중단하고 필요한 권한·소스 전달 방법만 보고한다.
2. 13단계 기준 테스트와 Git 변경 상태 확인.
3. A·B·C 작업을 신규 독립 브랜치에서 구현하되 운영 파일·개인 투자기록을 보호한다.
4. 오프라인/합성 시험과 모바일 자동시험을 반복 수행한다.
5. 가능하면 GitHub Draft PR 생성. 권한이 없으면 패치와 커밋 정보만 전달하고 생성했다고 주장하지 않는다.

## 8. 절대 금지 사항

실제 API 호출, 비밀키를 브라우저·저장소·로그·ZIP에 포함, 인증 없는 중계 API 공개, 사용자 승인 없는 유료 서비스/Cloudflare 자원 생성, 실제 거래 실행, main 병합, 운영 배포, 투자 기록 삭제·변형, 합성 결과의 실측 오인 표시.

**완료 판정 원칙:** ‘휴대폰에서 실제로 쓸 수 있도록 준비된 안전한 코드와 시험’은 합격할 수 있지만, 별도 승인과 실제 호출 없이 ‘공식 데이터 실조회 완료’ 또는 ‘실제 감시 가동’으로 보고해서는 안 된다.
