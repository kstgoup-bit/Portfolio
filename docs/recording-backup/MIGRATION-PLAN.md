# 운영 적용 전 자료 보존 계획

이 문서는 계획이며 실행 기록이 아니다. 이번 작업에서는 실제 사용자 저장소를 읽거나 내보내거나 삭제하거나 복원하지 않았다. main 병합, 앱 배포, GAS 배포도 하지 않았다.

## 현재 지켜야 할 사항

운영 main의 예전 백업에는 일반계좌 보유내역이 빠질 수 있다. 기존 백업이 있다는 이유로 앱 데이터 삭제, 재설치, 브라우저 초기화 또는 새 기기 복원을 먼저 진행하지 않는다. 현재 기기의 자료와 기존 백업은 그대로 둔다.

개발본의 v6 백업은 이미 일반계좌와 저장된 지수 이력을 포함한다. 그러나 개발 소스가 존재한다는 사실은 현재 운영 앱에 그 기능이 적용됐다는 뜻이 아니다. 이번 보완본으로 기존 운영 자료를 자동 이전하지 않는다.

## 별도 승인 후 검토할 순서

1. 적용할 정확한 소스 커밋과 운영 앱의 차이를 확인한다. 앱 배포와 GAS 변경의 승인은 구분한다.
2. 실제 모바일에서 먼저 합성 자료로 내보내기, 취소, 미리보기, 명시적인 복원, 되돌리기, 저장 실패와 재시작을 검증한다. PWA 설치 상태와 오프라인 모듈 로딩도 별도로 확인한다.
3. 실제 자료 보존이 별도 승인되면, 현재 기기에서 안전하게 보존할 범위와 제외 항목을 확인한다. 예전 백업 하나만으로 일반계좌가 보존됐다고 가정하지 않는다. 개인 자료를 개발 패키지나 GitHub에 넣지 않는다.
4. 기존 v4/v5/v6 백업에서 생략된 계좌나 지수 이력은 빈 값으로 추정하지 않는다. 생략은 현재 값 유지, 명시적인 빈 배열은 비우는 요청이라는 차이를 미리보기에서 확인한다. 손상·중복·미래 형식은 복원을 거절한다.
5. 수동 가격이 필요한 종목은 사용자가 종목별로 명시적으로 선택하고 실제 가격 기준 시각을 입력한다. 과거 가격의 시각을 알 수 없으면 현재 시각을 붙여 이전하지 않는다. 수동 값은 공식 종가나 검증된 실시간 시세로 승격하지 않는다.
6. 과거 누락된 자산 기록은 그대로 둔다. 매입가, 현재가 또는 보간값으로 빈 날짜의 기록을 생성하지 않는다. 기존 같은 날 기록을 새 값으로 자동 교체하지 않는다.
7. 복원 중단이나 저널 손상이 있으면 일반 앱 쓰기와 자동 시세 갱신을 중지하고 원문을 보존한다. 중단 상태를 임의로 정상으로 바꾸거나 자동 복구하지 않는다. 별도 자료 확인과 복구 승인이 필요하다.

## 알려진 한계

- localStorage는 여러 탭에 걸친 원자적 거래 저장소가 아니다. 충돌 검사와 중단 보호는 모든 동시 쓰기를 완전히 막는다는 보장이 아니다.
- 모든 기기와 브라우저에서의 저장 공간·다운로드·파일 선택·PWA 동작은 이 환경의 Node/DOM 시험으로 확인할 수 없다.
- 기존 매매 점검 기록의 별도 백업 범위는 바꾸지 않는다. v6가 모든 앱 및 레이더 기록과 비밀 설정까지 포함하는 전체 기기 백업은 아니다.
- GAS 주소, API 키, 비밀번호와 같은 비밀 설정은 이 패키지나 백업 검토 자료에 넣지 않는다.
- 지수 이력 보존은 현재 저장된 값의 보존이다. 출처·최신성·조정 기준이 확인되지 않은 과거 값이 공식 검증값으로 바뀌지는 않는다.
