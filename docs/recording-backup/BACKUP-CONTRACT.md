# HAS 백업 보존·복원 경계 계약

## 검토 기준과 이번 변경의 범위

- 검토 트리는 원격 `12cd44955f328755ab4713e7c6b39c934cc86dec`를 검증해 재구성한 로컬 기준 `3098edc06f99e9bfd1b85ccd75b67b950a59978e`이다.
- **이 트리의 기존 v6 백업은 이미 일반계좌 `v5_gen`과 지수 기록 `v5_benchHist`를 포함했다.** 이전 HTML 직접 내보내기의 `genStocks`·지수 기록 누락을 현재 v6에도 남아 있는 결함으로 설명하면 안 된다. 이번에는 별도 백업 시스템을 만들지 않고 `backup/core.js`, `backup/ui.js`를 강화했다.
- 실제 사용자의 저장소·백업은 읽지 않았다. 저장·복원·되돌리기 시험은 모두 합성 메모리 저장소에서만 수행했다. 운영 반영, 실제 복원, 자동 마이그레이션, 네트워크, 키 설정은 수행하지 않았다.

## 저장 형식과 호환성

기존 `format: "kst-portfolio-backup"`, `schemaVersion: 6`, `storage` 형식을 유지한다. 계좌 4개가 모두 필요하며, 배열 `[]`는 명시적인 빈 계좌이다. `null`은 빈 계좌를 뜻하지 않으며 거절한다.

허용 키는 기존 v6 목록을 유지한다. 계좌, 스냅샷, 입출금, 배당, 가계부, 환율 이력, 메모, 분류·투자원칙, 부채·비금융자산, 목표 비중, 지수·위험 캐시, 관련 화면·계산기 값이다. 허용되지 않은 저장 키는 내보내지 않으며 파일에 들어 있으면 거절한다.

- `v5_gen`이 일반계좌의 실제 저장 키이다.
- 지수의 실제 저장 키는 **`v5_benchHist`**, 내부 시리즈는 **`KS200`, `QQQ`, `SPY`**이다. 화면 메모리의 `NDX`는 `QQQ`에 대응하며 파일에 `NDX`로 임의 변환하지 않는다.
- 지수의 `fetchedAt`, `fetchedAtISO`는 받은 기록 그대로 보존한다. 최신 시세나 거래일 종가 인증으로 승격하지 않는다.
- v5의 기존 필드와 선택적 `genStocks`, `benchHist`를 지원한다. `benchHist`는 실제 캐시 구조를 그대로 담아야 한다. 추측한 다른 필드명은 조용히 버리지 않고 거절한다.
- v4의 기존 해석은 미리보기 계획에 남겼다. 부족한 숫자를 기존 호환 규칙에 따라 계획에서 0으로 표시하는 경우가 있으며, 파일 선택·미리보기만으로 저장하지 않는다. 실제 v4 복원·마이그레이션은 이번에 실행하지 않았다.
- 파일에서 **빠진 키는 현재 값을 유지**한다. `v5_snap`, `v5_deposits`, `v5_benchHist`, `v5_balGoals`의 **빠진 그룹도 유지**한다. 예를 들어 `snapshots:{dom:[]}`는 국내 스냅샷만 비우는 계획이며 일반계좌 스냅샷을 지우지 않는다. 빈 객체 `{}`는 모든 그룹 삭제 요청이 아니다.
- 그룹을 합치는 과정에서 JSON 공백·속성 순서는 정규화될 수 있다. 의미 있는 필드와 선택적 메타데이터 값은 그대로 유지한다. 존재하지 않는 기록, 출처, 시각을 새로 만들지 않는다.

## 기록 출처 보존

기존 `{ts,val,cost}` 기록을 계속 읽는다. 신규 수동 가격의 `pricingMode`, `manualPrice`와 스냅샷 출처 메타데이터는 삭제하거나 현재 시세로 바꾸지 않는다.

신규 스냅샷 계약은 `schemaVersion:1`, `origin`, `priceAsOf`, `recordedAt`, `quality:"unconfirmed"`, `signalHold:true`, `manualComponents`, `components`, `fx`이다. 수동 가격은 `value`, 시간대가 있는 `priceAsOf`, `currency`, `unit:"per-held-unit"`, `maxAgeDays:1..4`를 가진다. 구성 항목은 가능하면 실제 보유 ID인 `stockId`를 포함한다. 같은 종목코드라도 보유 ID가 다르면 두 항목을 구별한다. 구형 출처 메타데이터에 ID가 없으면 임의로 만들지 않는다.

알려진 메타데이터 버전·숫자·날짜·출처 조합을 검사한다. 미래 버전이나 손상된 필드는 거절한다. 허용된 기록 객체 안의 추가적인 안전한 JSON 메타데이터는 그대로 보존한다. 이 검사는 **자료 형식과 내부 일관성 검사**이며, 사용자가 입력한 출처의 진실성이나 가격의 정확성을 검증하지 않는다.

## 입력 제한과 거절

- 기존 전체 파일 한도 **UTF-8 20MiB** 유지.
- JSON 값당 최대 중첩 30, 항목 500,000, 배열 길이 50,000, 객체 속성 50,000. 계좌별 종목 수는 10,000.
- 바깥 백업뿐 아니라 `storage` 안에 문자열로 담긴 JSON도 토큰 단계에서 검사한다. 같은 속성이 두 번 나오거나 유니코드 이스케이프로 이름을 감춘 중복도 거절한다.
- 프로토타입 관련 속성, 실행 가능한 HTML 문자열, 알려진 인증정보 속성·형태, 비유한 수, 안전 범위를 넘는 수, 숫자 자리에 문자열·null, 음수 보유수량·가격, 중복 보유 ID를 거절한다.
- 지수 가격은 양수, 시각은 유효한 정수이며 시리즈 안에서 엄격히 증가해야 한다. 중복·역순 지수점과 잘못된 캐시 키를 거절한다.
- 출처 포함 스냅샷의 수동 구성과 전체 구성은 가격·출처가 일치해야 한다. 중복 ID, 잘못된 만료일수·환율, 신뢰 승격 표시는 거절한다.
- 손상된 저장 자료를 정상 메모리 대체값으로 가려서 내보내지 않는다. 검증 결과·오류에는 입력 원문이나 인증정보를 넣지 않는다.

## GAS 주소와 비밀정보

기존 v6 정책을 유지한다. API 키, 잠금 비밀번호, GAS 주소, 레이더 자료를 새 백업에 복사하지 않는다. 구형 `gasUrl` 필드는 복원 계획·저널로 옮기지 않으며 자동 복원하지 않는다는 경고를 제공한다. 현재 기기의 해당 설정을 지우거나 바꾸지 않는다.

일반 메모 등에 사용자가 비밀을 임의로 적었을 가능성을 완전히 판별하는 기능은 아니다. 알려진 키·토큰 형태는 거절하지만 **완전한 비밀 탐지나 익명화 보장을 하지 않는다.** 백업과 복원 전 사본은 개인 금융 기록이므로 공개 공유하지 않는다.

## 복원과 중단 상태

`parse()`와 `preview()`는 쓰기를 하지 않는다. `parse()` 결과는 깊게 동결된 계획이고, 검증되지 않은 임의 계획을 `apply()`로 보낼 수 없다.

`preview()`는 변경 대상의 기존 바이트와 복원 저널을 기억한다. 적용 전에 대상·저널·화면 메모리가 바뀌었으면 다시 미리보기를 요청한다. 적용할 때는 원본과 변경 예정값을 모두 가진 **버전 2 저널**을 먼저 저장·확인한다. 사본을 저장하지 못하면 계좌 자료에 쓰기 시작하지 않는다.

저장 오류 때는 이번 작업 값과 일치하는 항목만 원래대로 돌리는 제한적 처리를 한다. 기존처럼 모든 키를 먼저 삭제하지 않는다. 다른 편집이나 다른 저널이 감지되면 덮어쓰지 않고 멈춘다. 복구도 실패하면 사본을 남기고 명시적으로 알린다.

**localStorage에는 다중 키 트랜잭션이나 비교 후 교환이 없다.** 검사 사이의 아주 짧은 경쟁, 동일한 값으로 바뀌었다 돌아오는 경우, 프로세스 종료, 여러 탭 동시 작업을 완벽히 막는다고 주장하지 않는다. 복원할 때는 다른 탭을 닫는다. 버전 2 저널은 완전한 원자성을 제공하지 않는다.

- 앱 시작 시 `recover()`를 실행하지 않는다. `recover()`는 미완료 저널을 만나면 쓰기 없이 거절한다.
- 미완료·손상·지원하지 않는 저널은 일반 백업, 복원, 기록·자동 갱신을 중지한다. 보류 화면이 나타난다.
- 정상적으로 읽을 수 있는 복원 전 사본만 별도 파일로 내보낸다. 손상된 사본은 내보내기도 중단하고 원본 바이트를 보존한다. 원본을 삭제하거나 재설치하지 않는다.
- 복원 전 사본은 일반 복원 파일로 받아들이지 않는다. 별도 검토 없이 복구를 시도하지 않는다.
- 명시적 되돌리기도 버전 2의 완료된 저널이고, 이후 변경 대상이 편집되지 않았을 때만 가능하다. 과거 v1 저널로 임의 되돌리기하지 않는다.

## HTML 연결 계약

별도 모듈을 추가하지 않는다. 기존 `backup/core.js`, `backup/ui.js` 로딩을 유지한다. HTML의 통합 코드가 다음을 제공해야 한다.

1. `backupStateLoaded`는 `load()` 시작 전 false, 성공적으로 끝난 뒤에만 true여야 한다. UI는 이 값이 true가 아니면 빈 전역 배열로 원본을 덮는 백업을 만들지 않는다. 환율도 실제 `usdKrw` 입력 문자열을 검증하며 `getRate()`의 1370 대체값을 쓰지 않는다.
2. 초기 `load()`, 저장, 스냅샷, 백그라운드 시세·지수 쓰기 전에 복원 저널 보류 상태를 검사한다. 지연 로딩된 UI 이전에도 보류를 확인해야 한다.
3. `invalidateBackupRuntime()`가 이전 시세·환율·지수 콜백을 무효화한다. UI는 적용·되돌리기 **전에** 호출하며 이 함수가 없으면 적용하지 않는다.
4. 지수의 결과 합치기·재시도·표시 경로가 실행 식별자와 보류 상태를 검사해야 한다. 식별자 증가만 하고 콜백에서 확인하지 않으면 무효화가 아니다.
5. `HASBackupUI.isWriteBlocked()`와 `HASBackupUI.showBlocked()`를 사용할 수 있다. 후자는 보류 안내와 안전한 사본 내보내기 제어를 표시한다.
6. 성공 후 UI는 `load()` 다음 `benchmarkHistory={KS200:[],NDX:[],SPY:[]}`로 비우고 `loadBenchmarkCacheSync()`, `renderAll()` 순서로 갱신한다. 명시적으로 빈 지수 캐시를 복원했을 때 과거 메모리 값이 남지 않아야 한다. 백업 모듈은 보유종목·지수 이력 조회를 직접 시작하지 않는다. 다만 기존 renderAll()의 시장 카드 조회 부수효과는 남아 있다. 독립 시험에서는 이 렌더링을 가짜 함수로 바꾸었으므로 실제 렌더링의 외부 요청까지 검증했다고 주장하지 않는다.

## 실행 검증

```sh
node --check backup/core.js
node --check backup/ui.js
node --require ./tests/lib/no-network.cjs --test \
  tests/backup-contract.test.cjs tests/backup.test.cjs \
  tests/backup-compat-stage19.test.cjs tests/regression-stage13.test.cjs
```

신규 55개와 기존 45개, 총 **100개 통과**. 모든 자료는 합성이다. 네트워크 차단 훅 사용, 실제 브라우저나 사용자 저장소 미사용. 신규 UI 검사는 실제 어댑터 코드를 최소 DOM 대역에서 실행하며 시각적·모바일 브라우저 검증을 의미하지 않는다. 금지된 전체 npm 검사·네트워크 의존 검사·Chromium 실행은 재시도하지 않았다. 상위 통합 검사는 별도 보고한다.
