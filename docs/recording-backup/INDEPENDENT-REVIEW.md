# HAS 기록·백업 독립 검토

## 결과

최종 합성 검증 **32/32 통과**, 실패·취소·건너뜀 0. 외부 네트워크 시도 0. `git diff --check` 통과. 확인한 범위에서 남아 있는 차단 수준 문제는 찾지 못했다. 이는 전체 회귀, 실제 브라우저, 운영 배포 검증을 뜻하지 않는다.

검토 대상은 `has-recording-backup-20261110` 별도 작업본이다. 구현 파일은 이 검토에서 수정하지 않았다. 실제 사용자 저장소나 계좌, 키, 실제 API, 운영 환경은 사용하지 않았다. 소스 기준 해시는 `logs/audited-source.sha256`에 기록했다. 해시 이후 코드가 바뀌면 관련 검증을 다시 실행해야 한다.

## 독립 검토에서 찾아 수정된 사례

1. **KRX 우선주 코드 거절**: 저장소 기본 종목의 `00680K`가 새 숫자 전용 정규식에 걸렸다. 숫자로 시작하는 여섯 자리 영숫자 코드와 정확한 Yahoo 종목·시장 검증을 함께 적용한 뒤 합성 검증을 통과했다.
2. **같은 티커를 가진 서로 다른 보유 행의 백업 실패**: 앱은 서로 다른 ID의 동일 티커 행을 허용하지만 새 스냅샷 메타 검증은 계좌+티커를 중복으로 취급했다. `stockId`로 보유 행을 구분한 최종 스냅샷이 정확히 백업·복원된다.
3. **정상 수동 기준 일시 저장 거절**: 실제 HTML을 jsdom에서 실행하면 datetime-local 값이 `.000` 같은 소수 초를 포함해 정규화될 수 있었다. 최종 코드는 분·초·1~3자리 소수 초를 엄격하게 정규화하며 실제 날짜 오류와 빈 기준 일시는 계속 거절한다.
4. **구형 기록 원가 누락 호환**: 과거 `{ts,val}` 행의 `cost` 부재는 기존 지원 형식이다. 원래 행을 바꾸지 않고 다음 날 기록을 추가할 수 있다.
5. **복원 뒤 지연 재시도**: 성공 콜백뿐 아니라 오류 경로와 이미 예약된 재시도도 이전 입력 세대에 묶어 복원 후 실행되지 않도록 확인했다.

6. **복원 직후 자동 이름 변환으로 되돌리기 실패**: 기존 load 함수가 옛 연금 예수금 이름·티커를 자동으로 바꾸어 복원 사본과 달라졌다. 자동 변환을 제거한 뒤 복원→다시 읽기→되돌리기→다시 읽기 전 과정에서 이름·티커·분류 원문이 그대로 유지됨을 실제 HTML로 확인했다. 향후 변환은 별도 계획이다.

## 검증 범위

- 전체 JSON 및 v6 내부 문자열 JSON의 중복 키, 알 수 없는 저장 키, 잘못된 원가·지수 이력 거절.
- 빠진 구형 계좌 보존과 명시적인 빈 계좌 적용 구분.
- 과거 기록·확장 메타·벤치마크 이력의 정확한 왕복, 손상된 복원 사본 원문 보존, 미리보기 후 변경 감지.
- 수동 값·시각·통화·단위·허용 기간, 미래·오래된 값·숫자 범위 검증.
- 평균단가를 시세로 대신하지 않음, 수신 후 가격 변경 감지, 해외 자산에 수신 값과 일치하는 세션 환율 필요(시장 정확성 인증 아님).
- 같은 날 기록을 덮어쓰지 않음, 숫자 합산 한도.
- 실제 HTML 함수 실행으로 수동 입력 UI, 기록, 준비 상태 사본의 쓰기 차단, 오래된 시세 콜백·재시도 차단 확인.
- 실제 백업 UI와 `loadBenchmarkCacheSync`로 복원된 지수 값의 메모리 반영 확인. 이 사례의 일반 렌더링과 관련 없는 네트워크 효과는 stub 처리했다.
- GAS 양성 대조군, 종목·통화 불일치, 극단적인 가격, 유효하지 않은 timestamp, `00680K` 호환 확인.

## 제한과 후속 확인

- `MemoryStorage`, 오프라인 jsdom, 가짜 GAS만 사용했다. 실제 Chromium은 재시도하지 않았다. 실제 Android/PWA, 레이아웃·터치, 다중 브라우저 탭의 실제 경쟁은 확인하지 않았다.
- GAS의 거래소 코드/이름 허용 목록, 필수 `dataGranularity`, 시장 인자와 실제 Yahoo 응답의 현재 호환성은 실표본으로 확인하지 않았다. 잘못된 혼합 티커 요청이나 12개 초과 요청은 전체 거절하는 계약 변경이 문서화돼 있다.
- GAS `bars:{d,c}`는 날짜별 값이며 확정 종가·시장 최신성·공식성을 인증하지 않는다. 임의 장 마감 시각이나 과거 결측 가격을 생성하지 않는다.
- 새 백업은 검증에 실패한 자료를 자동 정리하지 않는다. 손상 사본은 보존하고 쓰기를 막지만, 검증을 통과하지 못한 사본은 앱의 정상 사본 내보내기로 내보낼 수 없다. 별도 검토가 필요하다는 안내가 제공된다.
- 실제 자료 이전, 삭제, 복원, 배포, 원격 push, 주문은 하지 않았다.

## 재실행

저장소 루트에서 기존 잠금된 개발 의존성을 사용할 수 있는 환경으로 실행한다.

```sh
node --require ./tests/lib/no-network.cjs --test tests/recording-independent.test.cjs
```

이 실행에서는 이미 설치된 jsdom을 사용했다. 실제 Chromium, 별도 설치와 외부 네트워크는 사용하지 않았다.
