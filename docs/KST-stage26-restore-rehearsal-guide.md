# HAS 26단계 — 실제 백업 복원 리허설 절차와 보고 양식 (제3과제)

현재 상태: 실제 사용자 백업 파일을 **받지 못했습니다.** 따라서 실제 파일로 리허설했다고 보고하지 않으며, 합성 백업(실제 앱이 만든 v6, 구버전 v5, 손상·미래 버전·악성 문자열)으로만 시험했습니다.

## A. 휴대폰에서 백업 파일 만들기 (현재 운영 앱에서)
1. 홈 화면의 HAS(포폴) 앱을 연다 → 아래쪽 **설정** 탭
2. **📥 백업 파일 다운로드** 버튼을 누른다 → `KST-전체백업-v6-날짜.json` 이 휴대폰 “다운로드” 폴더에 저장된다
3. 화면 아래 안내문(“4개 계좌와 저장된 기록·설정을 백업했습니다. API 키·잠금·GAS 주소·레이더는 제외합니다.”)이 보이면 정상. “백업 실패”가 보이면 **복원하지 말고** 알려 주세요(저장 자료에 손상된 항목이 있다는 뜻입니다. 앱은 손상 자료가 하나라도 있으면 백업을 만들지 않고 현재 자료를 바꾸지 않습니다).
4. 이 파일을 **GitHub에 올리거나 채팅·AI에 붙이지 마세요.** 복사본을 폰 안 다른 폴더(예: 내 파일 > 백업보관)에 하나 더 두는 것을 권합니다(원본 덮어쓰기 방지).

## B. 백업 파일 형식·필수 키·버전 (코드 기준 `backup/core.js`)
- 형식 이름 `kst-portfolio-backup`, `schemaVersion` 6, `storage` 객체 안에 키별 문자열 값
- **필수**: 일반(`v5_gen`)·ISA(`v5_dom`)·해외(`v5_ov`)·연금(`v5_pen`) 4개 계좌 모두
- 선택(있으면 복원): 배당, 가계부, 예수금, 목표 비중, 자산·부채, 메모, 투자원칙, 환율, CMA 금액, 스냅샷 등
- 제외(백업·복원 모두 안 함): Gemini 키, AlphaVantage 키, 잠금 비밀번호, GAS 주소, 레이더
- 한 항목이라도 형식이 틀리면 **전체를 거절**하고 현재 자료를 바꾸지 않음(안전하지만, 손상 한 건이 백업 자체를 막을 수 있음 → 위험 항목 참조)
- 구버전(v4/v5) 백업은 지원 키만 교체하고 없는 계좌·설정은 현재 값을 유지

## C. 원본 파일의 SHA-256 기록
- 리허설 화면(`has/restore-rehearsal.html`)이 파일을 고르는 즉시 SHA-256을 보여 줍니다(파일 바이트 기준). **그 값을 적어 두세요.** 나중에 같은 파일을 다시 고르면 같은 값이어야 하고, 다르면 파일이 바뀐 것입니다.
- 이 화면은 파일을 읽기만 합니다(수정·삭제·업로드 없음, 시험 중 두 번 읽어 내용 동일 여부도 표시).

## D. 격리된 시험 환경 (실제 앱 저장소를 건드리지 않음)
- 리허설 화면은 **가짜(메모리) 저장소**에서만 복원을 연습합니다. 브라우저의 실제 localStorage를 쓰지 않는다는 것을 정적 시험으로 확인했습니다(코드에 localStorage 문자열 없음, CSP로 네트워크 차단).
- 연습 내용: 형식 검사 → 미리보기(적용 전 상태 불변) → 적용 → 백업 내용과 항목별 완전 일치 → 백업에 없는 현재 항목 유지 → 같은 백업 반복 적용 동일 → 되돌리기로 직전 상태 복귀 → 복원 도중 저장 실패 시 자동 원복 → 사본 저장 실패(저장공간 부족) 시 복원 거부 → 잘린·미래 버전 파일 거절.
- 실제 앱에서 복원할 때의 안전장치(이미 구현·시험): 적용 전 사본을 기기에 보관, 사본 저장 실패 시 복원하지 않음, 도중 실패 시 자동 복구, “되돌리기” 버튼.
