## 좁은 수정

실행 코드 변경은 `backup/core.js`, `backup/ui.js` 두 파일뿐이다. 일일기록·GAS 연결·Dietz 계산은 이번에 바꾸지 않았다.

1. 구형 FG 문자열은 기존 공통 숫자 문법 검사와 0~100 범위 검사를 거친다. 기존 숫자형도 지원한다. 빈 문자열·공백·잘못된 형식·NaN/Infinity·범위 밖·객체·배열은 계속 거절한다.
2. FG null은 “백업에 없는 선택 설정”이다. 0이나 문자열 null로 만들지 않고, 삭제·덮어쓰기·되돌리기 대상으로 넣지 않는다. 현재 기기 값은 그대로이고 새 기기에 값이 없으면 없는 채로 남는다.
3. USD/KRW는 기존 숫자형·양수 검사를 유지한다. 현대 v7 봉투의 문자열 규약·계좌 검사·복원 일지·동시 수정 방지·API/GAS 제외 범위를 완화하지 않았다.
4. 일반계좌 누락 경고에 불완전 백업이며 새 기기 복구가 불가능하다는 점을 명시했다. 구형 복원 완료 문구도 “포함된 자료만 복원, 없는 계좌·설정은 복구된 것이 아님”으로 바꿨다.
5. 기존 보호 해시를 덮어쓰지 않았다. 현재/기준 바이트 해시와 유일한 역변환 조각을 추가해 최신 클로 기준으로 되돌린 다음 이전 보호 증명을 그대로 연결한다.

## 일반계좌 보호와 이관 보류

원래 main의 v5 내보내기는 `genStocks`를 아예 담지 않는다. 원래 가져오기 함수도 일반계좌를 복원하지 않는다. `snapshots.gen`이나 계산기 수량은 보유 종목 원본을 대신할 수 없다.

현재 기기의 일반계좌를 덮어쓰지 않고 유지하는 것은 별도 파일에 백업했다는 증거가 아니다. 합성 시험에서 기존 기기 값은 유지되지만 새 기기에는 일반계좌가 생기지 않음을 확인했다. 이 상태로 v7 전체 백업을 만들면 4개 계좌 요건 때문에 거절한다. 일반계좌가 실제 들어 있는 별도 합성 파일과의 대조 시험도 했다.

**운영 반영·기기 변경 전 필요 조건:** 변경 전 원래 자료의 일반계좌를 포함한 독립 사본이 확보되고, 그 사본이 4개 계좌의 원본을 보존하며 원래 앱/복구 경로로 되돌릴 수 있음이 검증되어야 한다. 변경 후 v7을 만들거나 현재 기기 값이 남아 있다는 사실만으로 이 조건을 충족하지 않는다. 원래 v5 가져오기만으로 일반계좌까지 되돌릴 수 있다고 안내하면 안 된다.

이번 작업은 실제 저장소를 읽거나 백업·복원하지 않았다. 따라서 이 조건은 미검증이며 이관은 계속 보류한다. 실제 자료 접근·보존·복원과 운영 배포는 별도로 허용된 절차가 필요하다. 없는 과거 자료를 추정·합성해 복구하지 않는다.
