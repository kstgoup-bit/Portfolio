# KST 매수·매도 통합 투자관리 설계 — 2026-10-29

## 범위와 원칙

이번 단계는 **다음 설계와 합성 계약 시험**이다. 기존 매수100점 배점·매도 연구·4계좌·백업v6·운영 HTML·manifest·SW를 변경하지 않는다. 실제 보유 연결·세금 자동 계산·실데이터 신호 활성화·자동매매는 구현하지 않는다. 신규 화면/운영 메뉴도 추가하지 않는다.

`management/review.js`는 외부 I/O가 없는 합성 연구 함수다. 기존 매수/매도 엔진을 호출하거나 실제 계좌를 읽지 않고, 미래의 검토 결과 봉투(envelope)를 어떻게 병합할지 시험한다. 실제 엔진의 입력 변환/동일 종목 연결/근거 전달은 **미구현**이다. `PLAN-DEMO-*` 합성 대상, 명시적 합성 계좌 정책, 기준 거래일, 가치평가 확인 상태만 받는다. status는 검토 정보이며 order=null, automaticAction=false, actualActiveCount=0이다. 이 0은 합성 계약이 실제 감시를 활성화하지 않는다는 뜻이며 실운영 상태 조회값이 아니다. 실제 레지스트리의 활성0은 별도로 확인한다.

## 계좌 정책

| 영역 | 연금 장기 코어 | 해외 직접투자 새틀라이트 |
|---|---|---|
| 목적 | 장기 복리·노후 현금흐름의 기반 | 별도 위험 예산 안에서 기회 검토 |
| 목표/최대 비중 | 사용자별 명시값 필요, 자동 기본 투자한도 없음 | 사용자별 명시값 필요, 코어 자산의 위험예산 잠식 금지 |
| 검토 | 장기 논리·정기 자산배분·현금흐름 | 논리·가치·집중·교체 비용과 환율 |
| 세금/제약 | 인출·계좌 제약은 후속 검토 | 해외 세금·환전·비용은 후속 검토 |
| 승인 전 | 정책 검토 대기, 실제 행동 변경 없음 | 동일 |

합성 함수의 reviewConfirmed는 시험 입력 확인이며 **실제 사용자 승인 기록이 아니다**. 함수는 역할을 구분해 반환하지만 역할별 자동 매매/차등 점수/강제 보유기간을 적용하지 않는다. 실제 한도 승인·저장과 계좌별 종목 합산은 후속 설계다. 현재/목표/최대 비중은 0~1, 목표≤최대; 현재−목표 차이만으로 매수/매도를 만들지 않는다. 전체 목표합계·계좌간 중복·통화 환산은 미구현이다.

## 통합 검토 상태

| 상황 | 표시 | 금지되는 해석 |
|---|---|---|
| 결측·4달력일 초과·미래·합성/실제 혼입·대상/기준일 불일치·가치평가 불확실 | 평가 불가, 구체적 이유 유지 | 일부 정상 자료로 전체 가능 선언 |
| 매수 검토와 일부 매도/논리 훼손 검토 동시 | 상충 근거 재검토, 양쪽 결과 유지 | 점수 상계·자동 주문 |
| 구조적 논리 훼손 검토 | 논리 근거/반대 근거 재검토 | 단기 주가하락을 구조 악화로 단정 |
| 명시 최대비중 초과 또는 매도 엔진의 비중 검토 | 비중 점검 | 강제 축소·수량 계산 |
| 매도 연구의 일부 매도 검토 | 근거·대안·세금·비용 재검토 | 실제 매도 신호 발생 주장 |
| 매수 검토 | 매수 근거 검토 | 목표비중 미달 자체를 매수 신호로 해석 |
| 그 외 근거 정상 | 장기 보유 검토 | 수익/안전 보장 |

입력 봉투는 buy.status=review/none/unavailable 및 sell.status=5단계 검토상태다. mode=synthetic, 동일 companyId/asOf가 필수다. 합성 예의 가격 최신성은 단순 4달력일 제약이며 휴일/조기폐장/정규장 캘린더 검증의 대체물이 아니다. 리뷰봉투가 실제 원자료를 정직하게 요약했는지를 함수가 인증하지 않는다. 다음 단계에는 근거 문서·출처·확인일·결측·반대근거의 공통 참조 id 및 버전까지 검증해야 한다.

+20/+30/+50/+100/+200%는 기존 매도 연구의 **알림 예시**로만 남긴다. 통합 함수는 수익률 입력을 판단에 사용하지 않는다. 불확실한 가치평가나 오래된 시세를 상승률로 덮지 않는다.

## 목표와 장기 관리

중기 목표는 **5년 내 투자자산 10억 원(KRW, 명목)**이다. 목표 정의(예수금 포함 여부, 부채 차감 여부), 시작 투자자산, 납입·인출 가정, 세후/비용 후 수익 가정은 사용자가 확인해야 한다. 이번 단계에서 실제 자산을 읽거나 달성 확률을 산출하지 않았다. 60개월이라는 기간을 코드의 확정 수익률 또는 강제 매매 기준으로 쓰지 않는다.

후속 시나리오의 월말 납입 가정식: V(m+1)=V(m)×(1+r(m))+납입(m)−인출(m)−세금/비용(m). 이는 가정에 따른 산술이며 예측·달성 보장이 아니다. 음의 수익·현금유출·물가·환율 시나리오를 함께 보여주고, 부족분을 레버리지로 채우도록 유도하지 않는다. 실제 목표 계산기·세금 엔진은 미구현이다. 목표 달성 후에도 투자 기간을 종료하지 않고 장기 성장과 안정적 노후 현금흐름을 함께 관리한다. 생활비/연금/인출률 연결은 별도 사용자 확인과 설계가 필요하다.
