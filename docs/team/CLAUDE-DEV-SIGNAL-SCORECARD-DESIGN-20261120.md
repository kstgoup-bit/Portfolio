# 곡소리 신호 성적표 설계서 (A안) — 클로, 2026-11-20

상태: **설계만. 코드·GAS·앱 변경 없음.** 순태씨 승인(A안) 후 첫 문서. 이 설계로 만들어도 되는지 확인을 받는다.

## 1. 목적과 원칙
- 질문 하나: **"곡소리 후보(가격이 고점 대비 크게 빠진 종목)가 이후 지수보다 나았나?"** 철학("곡소리에 분할매수")을 숫자로 검증한다.
- 매수 권유가 아니다. 돈이 움직이지 않는다. 투자 원장(v5_*)을 읽거나 쓰지 않는다.
- 재료는 **정해진 규칙의 출력**(곡소리 Top 10)이다. AI의 자유 의견이 아니므로 말 바꾸기·환각이 없다. AI 의견(C안)은 재무 자료 연결 후 같은 틀에 추가한다.
- 정직 원칙: 표본이 작으면 "표본 부족"이라고 표시하고, 좋은 결과를 실력으로 단정하지 않는다.

## 2. 기록(스냅샷)
- 시점: 곡소리 계산이 새로 게시될 때마다(하루 1회, 아침). 같은 기준일(asOf)은 한 번만 기록(중복 거부).
- **기록 조건(품질 관문)** — 하나라도 어기면 그날은 기록하지 않고 사유만 남긴다.
  1. 요약 `generatedAt`이 36시간 이내
  2. 후보 행의 `status`가 `reference`(stale·자료부족 제외)
  3. `drawdownBasis`가 `bar-close-high-365d`(분할 보정된 새 기준). 옛 기준 값은 절대 기록하지 않는다.
  4. `missingCount`가 전체의 5% 이하
- 항목(후보 1개): 기록일, 기준일(asOf), 시장, 종목코드, 순위, 가격(기준일 종가), 하락률, 기준지수 종목(KR=069500, US=SPY), 기준일 지수 종가.
- 이름은 저장하지 않는다(표시 때 이름표에서 찾음).

## 3. 채점
- 평가 기간: **30일·90일·180일**(달력일). 기간 끝 ±5일 안에 자료가 없으면 "자료 부족"(점수 없음, 숨기지 않고 센다).
- 한 종목의 결과: 종목 수익률, 지수 수익률, **초과수익(= 종목 − 지수)**, 기간 중 최대낙폭.
- "신호 성공" = 초과수익 > 0 (단순 기준 하나만 쓴다. 낙폭 한도 같은 임의 임계값은 쓰지 않고 별도 지표로 보여준다).
- 가격·지수는 같은 기준의 일봉 종가. 가격 조정(분할·분배금) 미검증은 표에 그대로 적는다.

## 4. 표본을 세는 방식 (가장 중요)
- 같은 종목이 연일 Top 10에 있으면 같은 신호를 반복해서 세게 된다(독립이 아님).
- 그래서 **"신규 진입 이벤트"만 센다**: 종목이 Top 10에 5거래일 이상 없다가 새로 들어온 날. 이 날을 기준으로 채점한다.
- 표시 문구: "신규 진입 N건 중 지수 초과 M건 (승률 …%, 초과수익 중앙값 …%)".
- **N < 30이면 "표본 부족 — 참고만"**, 승률·중앙값은 보이되 결론 문구(좋다/나쁘다)를 쓰지 않는다. N ≥ 30이어도 시장 국면(하락장 등)이 한쪽이면 같은 결과가 계속된다는 보장이 없다는 문구를 항상 붙인다.
- 한계 고지: 상장폐지·거래정지 종목은 이후 가격이 없어 빠질 수 있다(생존편향). 시장(KR/US)은 따로 센다.

## 5. 저장 위치와 용량
- 추천: **GAS 스크립트 속성**에 별도 접두어(`HAS_SCORE_`)로 저장. 폰을 바꿔도 남고, 앱을 열지 않아도 매일 기록된다.
- 용량: 하루 10행 × 압축 약 25바이트 ≈ 250B, 6개월 ≈ 50KB. 단, 현재 속성 총량 한도(500KB)와 곡소리 계산 저장분(최대 약 240KB)이 있어 **점수 저장 상한을 60,000자로 고정**하고, 상한에 가까우면 채점이 끝난 오래된 스냅샷은 집계 숫자만 남기고 원본 행을 지운다. 한도 초과 시 새 기록을 거부하고 사유를 남긴다(기존 데이터는 지우지 않는다).
- 대안(앱 폰 저장소): 구현은 쉬우나 앱을 연 날만 기록되고 백업 모듈(보호 영역) 수정이 필요하다. 이 설계에서는 채택하지 않는다.

## 6. 화면
- 곡소리 탭 하단에 "곡소리 신호 성적표" 접이식 영역. 기본 문구: "기록 N일 · 신규 진입 N건 · 채점 완료 N건 (표본 부족)".
- 기록 시작일, 데이터 기준(종가·조정 미검증), 한계 문구를 항상 표시. 글자는 12px 이상, #333 이하(앱 규칙).
- 매수·매도 문구를 쓰지 않는다. 읽기 전용.

## 7. 구현 순서와 승인
| 단계 | 내용 | 승인 |
|---|---|---|
| P1 | 순수 계산 모듈 `has/signal-scorecard.js` + 시험(품질 관문, 중복 거부, 신규 진입 판정, 채점, 표본 부족, 데이터 누출 방지) | 불필요(앱·GAS 변경 없음) |
| P2 | GAS 저장·채점 초안(키 없음, 배포 안 함) + 모의 시험 | 순태씨가 붙여넣을 때 |
| P3 | 요약 `drawdownBasis` 필드 전달 + `type=scorecard` 요약 응답 + 앱 화면(읽기 전용) | "올려" |
| P4 | GAS 곡소리 파일 교체·재계산 완료 확인 **후** 기록 시작 | 순태씨 직접 작업 |

## 8. 확인하지 못한 것
- GAS 속성 총량의 현재 사용량(실측 필요), 야후 과거 일봉의 소급 정정 빈도, KR·US 휴장일에 따른 기준일 어긋남은 P2에서 시험·실측한다.
- 최소 1개월 뒤 첫 채점, 의미 있는 표본은 3~6개월 이상 소요(시간이 지나야만 생긴다).
