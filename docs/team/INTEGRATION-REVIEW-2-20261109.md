## 4. 새로 찾은 결함과 조치
1. **실제 브라우저 시험이 패치로 깨짐.** 화면이 `analyzePack`에서 `analyzeJSON`으로 바뀌었는데, 패치는 jsdom 시험의 가짜 엔진만 고치고 **Playwright 모바일 시험의 가짜 엔진은 그대로** 두었음 → "분석 엔진을 불러오지 못했습니다"로 실패. 실제 화면은 정상(진짜 엔진으로 샘플 분석 통과). 시험 쪽만 고침. 패치 쪽이 "브라우저를 못 돌렸다"고 밝힌 바로 그 범위에서 생긴 결함입니다.
2. **제 `data-workbench-colors.cjs`가 분석 성공 여부를 검사하지 않아** 위 문제를 못 잡았음 → "검사 완료"가 아니면 실패하도록 강화.
3. **준비도 검사 결과가 동결되어 있지 않았음** → 호출자가 결과 필드를 바꿔 "준비됨"처럼 보이게 할 수 있었음. 깊은 동결을 추가하고 시험 추가. (다른 모듈은 이미 동결)

## 5. 새 코드 독립 검증
- **입력 경계(`analyzeJSON`)** 반례 17개 전부 통과: 비문자열·null·함수·심볼, UTF-8 1MB 경계(한글 33만 자), 깊이 17·1000 중첩, 노드 15만 초과, `__proto__`, BOM, 무한대, 고립 서로게이트, **중복 키로 판정 우회 불가**, 최대 크기 1초 이내. 신뢰 객체용 `analyzePack`도 희소 배열 3천만을 빠르게 거절, toJSON·접근자 거절, 정상 입력에서 `analyzeJSON`과 결과 동일.
- **준비도 검사(`source-readiness`)** 22개 시험: 모든 선언이 갖춰져도 `declared-only`·미검증·연결 없음·독립 미확인·비밀검사 안 함. 입력 속 `status/verification/liveConnection/independenceVerified/ready/verified` 필드나 하위 `independent-verified` 선언으로 **승격 불가**. 입력 속 비밀값·URL은 결과에 되풀이되지 않음. 32KB 초과·깊은 중첩·`__proto__` 안전. CLI는 없는 파일·큰 파일·JSON 아닌 파일에서 내용·스택을 노출하지 않음.
- 설계 한계(패치도 명시): `analyzePack`은 **신뢰하는 내부 객체용**이며 적대적 Proxy 샌드박스가 아님. 외부 입력은 반드시 `analyzeJSON`.
