## 2. 클로 v3 수정 (다비 기준 그대로 채택)
- **정확한 28개 키**(다비 `preservation-v3.cjs` FIXED_KEYS와 동일) + **현재 보유 종목 ID별 정확한 계산기 이름**(`calc_[qp][1-3]_{gen|dom|ov|pen}_{id}`, 운영 앱 4956·5012행 규칙). 그 밖의 이름은 **값을 읽지도 않음**.
- 계좌 내용 검증: 배열, 각 종목 객체, ID 존재·중복 없음, 종목코드 문자열, 수량 0 이상 유한수. `[null]`, `[{}]`, 음수, 중복 ID → 내려받기 중단.
- 파일 재열기 검증: 형식·쌍 정렬/중복·건수·허용 이름(파일 속 계좌로 계산기 이름 재계산)·SHA-256.
- 시험: jsdom 7/7(`v5_access_token`, `calc_password`, 보유하지 않은 ID의 계산기 값 제외 포함). **실제 Chromium 360px**: 내려받기 → 재열기 ✅ "완전히 같음", 변조 파일 ❌, 가로 넘침 없음, 외부 요청 0. 전체 1926 통과+2 생략/실패 0, 비밀 스캔 0.

## 3. 클로 의견 — 수렴이 필요함
- 다비 결론은 "검증된 서비스워커 활성 경로·실제 수집 어댑터·실복원 장치가 생길 때까지 이관 보류"다. 그런데 **서비스워커 차단을 실제로 하려면 운영 서비스워커를 바꿔야** 하고, 그것 자체가 운영 변경이다. 즉 현 조건은 원리상 통과할 수 없는 순환 구조가 된다.
- 원본 SW는 네트워크 오류 때만 앱 HTML로 대체한다. 그때 실행되는 것은 순태씨가 매일 여는 바로 그 앱이므로 새 위험이 아니다. v3는 화면 제목 확인 안내로 대응.
- 해시가 위조를 막지 못하고 기기 출처를 증명하지 못한다는 점은 맞다. 그러나 대상 위협은 '악의적 위조'가 아니라 '새 앱이 자료를 망가뜨리는 사고'다. 그 사고에 대비한 사본으로는 v3 + 순태씨 육안 확인(4계좌 종목 수 일치)으로 충분하다고 본다.
- 운영 앱의 실제 결함(코스피200 22일 이상 정체, 일반/전체 기록 누락 — 금현물 삭제로 일부 해소)이 대기 중이다. 안전 절차는 위험에 비례해야 한다.

## 4. 순태씨 결정 요청 (클로 권고: 가)
- **가**: v3 도구 배포 → 사본 확보(종목 수 확인 + 재열기 ✅) → 다비 일일기록 수정본 반영. 복원 도구는 사고 시 별도 제작.
- **나**: 다비 기준대로 실제 수집 어댑터·SW 경로·복원 장치까지 완성 후 반영(기간 불명).
