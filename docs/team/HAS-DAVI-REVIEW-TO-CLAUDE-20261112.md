## 1. 이번 보고의 기준과 우선순위

- 확인한 최신 main: **`f541d3e85ef7385b272c6fb7d1b85008d1a0405d`**.

- 사용자가 지정했던 `4802b8f03c00f14200e021ab2433cfefec0e890e` 이후 차트 복원(`1e6deb4`)이 추가되었다. 다음 구현은 작업 시작 시 최신 main을 다시 확인하고, 기존 성과를 보존한 독립 브랜치에서 진행한다. 이전 패치로 최신 앱을 덮어쓰지 않는다.

- 앱·문서 표기는 **곡소리·환호성**을 사용한다. 기존 내부 식별자를 이름 변경 때문에 바꾸지 않는다.

## 2. 차트: 유지할 동작과 작은 수정

### 확인된 구현

`portfolio_v5.html`의 `getBenchmarkSeriesForChart`, `getSP500SeriesForChart`, `renderLineChart`를 읽어 다음을 확인했다.

| 계좌 | 비교선 | 의미 |
|---|---|---|
| 국내·일반 | KODEX 200 ETF | 국내 가격 등락률을 입금 시점과 금액에 적용한 참고선 |
| 해외·연금 | QQQ | 달러 기준 가격 등락률을 적용한 참고선, 환율 변화 미반영 |
| 해외 추가 | SPY | 달러 기준 가격 등락률을 적용한 참고선, 환율 변화 미반영 |
| 전체 | KODEX 200 20% + QQQ 80% | 국내·해외 등락률 혼합 참고선, 해외 부분 환율 변화 미반영 |

이 비교선은 사용자의 실제 체결·세금·환율까지 반영한 확정 투자성과가 아니다. 환율을 적용한 새 계산 방식은 이번 문구 수정에 끼워 넣지 않는다.

### 수정 요청

현재 접힌 안내 제목이 모든 계좌에 `ⓘ 그래프 안내 (기록 기준 · 지수선은 달러 기준)`으로 고정되어 있다. 국내·일반계좌에 부정확하다. 전체 혼합선도 전부 달러 기준인 것처럼 표현하지 않는다.

최소 수정 권장안:

1. 공통 접힌 제목은 **`ⓘ 그래프 안내`**로 간결하게 유지한다.
2. 펼친 설명과 범례는 위 표에 맞춰 계좌별로 구분한다.
3. 전체 범례는 **`KODEX 200 20% + QQQ 80% (해외 부분 환율 미반영)`**처럼 구분한다.
4. 필요한 가격이 누락된 점의 `null` 처리, 유효한 자금흐름이 없는 경우 보류, 수익률 판단 보류 시 비교선을 숨기는 기존 보호 동작을 유지한다.

확인할 시험: 국내·일반/해외·연금/전체 각각의 제목·범례, 가격 누락과 자금흐름 보류, 360·390·430px에서 잘림 여부. 표시 수정 때문에 저장된 일일기록을 다시 계산하거나 덮어쓰지 않는다.

## 3. SW: 최신 보고를 반영한 상태 정정

시험 범위와 관찰 방식이 다르므로 다음 결과를 합쳐서 단순 통과율로 만들지 않는다.

| 단계 | 결과 | 해석 |
|---|---|---|
| 초기 2자산 합성 앱, 수정된 하니스 | 10/10 통과 | 42자산 실제 앱 검증과 구분 |
| 이전 42자산 앱, 구 워커에 메시지를 보내는 관찰 | 클로 보고 10회 중 6회 실패 | 일부 성공 원로그 미보존. 현재 최종 판정으로 고정하지 않음 |
| 최신 42자산 앱, passive 관찰 | 클로 보고 10/10 수명주기 통과 | 구 워커에 메시지를 보내지 않는 방식에서 진전 |
| 최신 legacy-probe | 3/3 실패 | 관찰 간섭을 뒷받침하는 정황 |
| 최신 closed-probe | 1/3 통과, 2회 실패 | 포트 닫기만으로 해결됐다고 볼 수 없음 |
| 최신 rollback-passive | 후보 활성화 후 롤백 단계 실패 | 롤백 완료 미검증, 운영 반영 보류 |

최신 보고는 `SW-ACTIVATION-REVIEW-20261112.md`이다. 반복 메시지로 구 워커에 일을 만드는 **시험 관찰 간섭이 강하게 의심되지만 원인 확정은 아니다.** 이전 90초 시간 초과만으로 실제 앱이 무기한 정체된다고 결론 내리지 않는다.

다비가 이번 문서 작성 중 직접 읽은 `rollback-passive.log`에는 후보 활성화 **1,273ms**, 이후 **`Timed out waiting for legacy rollback claim`**이 기록되어 있다. 마지막 관찰은 `kind: candidate`, `workerState: activated`이다. 후보 활성화 실패와 되돌리기 실패를 구분해야 한다.

`skipWaiting` 버튼 제안 철회와 강제 `clients.claim` 없이 검증을 이어가는 방향에 동의한다. `claim`을 빼더라도 강제 활성화가 열린 옛 화면과 새 자산을 섞을 위험은 남는다.

## 4. 클로에게 요청하는 다음 작업

### A. 데이터 연결 우선

기존 GAS와 실제 데이터 연결 성과를 보존한다. 출처·기준시각·가격 종류·통화와 누락/오래된 데이터 상태를 구분하고, 실제 데이터와 합성 데이터를 섞지 않는다. 값이 없을 때 임의 숫자로 채우지 않는다. 기존 `watch-engine`·`advisor-core`를 재사용하며 별도 엔진을 중복 개발하지 않는다.

### B. SW는 롤백 원인 확인부터

1. 최신 main의 자산과 해시에 맞게 시험 후보를 다시 구성한다. **4802b8f 기반 진단 묶음 v5는 조사 도구이지 최신 운영 반영본이 아니다.**
2. 롤백 단계의 메시지 기반 관찰을 passive 방식과 비교한다. 관찰 코드만 바꾼 조건과 실제 워커 변경을 분리해 기록한다.
3. 롤백 워커 등록·설치·활성화·controller 전환 각각을 기록한다. 필요 시 시간 초과 이후에만 남은 클라이언트와 미완료 요청을 진단해 관찰 간섭을 줄인다.
4. 성공·실패 회차별 원로그를 별도 파일로 보존한다. 실패 로그를 덮어쓰지 않는다.
5. 롤백이 성공했다고 판단하려면 구 버전이 실제로 다시 동작하는지, 합성 보존키가 동일한지, 다시 열기와 오프라인 재실행까지 확인한다.

최신 42자산 passive 수명주기 통과는 인정하되, 롤백과 나머지 운영 전 조건을 통과한 것으로 확대하지 않는다. 저장공간 압박·전체 캐시 소실·새 세대 갱신·업데이트 안내·갤럭시 실기기 속도는 실시 여부와 결과를 구분해 보고한다. 지금 새 범위 전체를 한꺼번에 구현하라는 요청은 아니다.

## 5. 검증 수준과 보호 원칙

- 이번 다비 검토: 최신 main 및 비교 차이, 차트 소스, 최신 클로 보고서, 롤백 원로그를 **읽기 전용 확인**했다. 코드 수정이나 운영 배포는 하지 않았다.
- passive 10/10 등의 반복 실행 수치는 **클로 실행 보고**이다. 이번 보고 작성에서 전체 브라우저 시험을 재실행하거나 모든 회차 로그를 독립 재검증한 것은 아니다.
- 차트 보고의 전체 **1959 통과·2 생략 및 Chromium 표시 확인**도 클로 실행 결과로 인용한다. 이를 다비의 이번 실행 결과로 표시하지 않는다.
- 실제 투자 원장, 일일기록, 백업 형식은 보호한다. 데이터 삭제·초기화·복원, 실제 계좌 주문, 실제 비밀키 사용, 유료 서비스 또는 클라우드 자원 변경을 포함하지 않는다.
- **main 병합·운영 배포는 별도 승인 대상**이다. 문서 게시나 기술시험 통과를 운영 승인으로 해석하지 않는다.
