## 작업 범위
1. 기존 클로 브랜치 `work/claude-universe-screen-20261112`를 이어 사용. 변경 후보는 has/universe-screen-ui.js, has/universe-screen.html 및 관련 tests/에 한정. 가능한 한 현재 화면·검증기·callback 안전 처리·과거 오류 처리를 보존하고 중복 화면/모듈을 만들지 말 것.
2. 화면 첫 진입 자동 1회 조회는 실제 운영 기본값에서 활성화하지 말고, **합성/시험 모드에서만** 가짜 JSONP·검증된 synthetic 응답으로 시연 가능하도록 옵트인 게이트를 설계. GAS 주소가 없거나 승인되지 않았으면 자동 네트워크 요청 0, 상태에 미연결·판단 보류 표시. 실제 API 키·비밀값·사용자 원장·백업은 입력·전송하지 않음.
3. 같은 한국 기준일 동안의 캐시 재사용, 중복 클릭·다중 요청 병합, 성공 후 페이지 재진입, 새 기준일/만료/오류 시 적절한 갱신·보류 테스트. 기존 UTC 날짜(`new Date().toISOString().slice(0,10)`)를 KST/시장 자료 기준과 구분하고, 영업일/휴장일의 정확한 갱신 정책은 미확정이면 근거와 제한 명시. **현재 투자기록 localStorage 및 백업의 어떤 키도 수정하지 말 것**(가능하면 메모리 캐시만 사용).
4. 응답은 반드시 HASUniverseScreen.validateSummary 통과 후 표시; 누락·오래된·출처 불명·비교기준 불일치 가격은 매수후보가 아닌 '자료 부족/판단 보류'. 당일 가격과 1/3/6/12개월 구분, 자료 기준일, 가격 종류, 통화, 조정기준을 명확히 표기. '매수 검토' 자동 의견 금지.
5. 기존 `400종목` 프로젝트 이름은 유지하되 실제 감시 건수는 응답 total을 그대로 노출하고, 추후 KR 201 + US 200 = 401 전환 시 UI에서 잘못 '정확히 400'이라 주장하지 않도록 표시를 동적으로 설계. 실제 유니버스 계약 변경이나 공식 미국 목록 생성은 이번 단위에서 하지 말 것.
6. 앱 화면 또는 보호 파일이 수정되면 tests/lib/live-data-edits.json 역방향 쌍과 live-data-pins.json 갱신, 무관한 사용자 기록·기존 배포 수정 금지. 기타 보안·성능·모바일 변화는 tests로 검증.
