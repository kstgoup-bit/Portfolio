## 3. 클로 의견 — 동의하지 않는 부분과 비례성
- **서비스워커 fallback**: 원본 SW는 네트워크 우선이다. 온라인이면 도구 페이지가 그대로 온다. 오프라인일 때만 기존 앱 HTML로 대체되는데, 그건 순태씨가 **매일 앱을 여는 것과 같은 동작**이다. 도구가 새로 만드는 위험이 아니다. 대응: 화면에 "인터넷 연결 상태에서 열고, 이 제목 대신 평소 앱이 뜨면 멈추라"를 표시. SW 변경은 하지 않음.
- **"원본을 여는 것도 읽기 전용이 아니다"**: 맞지만 순태씨는 매일 원본 앱을 연다. 기준점은 "사본을 받는 시점의 저장값"이면 충분하다.
- **게이트 1·5(기기·프로필·PWA 실측, 별도 시험 공간)**: 원칙은 맞으나 비전문가 사용자가 폰에서 수행하기 어렵다. 위험 대비 절차가 과하면 운영 앱의 실제 결함(코스피200 정체·일반/전체 기록 누락)이 계속 남는다. 제안: 이 도구 결과(4계좌 종목 수가 화면과 일치 + 파일 재열기 ✅)를 **독립 사본 조건의 충족 기준**으로 삼자.
- 복원 도구는 여전히 만들지 않는다. 사본은 "되돌릴 근거 자료"이며, 실제 복원은 문제 발생 시 별도 승인·도구로.

## 4. 제안 절차(순태씨 승인 E 필요)
1. `backup-raw-export.html`만 배포(앱·SW 불변).
2. 순태씨: 와이파이/데이터 켠 상태로 도구 열기 → 4계좌 종목 수가 앱 화면과 같은지 확인 → 내려받기 → "받은 파일 열어 확인" ✅ → 카카오톡 나에게 보관. 기존 백업 버튼 파일도 함께 보관.
3. 다비 일일기록 수정본 반영 → 새 앱에서 v7 백업 → 다음 날 코스피200·기록 확인.
