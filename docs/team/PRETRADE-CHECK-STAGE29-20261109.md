# 29단계 — 매매 전 점검·사유 기록 (클로 → 다비 인계 보고서, 2026-11-09)

## 1. 왜 이 기능인가
순태씨의 철학 문서 6장 성공 기준 중 **④ 불필요한 매매·감정 판단이 줄었는가**, **⑤ 판단 성과 검증**은 지금까지 측정할 수단이 없었다. 지금까지 만든 것(시세 신선도, 비교기, 마스킹, 작업대)은 대부분 앱 밖 시험 화면이거나 데이터 신뢰 쪽이었다. 이번에는 **앱 본체까지 끝까지 연결된 첫 기능**을 만들었다. 순태씨의 상시 규칙(매수·매도 전 ①뉴스 ②실적·공시 ③컨센서스 ④커뮤니티 순서 조사)과 철학 문서의 반대 근거·비중·분할·"위대한 기업은 오래 보유" 원칙을 폰에서 쓰는 점검표로 만들었다.

## 2. 무엇이 들어갔나
- 앱: 위험관리 그룹에 **"📝 매매 점검"** 탭 하나(앱 수정 6곳, 추가뿐. tests/lib/has-stage29-edits.json으로 되돌림 고정).
- has/pretrade-log.js: 점검표·검증·점검 상태 평가·요약·저장소(순수 모듈, 주입 저장소).
- has/pretrade-panel.js/.css: 화면(textContent만, innerHTML 없음, 글자 12px 이상·#333 이하).
- 시험: tests/pretrade-log-stage29.test.cjs(16개), tests/pretrade-integration-stage29.cjs(실제 Chromium 23개).

## 3. 동작 계약 (다비가 다듬을 부분)
- 구분 3종: 매수 / 매도 / 비중 축소. 공통 필수: 4단계 조사(출처 메모 필수) + 비중·현금 확인. 매수 전용: 본질가치·경쟁력, 악재 일시성 구분, 분할 계획. 매도·축소 전용: 매도 이유(고평가·성장 둔화·논리 훼손·집중도), "위대한 기업" 원칙 충돌 검토, 세금·수수료·환율·재매수 수량 검토.
- 이유와 **반대 근거**를 모두 적어야 점검 완료. 감정 상태(차분/공포/탐욕)와 결정(진행/보류/취소) 선택.
- **기록은 막지 않는다.** 막으면 기록 자체를 피하게 된다. 대신 "점검 미완료 상태로 진행"과 "공포·탐욕 상태에서 진행"을 따로 세어 보여 준다(성공 기준 ④의 측정치).
- 사후 메모(나중에 돌아본 한 줄). 수익률·적중 평가는 하지 않는다(⑤ 평가는 기존 advice-journal 설계와 연결할 후속 과제).
- 이 화면은 매수·매도를 권하지도, 주문하지도 않는다(철학 문서 6장 10번: 최종 결정은 사용자).

## 4. 안전 경계 (시험으로 고정)
- 투자 원장(v5_*) 비접촉: 실제 Chromium에서 점검을 기록·사후 메모 저장한 뒤에도 원장 문자열이 바이트 단위로 같다. 새 저장 키는 `has_pretrade_log_v1` 하나뿐.
- 저장값이 손상돼 있으면 덮어쓰지 않고 경고만 한다(시험 포함). 일부 항목만 잘못되면 그것만 버리고 개수를 알린다(삭제 아님).
- 모듈이 없거나 저장소를 못 쓰면 이 탭만 "사용할 수 없음"이고 기존 앱은 정상(시험 포함).
- 이 모듈의 코드에서 나가는 네트워크 요청 0건, 페이지 오류 0건, 외부 AI 전송 없음, 키·비밀 접근 없음.

## 6. 알려진 한계
1. **백업에 포함되지 않는다.** 기존 백업은 허용 키 목록 방식이라 `has_pretrade_log_v1`을 담지 않고, 복원도 이 키를 건드리지 않는다. 폰을 바꾸면 이 기록은 사라진다. 백업 모듈은 보호 영역이라 순태씨 승인과 별도 시험이 필요하다 → 다음 단계 1순위 후보.
2. 갤럭시 실기기 시험 아님(브라우저 에뮬레이션).
3. 종목 시세·AI 의견과 연결하지 않았다(독립 기록). 연결 시 AI 의견을 "점검 근거"로 자동 채우지 않는다는 원칙을 유지할 것.
4. 점검 항목 문구와 필수 여부는 클로의 초안이다. 철학 문서 기준으로 다비가 검토·개선해 주길 요청한다.

## 7. 협업 요청과 제안
- **다비**: 점검 항목·필수 규칙의 철학 일치 검토, 사전 점검 결과를 5장 "우량주 복귀 시뮬레이터"의 매도 점검(세금·환율·재매수 수량)과 연결하는 설계, 기록↔advice-journal 사후 평가 계약 설계.
- **클로**: 백업 포함(승인 후), 적대 입력·원장 보호 시험, 앱 연결 유지보수.
- 순서 제안: ① 백업 포함 ② 복귀 시뮬레이터 확장 ③ 사후 평가 연결. 시세 비교(KIS) 쪽은 GAS 응답 표본이 오면 다시 진행한다.
