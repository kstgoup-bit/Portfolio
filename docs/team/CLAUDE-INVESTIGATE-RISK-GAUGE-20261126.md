# 위험계(위험관리 > 위험계) 이상값 원인 조사 — 조사만, 코드 변경 없음

작성: 클로 · 2026-11-26 · 요청: 순태씨(화면 캡처: VIX 3.0 "안전", 10Y 1.00%, 2Y 1%, HY 100bps, 금리차 0.00, DXY 100.00, WTI 조회 실패, "VIX·DXY·WTI 실패→이전값")
대상: portfolio_v5.html `fetchRiskData()`(약 4354행 이하), `rkUpdateUI`(4191행).

## 확인한 원인(코드 읽기 + 재현)
1. **쓰레기 응답을 숫자로 받는다.** `parseFred`는 줄을 쉼표로 나눠 두 번째 칸의 숫자를 읽는다. 중계 서버가 오류 HTML을 돌려줘도 "…, 1 …" 같은 줄에서 1을 읽는다(재현: 오류 HTML → 1 반환). `raceUrls`는 **먼저 온 응답이 이긴다**(내용 검증 없음). → 10Y·2Y·HY가 전부 1.0 근처로 나오는 현상과 일치(HY 1.00→100bps, 10Y−2Y=0.00). 10Y(0.1~15)·HY(0.5~30) 허용 범위가 너무 넓어 1.0이 통과한다.
2. **가짜 기본값이 실제 값처럼 표시·저장된다.** 조회 실패 시 `cached.x || 280(HY) / 4.5(10Y) / 18(VIX) / 100(DXY) / 0.5(금리차)`로 대체해 화면에 그리고 `v5_riskData`에 다시 저장한다. DXY 100.00은 이 기본값으로 보인다(조회 실패 메시지와 일치).
3. **VIX 3.0은 오래된 손상 캐시.** 현재 VIX 검증(5~100)은 3.0을 막지만, 과거 손상값이 `cached.vix`에 남아 있고 정리 코드는 WTI에만 있다(주석 "$3 버그"). 그 값이 '이전값'으로 계속 표시돼 "안전"이 나온다.
4. **기준일이 없다.** 값마다 조회·관측 날짜를 안 보여 주고(FRED 마지막 줄 날짜 미사용), 이전값을 쓴 항목도 같은 색의 정상 값처럼 보인다.
5. **출처가 불안정.** 무료 공개 중계 서버 4곳(allorigins, corsproxy, codetabs, thingproxy)과 Yahoo·FRED를 섞어 쓴다. 중계 서버는 내용이 바뀌거나 막힐 수 있다(앱도 "미검증 출처"로 표기).
6. **이미 다른 판단에 쓰이고 있다.** 아침 브리핑(`v5Brief`)과 "종합 위험지수 N점 — 안전 구간… 지금은 투자하기 좋은 환경이에요" 행동요령 카드가 `v5_riskData`를 읽는다. 잘못된 값이 지금도 '안전' 메시지로 나올 수 있다.

## 제안(순태씨 승인·지피 검토 후, 코드는 아직 없음)
A. 값마다 **합리적 좁은 범위 + 형식 검사**(예: FRED CSV 헤더·날짜 형식 확인, 10Y/2Y/HY/VIX 최근 이력 대비 급변 의심 표시).
B. **가짜 기본값 제거**: 값이 없으면 '없음'으로 표시하고 종합점수에서 제외(점수는 '일부 자료 없음' 표시).
C. 값마다 **관측일·조회시각·출처·"이전값/오래됨" 표시**. 24시간(주말 고려)보다 오래되면 판단에 쓰지 않음.
D. 오래된 손상 캐시 일괄 정리(범위 밖 값 폐기) — 1회성 마이그레이션.
E. 중계 서버 대신 이미 쓰는 GAS 중계(Yahoo 이력 등)로 옮기는 안 검토(승인 필요, GAS 변경은 별도).
F. 종합점수 카드(안전/행동요령)는 자료가 온전할 때만 표시. 위험계는 **종목 선택이 아니라 시장 환경(매수 속도·단계 조정, 자동매매의 중지 조건)** 용도.
G. 시험: 쓰레기 응답, 범위 밖 값, 오래된 캐시, 일부 실패 시나리오.
