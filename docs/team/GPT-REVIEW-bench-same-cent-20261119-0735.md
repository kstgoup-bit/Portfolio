## 수정 요청 (중요 순)

**CR-1. 정리 전 사본을 검증 가능한 복구 단위로 완성.**
현재 `backup/ui.js`의 `kst-bench-same-value-archive`에는 `originalV2Raw`와 removed만 포함하고 `v5_benchHist` 원문(`legacyRaw`)이 없음. V2 스토어는 `legacyFingerprint`로 그 원문에 결합되어 있으므로, 보관 파일만으로 본래 연결 상태를 복구·검증할 수 없음. 사본에 두 저장 키의 정확한 원문과 스키마·검증용 결합값을 포함하고, 원문 재검증 및 사본→검증→원상복구 왕복을 **합성 로컬 자료만으로** 시험할 것. 기존 전체 백업과 일반 복원 파일이 아님을 명시하고 자동 복원은 구현하지 말 것(별도 승인).

**CR-2. 갤럭시 다운로드 실패에도 정리 저장이 열리는 문제 해결.**
현재 `download()`은 앵커 click 시도 직후 반환하며 실제 파일 저장을 확인하지 못함. 그럼에도 안내 문구는 ‘내려받았습니다’로 단정하고 `정리 저장 (사본 확인함)` 버튼을 즉시 노출함. 갤럭시 브라우저의 기존 백업 다운로드 실패 이력이 있으므로 이 차이는 실제 손실 위험임. 최소한 다운로드는 ‘시도됨·저장 여부 미확인’으로 표시하고, **사용자가 내려받은 JSON 파일을 다시 선택해 실제 내용·원문 해시·미리보기 시점 자료의 일치를 확인해야만** 저장 가능하도록 fail-closed 게이트를 구현할 것. 취소·파일 미선택·손상·불일치·브라우저 실패는 저장 0. 이미 구현된 원문 변경 감지(`v5_benchHist`/`V2`)는 유지.
