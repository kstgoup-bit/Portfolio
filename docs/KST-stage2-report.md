## 남은 문제와 다음 단계

1. **원격 브랜치·Draft PR 미생성:** GitHub 연결에 해당 저장소 contents 쓰기 권한을 제공한 뒤 개발 브랜치만 push한다. 개인 토큰을 대화에 붙여넣을 필요가 없다. 사용자가 직접 적용하려면 패치와 로컬 커밋을 사용할 수 있다. main 병합·Pages 배포는 하지 않는다.
2. **실제 200종목 확정 미완료:** 공식 상장 정보, 기준일 시총, 최신 공시·재무, 경쟁력 및 반대 근거를 검증해 후보를 활성화한다. 합격하지 못한 기업은 보류·제외 이유를 남긴다.
3. **실제 공급자 미선정:** `docs/data-provider-design.md`의 라이선스·빈도·한도·시간대·수정가격·비용·보안 확인을 마친 후 별도 승인을 받아 서버/프록시를 연결한다. 무료 한도나 가격을 검증한 것으로 주장하지 않는다.
4. **기존 백업의 일반계좌 누락:** 원본 `exportData()`가 `genStocks`를 포함하지 않고 `importData()`도 이를 읽지 않는다. 이번에 기능을 유지했으므로 해당 결함도 남아 있다. 운영에서 전체 백업을 신뢰하기 전에 별도 수정·왕복 복원 시험이 필요하다.
5. **기존 키 평문 저장·기존 AI/프록시 설계:** 이번 레이더 범위에서 변경하지 않았다. 별도 보안 개선 과제다.
6. **기존 PWA의 오래된 HTML·HTML 대체 응답:** 워커를 바꾸지 않았으므로 오프라인에서 과거 HTML이 보일 수 있고 JSON/JS 요청에 HTML이 대체될 수 있다. 레이더의 데이터 실패는 오류로 표시한다. 실제 기기 캐시는 건드리지 않았으며, 향후 승인된 배포 전에 자산별 캐시 정책을 별도로 설계해야 한다.
7. **설정 이외 사용자별 레이더 편집 기능:** 현재 목록은 저장소 JSON으로 관리한다. 사용자별 후보 편입·정성 점수 입력 편집기는 이번 MVP에 포함하지 않았다. AI 분석 생성·수집 서버·자동 주문·예약 감시는 구현하지 않았다.

main은 개발 기준을 확인하는 읽기 작업만 수행했다. 원격 브랜치 생성 및 push 시도는 실패했고 코드가 서버로 전송·반영되지 않았다. 운영 배포·병합·Pages 설정 변경 도구는 호출하지 않았다. 실제 기기 투자 기록 보존은 이 변경이 배포되지 않았고 실제 데이터에 접근하지 않았다는 범위에서 확인되며, 실제 기기 데이터 내용의 전후 비교까지 했다는 뜻은 아니다.
