## 1. 기준선·무결성·원격 작업

원격 main을 GitHub 연결로 다시 조회한 결과 `fd2599398d2f2ef1816ca9b64ea134ea8811309d`이며 2단계 기준과 같다. 파일 목록 10개도 확인했다. 로컬 2단계 커밋은 `bfaa5024ba38d5c15873a0077559cbf4840e7d25`다.

새 로컬 독립 브랜치: `work/kst-value-radar-stage3-20261029`. 2단계 커밋을 부모로 두고 3단계 변경을 추가 커밋으로 분리했다. 최종 커밋 SHA와 파일별 목록은 ZIP의 delivery.json 및 패치 첫 줄에 있다.

### 안전한 원격 후속 조치

## 3. 백업·복원 결함 수정

일반계좌 `v5_gen`을 포함해 네 계좌의 종목명·티커·ID·수량·평단·현재가를 내보내고 가져온다. 저장 코드를 확인해 자산 스냅샷, 계좌별 입금 기록, 배당, 가계부 투자 납입, 투자 노트·메모·분류, 자산·부채, 환율·목표 비중·필터·계산기·지원 캐시를 백업 범위에 넣었다. 별도 증권사 체결 원장 키는 발견되지 않았으므로 없는 기능을 백업했다고 주장하지 않는다.

새 스키마 v6는 허용된 키의 원문 문자열을 보존하며 API 키·비밀번호·GAS URL·세션·타 앱·레이더 키를 제외한다. 새 파일은 네 계좌를 모두 요구하고 손상 JSON·미래 버전·누락 필드·중복 종목 ID·비유한 숫자·실행 가능한 문자열·범위 밖 키를 거절한다. 한글·정상 특수문자는 보존한다. 기존 저장 데이터가 손상돼 앱이 메모리 기본값으로 대체한 경우에도 이를 숨겨 백업하지 않는다.

구버전 v5에 일반계좌가 없으면 현재 일반계좌를 유지한다. v4 시장별 stocks/pension/normal 기록을 변환하며 기존 변환처럼 생략된 숫자는 0으로 보완한다. 구버전 기록 객체의 빠진 하위 계좌도 유지한다. 제공된 배열은 교체하며 자동 병합하지 않는다. 명시적 빈 배열은 빈 계좌/기록으로 복원한다. 이 정책과 계좌별 전후 건수를 적용 전에 보여준다.

복원 미리보기·취소는 쓰기를 하지 않는다. 적용 전 `kst.portfolio.restoreJournal`에 대상 키의 원문과 부재 상태를 저장한다. 사본 저장 실패 시 자료를 쓰지 않고, 중간 실패 시 원래 값으로 rollback한다. 중단된 prepared journal은 다음 시작 때 복구를 시도한다. 가장 최근 전체 복원의 직전 상태로 되돌릴 수 있고 사본을 별도 파일로 내보낼 수 있다. 레이더의 `kst.radar.state/preRestore`와는 별개다.

제약: localStorage 여러 키는 완전한 원자적 트랜잭션이 아니다. 저장 장치의 지속 오류로 rollback도 실패하면 사본을 남기고 복구 미완료를 명시하며 사용 중단·사본 내보내기를 안내한다. 사본 때문에 추가 공간이 필요하며 실패를 무시해 진행하지 않는다. 여러 탭 동시 편집은 지원하지 않는다. 기존 API 키 평문 저장 위험은 수정하지 않았으며 호환성 검토·승인 후 별도 개선할 보안 과제다. 상세 스키마/범위/제약은 `backup-schema-v6.md`에 있다.

## 5. 자동 시험과 모바일 증거

- 새 백업 시험 **29개 통과**.

- 모바일·회귀 **16개 시험 묶음 통과, 0개 실패**. 원래 12묶음과 새 4묶음이며 개별 클릭 수를 부풀려 표현하지 않는다.
- `node tests/mobile.cjs` 또는 `npm run test:mobile`. 360/390/430px에서 레이더 실제/데모 목록·상세·기준·상태, 일반/ISA/해외/연금 CRUD, 전체 백업 다운로드·미리보기·취소·적용·새로고침·undo, 뒤로가기·focus 복귀, 오류·오프라인을 확인했다.
- 레이더 신규 조작부 44px 이상, 가로 넘침 없음, 시험 중 JS 오류 없음. 새 전체 복원 조작 버튼도 44px 이상이며 설정 화면 가로 넘침을 검사했다. 기존 앱의 모든 과거 버튼 크기를 일괄 수정한 것은 아니다.
- 헤드리스 Chromium 138 모바일·터치 재현과 로컬 한국어 글꼴을 사용했다. 실제 Android 설치·홈 화면 갱신은 미실시다. 실제 기기 투자 기록을 읽거나 자동 설치/캐시 삭제하지 않았다.
- 실제 거래·가격·재무 API 시험이 아니라 합성 자료·차단된 기존 자동 시세 호출 조건에서의 기능 시험이다. 계좌·부채·자산의 기존 소스 기본값도 시험 초기 합성 값으로 덮어 주입해 사용했다.
- 신규 로컬 브라우저 컨텍스트에서 현재 워커의 캐시 HTML 오프라인 복귀를 시험했다. 운영 워커는 수정/등록 갱신하지 않았다. JSON→HTML 대체 문제는 별도 VM 시험으로 재현했다.
- `node --check`로 새 JS/CJS와 모바일 러너, 기존 inline JS의 구문을 확인하고 `git diff --check`를 수행했다. 전용 ESLint는 도입하지 않았다.

ZIP의 `evidence/stage3-unit.tap`, `evidence/stage3-mobile.log`, `evidence/mobile-results.json`이 결과 원본이다. PNG는 `evidence/baseline-*`, `radar-{real,demo,detail,criteria,status}-*`, `radar-{loading,error}-360`, `backup-{preview,status}-{360,390,430}.png`이다. 캡처는 모두 합성 데이터이며 실제 기기/사용자 데이터 화면이 아니다.

## 6. 공급자·실데이터 접근

Alpha Vantage, Twelve Data, Massive 공식 문서·가격·약관을 조회하고 커버리지, 수정 고가, 분할/배당 조정, 동일 기간 비교, 지연, 호출 제한, 200종목 부하, 사용 권리, 비용·오류·키 보관을 비교했다. 확인한 값과 동적 추출 실패·문서 간 차이·미확인 값을 분리했다. 요금·약관의 조회일과 URL은 `data-provider-comparison-stage3.md`에 있다.

실제 API 키·승인된 수집 계정·화면 표시/저장 권리와 조정가격의 실측 정합성을 확보하지 못했다. 따라서 **티커 조회 0개, 실데이터 API 요청 0건, 파일럿 미실시**다. 예제 시세를 실데이터 수집으로 세거나 임의 서버를 만들지 않았다. 후보 16개를 활성으로 전환하지 않았고 실제 감시 종목은 0개다. 앱의 실제 미연결 표시와 가상 3기업 데모를 유지했다. 파일럿 어댑터를 연결한 것처럼 주장하지 않는다.

후속 단계는 본인용 사용·표시·보관 권리와 공급자/키 관리 승인 → 최대 5개 고정 티커의 읽기 전용 검증 → 기준일·통화·시간대·조정·오류·지연 기록 → 신호 대조 순서다. 무료 호출 한도 안이라는 사실만으로 라이선스 적격성을 가정하지 않는다. 유료 계정·클라우드·예약 수집·자동매수·AI 정성 점수는 만들지 않았다.

## 7. 남은 사항

1. 원격 업로드·Draft PR: 403 해소 전 미완료. 로컬 소스·커밋·패치·ZIP 제공.
2. 실데이터 파일럿·공급자 확정·서버 설계/비밀 관리: 미실시/미확정. 승인 전 과금·서비스 생성 금지 유지.
3. 약 200개 검증: 확정 0, 보류 후보 16. 기업의 시총·재무·경쟁력·상장 정보 검증은 계속 미완료.
4. 실제 Android/PWA 업데이트, 다중 탭 동시 복원, 실제 저장 장치 장애·대량 기록의 기기별 UI 성능은 미실시.
5. 운영 워커 교체는 독립 제안/시험까지만. 원본 캐시 문제는 운영 앱에 남아 있다.
6. 기존 키 평문 저장은 별도 승인·호환성 개선 과제. 전체 백업에서도 키를 제외했다.
7. 복원은 엄격한 허용 스키마를 사용한다. 알 수 없는 옛 형식·실행 가능한 텍스트·손상 데이터는 원문 보관 후 별도 변환이 필요하다. 임의로 초기화하거나 불완전한 파일을 적용하지 않는다.

전체 소스 ZIP은 `.git`·개인 브라우저 데이터·의존성 바이너리를 포함하지 않는다. 저장소 원본의 기존 초기값은 소스 그대로 유지했다. ZIP의 `baseline/portfolio_v5.html`은 기준 main의 원문이며 테스트 러너가 이 파일을 사용하므로 git 이력이 없는 소스 폴더에서도 재현할 수 있다. 로컬 실행 안내는 ZIP 루트 README.md에 있다.
