# 국장 레이더 모바일 화면 설계안 (설계만, 구현 없음)

7단계에는 화면 코드가 **없다.** 아래는 후속 승인 시 구현할 설계안이며, 360/390/430px 모바일 검증과 실제 Android/PWA 시험은 화면이 생긴 뒤에 별도로 한다. 지금까지의 모바일 25묶음은 기존 화면의 회귀시험일 뿐 국장 레이더 화면을 검증한 것이 아니다.

## 공통 원칙
- 글자는 최소 12px, 색은 #333 이하의 짙은 색. 연한 회색 보조 글씨 금지.
- 터치 대상은 높이 44px 이상. 가로 스크롤 금지, 긴 문장은 줄바꿈.
- 화면 맨 위에 항상 표시: "합성 연구 화면 · 실제 감시 0종목 · 매수·매도 지시가 아닙니다".
- 모든 텍스트는 DOM 텍스트로 렌더링(HTML 주입 금지), 외부 요청 차단(CSP `connect-src 'none'`).
- 보유 종목·저장소를 읽지 않는다. 합성 사례만 표시.

## 화면 흐름
1. **후보 목록**: 검색 칸, 필터(개별주/ETF, 업종, 검증상태). 각 행에 종목명·코드·"미검증" 배지. 상단 요약 "후보 73 · 검증 0 · 활성 0".
2. **상세**: 상태 배지, 점수가 있으면 7개 요소 막대(배점 대비), 없으면 사유와 결측 목록. 접이식 섹션 "근거 / 반대 근거 / 불확실성 / 계산식 / 출처·기준일·재무 기간".
3. **매수·매도 대조**: 두 결과를 나란히(좁은 폭에서는 위아래) 보여 주고 충돌이면 "상충 근거 재검토" 띠를 표시.
4. **계좌 확인**: 일반/ISA/연금저축/IRP 선택 시 "확인 필요"를 기본으로 보여 주고, 사용자가 입력한 날짜·출처 규칙이 있을 때만 답한다.

## 폭별 배치
| 폭 | 목록 | 상세 |
|---|---|---|
| 360px | 1열 카드, 배지는 이름 아래 줄 | 요소 막대는 라벨을 위에 두고 한 줄 전체 폭 |
| 390px | 1열 카드, 배지는 이름 오른쪽 | 동일 |
| 430px | 1열 카드, 코드와 업종을 한 줄 | 점수 요약과 상태 배지를 한 줄 |

## 오류·결측 표시
모듈 로드 실패 시 기존 포트폴리오 메뉴로 돌아가는 버튼을 보이고 기존 데이터에는 접근하지 않는다. 결측은 "평가 불가 + 무엇이 없는지"를 문장으로 쓴다.
