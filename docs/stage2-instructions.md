# KST 곡소리 레이더 — Work 2단계 개발 지시서

작성일: 2026-10-28

## 1. 작업 목적 및 안전 원칙

미국 상장 대형·중형 우량주 약 200개를 체계적으로 감시하는 **KST 곡소리 레이더**를 기존 개인용 포트폴리오 앱에 추가한다. 주가 급락만으로 매수 추천하지 않고 기업의 경쟁력, 재무건전성, 밸류에이션, 하락 원인을 함께 분석할 수 있는 구조를 구축한다.

**절대 금지:** 운영 중인 `main` 브랜치 변경, 기존 앱 배포 변경, GitHub Pages 설정 변경, 실제 주문·매매 실행, 사용자의 투자기록 삭제 또는 초기화, 개인 API 키의 저장소 커밋, 외부 서비스에 사용자 포트폴리오 무단 전송.

## 2. 작업 대상 및 기준 확인

- GitHub: `kstgoup-bit/Portfolio`
- 현재 알려진 기본 브랜치: `main`
- 후보 최신 앱 파일: `portfolio_v5.html` (반드시 GitHub에서 다시 확인)
- 관련 파일: `portfolio.html`, `manifest.json`, `service-worker.js`
- **기준 커밋 SHA를 작업 시작 시 조회하고 보고할 것.** 본 지시서는 특정 SHA를 확정하지 않는다.
- `portfolio_v5.html`과 실제 휴대폰 홈 화면에서 실행되는 진입 URL/manifest의 `start_url` 및 서비스 워커 캐시 대상을 대조할 것. 두 HTML 중 실제 진입점을 확인하기 전에는 어느 파일도 운영 파일이라고 단정하지 말 것.
- 새 브랜치: `work/kst-value-radar-stage2-20261028` (동일 이름이 이미 있으면 충돌 없는 새 이름 사용)
- 사용자가 제공했던 `portfolio_v5.html`과 과거 레이더 시제품은 참고자료일 뿐, GitHub 최신 파일을 덮어쓰는 근거로 사용하지 말 것.

## 3. 사전 조사 — 코드 변경보다 먼저

1. 저장소 전체 파일, `main` HEAD SHA, 앱의 실행 경로와 HTML 구조를 확인한다.
2. 현재 탭/메뉴 구성, 주가 API 호출 방식, 저장 키(`localStorage` 등), 보유 종목 입력·수정·삭제·내보내기 기능, PWA 서비스 워커와 캐시 정책을 분석한다.
3. 기존 HTML에 API 키를 노출하거나 영속 저장하는 부분이 있는지 점검한다. 기존 비밀값은 로그·보고서에 출력하지 않는다.
4. 모바일 뷰포트 360px, 390px, 430px에서 현재 앱의 기준 화면을 캡처하거나 재현 가능한 테스트를 기록한다.
5. 전체 소스를 읽거나 테스트 환경을 구성할 수 없으면 임의 구현을 시작하지 말고 장애와 필요한 권한·자료를 보고한다.

## 4. 이번 단계 구현 범위 (MVP)

### A. 레이더 메뉴

- 기존 포트폴리오 화면과 명확히 구분되는 **‘곡소리 레이더’** 메뉴/탭을 추가한다.
- 기존 잔고, 거래 기록, 수익률 계산, 종목 분석 및 설정 기능은 그대로 유지한다.
- 레이더 화면에는 `후보 목록 / 상세 분석 / 감시 기준 / 데이터 상태`를 표시한다.
- 처음에는 **시연용 가상 데이터**와 **실제 데이터**를 혼동하지 않도록 명확히 분리한다. 실제 API 미연결 상태에서는 ‘실시간’, ‘200개 전체 감시 완료’, ‘매수 적기’라고 표시하지 않는다.

### B. 200종목 감시 목록

- 미국 상장 대형·중형 우량주 약 200개를 관리할 수 있는 **버전 관리 가능한 티커 목록**을 별도 데이터 파일로 만든다.
- 섹터, 회사명, 티커, 거래소, 선정 이유, 상태(활성/보류/제외), 마지막 검증일을 기록한다.
- 초기 편입 원칙: 원칙적으로 시총 50억 달러 이상, 사업 경쟁력·재무건전성 확인. 금융기업 및 고성장기업은 별도 평가 규칙.
- 숫자 200개를 맞추기 위해 미검증 종목을 채우지 않는다. 선정 근거가 불충분하면 ‘후보’로 분리한다.

### C. 1차 하락 감지

- 52주 최고가 대비 낙폭 -20%, -30%, -35%, -45% 구간.
- 3개월 S&P 500 대비 -15%p 이상, 관련 업종 ETF 대비 -10%p 이상 초과하락.
- 기준일·종가·통화·가격 수정 여부(분할 등)·데이터 출처를 각 신호에 기록한다.
- 임계치는 설정에서 조정 가능하게 만들되 초기값은 위와 같이 한다.
- **중요:** 주가 낙폭은 ‘분석 개시 신호’이며 자동 매수 지시가 아니다.

### D. 2차 정성·정량 평가

100점 모델: 사업 경쟁력 25, 성장·재무건전성 20, 낙폭·과잉반응 15, 밸류에이션 20, 악재 일시성 10, 회복 촉매 10.

- 85점 이상: 최우선 분석, 70~84: 심층 분석, 55~69: 관찰, 54 이하: 보류.
- 회계 부정, 유동성 위기, 핵심 경쟁력 훼손, 주요 고객 상실 등의 **위험 플래그는 총점보다 우선**한다.
- 실제 재무 데이터가 없으면 점수를 추정하지 말고 `평가 불가/데이터 부족`으로 표시한다.
- AI가 작성한 분석에는 주장별 근거 URL·기준일·확인 여부·반대 시나리오를 포함한다.

### E. 데이터 연결 설계

- 1단계에서는 데이터 공급자 어댑터 인터페이스를 구현하고, **테스트용 고정 데이터**로 동작 검증한다.
- 실제 가격 API를 사용할 경우 라이선스, 호출 제한, 200종목 수집 가능성, 종가 기준 시간, 오류·결측·재시도 정책을 검증한다.
- 브라우저에 비밀 API 키를 하드코딩하거나 GitHub에 커밋하지 않는다. 서버/프록시가 필요하면 별도 설계와 예상 운영비를 제시하고, **실제 유료 서비스 생성·배포는 승인받기 전 수행하지 않는다.**
- ChatGPT 예약 감시와 앱의 수집 서버는 별개임을 화면과 문서에서 분명히 한다. 예약 감시가 실제로 확인한 종목 수를 추정해서 부풀리지 않는다.

### F. 데이터 보존·보안

- 기존 `localStorage` 키는 변경·삭제하지 않는 것을 원칙으로 한다.
- 레이더 전용 저장 공간/키 네임스페이스를 분리하고, 스키마 버전·마이그레이션·백업/복원 방안을 마련한다.
- 사용자 포트폴리오를 외부 AI·서버에 전송하려면 별도 명시적 동의를 요구한다.
- XSS 방지를 위해 외부 데이터·AI 분석 결과를 HTML로 무검증 삽입하지 않는다.

## 5. 테스트 및 합격 기준

- 정적 구문/린트 검사 및 가능한 범위의 자동 테스트를 수행한다.
- 최소: 메뉴 전환, 기존 보유 종목 추가·수정·삭제, 레이더 필터, 정렬, 상세 화면, 데이터 결측, API 실패, 중복 티커, 분할 조정 가격, 로딩/오류 상태를 점검한다.
- 모바일 360/390/430px에서 가로 스크롤·잘림·버튼 터치 영역·뒤로가기·화면 복귀를 확인한다.
- 서비스 워커/PWA가 구버전 HTML을 보여주는 문제를 확인하되 **운영 캐시를 무단 변경하지 않는다.**
- 기존 앱의 주요 기능 회귀 테스트를 수행한다. 실패한 테스트와 미실시 항목을 성공으로 표시하지 않는다.
- 가상 데이터 기반 화면은 ‘데모’라고 명시하고 실제 매매 판단에 사용하지 않도록 한다.
