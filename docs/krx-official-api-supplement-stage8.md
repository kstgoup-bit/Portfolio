# 8단계 보완 — 금융위원회 KRX상장종목정보 API 검증 기능 (OFF / fixture-only)

작성일 2026-10-29 · 근거: 「금융위원회_KRX상장종목정보 활용자가이드」(24쪽) · 지시서 「KST 8단계 KRX 공식 API 보완 개발 지시서」

## 0. 한 줄 결론
공식 API 규격에 맞춘 **오프라인 파서·검증기·후보 대조 도구**를 준비했다. 실제 호출 수단(네트워크·키 입력)은 코드에 존재하지 않는다.
**공식 API 실조회 0회 / 실제 공식 검증 0종목 / 실제 활성 시세 감시 0종목.**

## 1. 가이드에서 확인한 API 규격 (문서 근거)
| 항목 | 내용 |
|---|---|
| 서비스/기능 | `GetKrxListedInfoService_V2` / `getItemInfo_V2` (종목정보, 조회-목록) |
| 호출 주소 | `https://apis.data.go.kr/1160100/GetKrxListedInfoService_V2/getItemInfo_V2` (REST GET, SSL, XML·JSON) |
| 인증 | `serviceKey` 필수 |
| 요청 변수(선택) | numOfRows, pageNo, resultType, basDt, beginBasDt, endBasDt, likeBasDt, likeSrtnCd, isinCd, likeIsinCd, itmsNm, likeItmsNm, crno, corpNm, likeCorpNm |
| 응답 | resultCode, resultMsg, numOfRows, pageNo, totalCount, basDt, srtnCd, isinCd, mrktCtg, itmsNm, crno, corpNm |
| 갱신 | 일 1회, 실시간 아님, 영업일 데이터를 다음 영업일 13시 이후 개방 |
| 성능 | 평균 응답 500ms, 초당 최대 30tps (가이드 기재) |
| 제외 | **우선주 정보 미제공**, 외국회사 국내 법인등록번호 없음 |
| 제공하지 않음 | 현재가·OHLC·52주·거래량·수정주가·신호 (식별정보 확인용) |

`numOfRows` 상한 10,000 (초과 요청은 10,000으로 제한 — 코드는 1~10,000 밖을 오류 처리).
가이드 예제 값(KR모터스 `A000040` 등)은 **문서 예시**이며 실제 조회 결과가 아니다. `tests/fixtures/krx/guide-example.xml`로 보관하고 모든 로그에 "문서예시/합성 픽스처 — 공식 조회 아님"을 표기한다.
**JSON 응답 구조는 가이드에 예제가 없어** 공공데이터포털 공통 형태(`response.header/body.items.item`)를 가정했다 — 미확정.

## 2. 구현 요약
| 파일 | 역할 |
|---|---|
| `kr-radar/krx-api.js` | 응답 파서(XML 최소 파서·JSON), 스키마 검증, 오류 분류, 코드 정규화, 쪽 합치기, 요청 명세 생성(전송 불가), OFF/fixture 어댑터, 후보 대조 |
| `tools/kr-krx-verify.cjs` | 사용자가 직접 내려받은 응답 파일을 오프라인 대조. `--attest-official` 없이는 verified 없음 |
| `tests/kr-krx-api.test.cjs` | 26개 시험 |
| `tests/fixtures/krx/guide-example.xml` | 가이드 응답 예제(문서 예시) |

핵심 규칙
- `srtnCd` `A000040` → 표시 코드 `000040`. **원본 `A000040`·ISIN·시장·기준일은 별도 보존.** 6자 영숫자는 접두 없는 코드로만 해석. 코드 추론·보정 없음.
- 오류: resultCode≠00, 필수 필드 누락, 기준일 형식/달력, 비정상 시장구분(KOSPI/KOSDAQ/KONEX 외), ISIN 형식·체크섬·코드 불일치, 중복 코드(관련 행 모두 제외), 페이지 수 불일치, 빈 응답, XML/JSON 파싱 실패, DTD/ENTITY/CDATA, Unauthorized/Forbidden/속도제한/호출량 초과(가이드 오류표). **자동 재시도 없음.**
- 대조 결과: `verified`(사용자가 제공한 실제 공식 응답과 코드+종목명+시장 정확 일치, 기준일 10일 이내) / `pending`(불일치·누락·차단·우선주·ETF 미확인) / `excluded`(별도 확인된 사유·확인자·확인일이 있을 때만) / `fixture-matched`(합성·예시와 일치 — **공식 검증 수에 포함하지 않음**).
- 모든 항목은 `decision: HOLD`, `priceStatus: DATA_UNAVAILABLE`. 이 API는 가격을 주지 않는다.
- 이 API만으로 종목명 변경·기업행위·시장 이전·상장폐지·거래정지를 검증할 수 있다고 주장하지 않는다.
- 검증 로그: 종목코드·종목명·시장·ISIN·기준일·출처·응답 해시·검증 규칙·결과. 원본 응답 전체는 저장·출력하지 않는다.

## 3. 이용허락 정리 (가이드 1.2, 13~14쪽)
- 공공누리 **제4유형**: 출처표시 + 상업적 이용 금지 + 변경 금지(2차적 저작물 작성 금지).
- 가이드 안내: 상업 목적 여부와 상관없이 **제3자 무단 제공·재배포 엄격 금지**. 상업적 이용 시 원천 소유자 한국거래소의 KRX Data Marketplace(data.krx.co.kr)에서 **유료 구매** 필요. 구매하더라도 상업 활용은 (1) 가공을 통한 독창성 있는 저작물 생산, (2) 제3자의 방문·가입을 통한 간접 수익 창출 목적에 한함. 문의처: 한국거래소 데이터사업부.
- 출처 표기 문구(제안): `출처: 금융위원회_KRX상장종목정보(공공데이터포털), 기준일 YYYY-MM-DD`.

| # | 항목 | 현재 처리 |

| 2 | 정규화 결과(코드·이름·시장·ISIN) 저장 | 미확정 — 저장하지 않고 해시만 기록 |

| 4 | GitHub(공개/비공개) 커밋 | 미확정 — 응답 원본·대량 추출물 커밋 금지, 합성/문서예시만 포함 |
| 5 | 브라우저(GitHub Pages/PWA) 배포·표시 | 미확정 — 배포 금지, 프런트엔드에 데이터·키 미포함 |
| 6 | "개인 투자 도구" 이용이 비상업적 이용인지(앱을 타인과 공유할 경우 포함) | 미확정 |
| 7 | ETF·리츠·스팩·외국법인 포함 범위 | 미확정 — ETF는 `pending`으로 별도 집계 |
| 8 | JSON 응답 구조, 휴일 응답 형태, 이력(과거 basDt) 조회 범위 | 미확정(가정은 시험으로 고정) |
| 9 | 일일 호출 허용량(개발계정/운영계정) | 가이드에 수치 없음 — 미확정 |

## 5. 기관 질의안
**금융위원회 / 공공데이터포털 활용지원센터**
1. 개인이 본인의 투자 후보 목록 점검용으로 `getItemInfo_V2`를 조회하고 결과를 로컬에 보관하는 것이 이용허락범위(공공누리 4유형)에 포함됩니까?
2. 종목코드·종목명·시장구분·ISIN과의 일치 여부(예/아니오)만 저장하는 것도 "변경금지" 대상입니까?
3. 비공개 저장소·개인 서버·개인 브라우저 앱에서의 보관·표시는 "제3자 제공/재배포"에 해당합니까?
4. 일일 호출 허용량(개발/운영), 초당 허용치, 휴일·미개방일 응답 형식(빈 응답인지 오류인지)은 무엇입니까?
5. JSON 응답(`resultType=json`)의 공식 예제와 필드 타입을 제공해 주십시오.
6. ETF·ETN·리츠·스팩·외국법인이 응답에 포함되는지, 상장폐지·거래정지·종목명 변경 이력은 어떻게 반영됩니까?

**한국거래소 데이터사업부 (KRX Data Marketplace)**
1. 개인의 비상업적 투자 판단 보조 용도로 허용되는 상품/이용권이 있습니까? 요금은 얼마입니까?
2. 가이드의 "상업적 이용" 범위에 개인이 무료 앱을 운영하며 타인과 공유하는 경우가 포함됩니까?
3. 가공·캐시·내부 DB 보관의 허용 범위와 보관 기간은 어떻게 됩니까?

## 6. 향후 인증키 보관 구조 제안 (구현하지 않음)
- 키는 **비공개 서버 측 환경변수 또는 승인된 비밀 저장소**에서만 읽는다. 프런트엔드(HTML/JS/PWA)·저장소·로그·ZIP·테스트 스냅샷에 넣지 않는다.
- 서버 측 호출 코드는 별도 모듈로 분리하고 이 저장소의 `kr-radar/*.js`(정적 가드로 네트워크·환경변수 금지)에는 두지 않는다.
- 호출 로그는 URL에서 `serviceKey`를 제거(마스킹)하고, 응답은 해시·건수·기준일만 남긴다.
- 호출 횟수는 하루 상한을 코드로 강제하고 429/quota 응답 시 자동 재시도하지 않는다.
- `buildRequestSpec`은 `serviceKey`가 전달되면 예외를 던지며, 반환값은 `sendable:false`다.

## 7. 향후 실데이터 파일럿 전 사용자 별도 승인 목록
1. 위 §4의 1~6번 항목에 대한 기관 회신 확인(서면/게시 근거) 후 이용 범위 결정.
2. 조회 허용 및 1회 조회 범위(기준일 1일, 전체 약 수천 건 → 페이지 수) 승인.
3. 인증키 보관 방식(서버 측 비밀 저장소) 승인 — 키는 채팅·저장소에 전달하지 않음.
4. 조회 결과 보관 위치·기간·삭제 방침 승인.
5. 조회 전 투자기록 백업(v6) 확인 및 롤백 계획.
6. 시세 공급자 별도 승인(이 API는 가격 제공 불가) — 미국·한국 시세 파일럿은 기존 8~10단계 게이트에 따름.
7. 어떤 경우에도 main 병합·운영 배포·유료 가입·자동매매는 별도 명시 승인 전 금지.
