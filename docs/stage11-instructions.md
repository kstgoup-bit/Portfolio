## 3. 필수 작업
### A. 통합 및 회귀 보호
1. 10단계 파일·투자기록·백업 로직·`portfolio_v5.html`·서비스워커·PWA 설정을 보존한다. 기존 모듈 변경이 필요하면 변경 사유와 영향 분석을 명시한다.
2. 8단계 보완의 KRX 오프라인 응답 검증기, 종목코드·종목명·시장구분·ISIN 비교, 중복·기준일·오류 차단, 가이드 기반 문서·시험을 10단계 데이터 무결성 파이프라인과 연계한다.
3. KRX 공식 종목 **신원 검증**과 실시간/종가 **시세 검증**을 엄격히 분리한다. 공식 검증되지 않은 종목은 실제 감시로 승격하지 않는다.
4. 한국 후보 73개 개별주와 별도 ETF 5개를 구분하고, 100개 목표 부족분 27개를 근거 없이 채우지 않는다. 우선주 등 API 제공 범위 밖의 종목은 별도 보류한다.
5. 응답 JSON 스키마가 실제 데이터로 확인되지 않았으므로 **가정임을 명시**하고 문서 예시·합성 fixture로만 시험한다. 실응답을 확보하면 구조를 재검증하도록 경계면을 설계한다.

### B. 이용권·보안
1. 가이드에 나타난 공공누리 제4유형(출처표시·비상업·변경금지) 및 제3자 재배포 제한을 기록한다. 개인 내부에서의 조회, 가공 비교, 저장, 결과 표시 가능 범위는 **확인 전 미확정**으로 분류한다. API 승인만으로 모든 이용권이 해결됐다고 단정하지 않는다.
2. `serviceKey`를 소스, HTML, GitHub, ZIP, 시험 로그, 오류 메시지에 넣지 않는다. 브라우저/PWA 직접 호출 방식은 인증키 노출 위험으로 금지한다. 향후 사용자 승인 후 로컬 또는 보호된 서버측 실행 경로를 별도로 설계한다.
3. 외부 네트워크 호출, 인증키 발급·입력·사용, 유료 가입, 결제, 운영계정 신청, 실제 데이터 수집은 금지한다. 사용자가 발급받은 개발계정의 존재만 상태로 기록한다.
4. 기관에 문의할 질의서 초안(비영리 개인 앱에서의 내부 종목 대조·가공·로컬 저장·표시 허용 여부, 출처표시 방법)을 작성하되 승인 없이 발송하지 않는다.

### C. 시험
1. 10단계 기준 단위시험 **315개**, 모바일 **25묶음**의 재현성을 먼저 확인한다.
2. 보완 브랜치의 신규 KRX 시험 **26개**를 통합해 실행하고, 전체 통합 시험 수는 **실제 테스트 실행 결과대로** 보고한다. 단순히 315+26=341 통과라고 미리 가정하지 않는다(중복·충돌·실행 환경 차이 확인).
3. 잘못된 종목코드, 동일 코드의 상이한 종목명, 시장 변경, 중복, 날짜 불일치, 누락 필드, 응답 오류, 비정상 JSON, 대량 페이지 누락, 잘못된 데이터 출처, 무단 네트워크 접근에 대한 실패 차단 시험을 추가한다.
4. 시험 통과와 **공식 검증 성공**, **실제 가격 감시 성공**을 구분한다. 실제 Android 기기 시험을 하지 않았다면 하지 않았다고 명시한다.
