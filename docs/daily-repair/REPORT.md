## 결론

최신 클로 검토의 일일기록 합의를 우선 반영했다. 실제 저장된 시작 시각으로 계산하고, 자산가치 변화·입출금 반영 수익률·ETF 관측 수익률·알파를 각각 판정한다. 기존 입금 원문을 소급 분류하지 않으며 새 기록부터 외부 입출금과 계좌 내 매매를 구분한다. 지수 정정 충돌은 날짜별로 원본과 대안을 남기고, 충돌 없는 새 날짜만 추가한다.

**실시간 시세·공식 종가·자료 이용권·모바일 실기기·운영 적용이 완료됐다는 뜻은 아니다.** 정상 매매와 현금 변화를 완전히 대사하는 입력 화면도 아직 연결하지 않았다. 근거가 부족한 보유 범위 변화는 저장 자산가치 변화만 보여주고 투자수익률과 알파를 보류한다.

## 구현한 사항

### 1. 실제 기간과 독립적인 계산 판정

`has/return-assessment.js`는 저장소·시세 조회 없이 전달된 입력만 계산한다. 비교 시작은 요청 날짜가 아니라 그보다 앞선 실제 저장 관측의 `snap.ts`다. 같은 날 보존된 이전 관측도 선택에 참여한다. 표는 각 행에 실제 시작·종료 시각을 기기 현지 시각으로 표시한다.

- 구형 출처 미검증 자체는 경고다. 수치가 유효하면 참고값을 계산한다.
- 잘못된 현재 시세/환율, 손상 기록, 설명되지 않은 보유 범위 변경, 외부 흐름의 불명확성은 해당 지표만 보류한다.
- 원수익률은 **기록 자산가치 변화**로 명명했다. 외부 유입이나 보유 누락이 섞일 수 있으므로 투자성과라고 표시하지 않는다.
- 지수 실패가 원수익률·Dietz까지 지우지 않는다. USD/혼합 지수는 자체 수익률과 통화를 표시하되 원화 포트폴리오의 알파와 비교선은 대응 환율 근거가 없어 보류한다.
- held 지표에 내부 진단값이 있어도 화면에 사용 가능한 수익률처럼 표시하지 않는다. `signalHold: true`, `quality: unconfirmed`를 유지한다.
- 실제 시작값 1,000, 중간 외부 입금 500, 종료 1,500인 반례에서 잘못된 요청 시작일로는 50%, 실제 `snap.ts`로는 0%가 나오는 기존 결함을 검증 기준에 반영했다.

### 2. 새 활동 분류, 기존 기록 보존

새 입력에는 `activityVersion: 1`과 계좌·고유 ID·유형·금액·기록 시각을 넣는다. 외부 입금/출금과 내부 매수/매도는 반드시 직접 선택한다. 내부 매매 금액은 외부 현금흐름 합계에 더하지 않는다. 보유량·예수금·주문을 변경하는 기능이 아니다.

실제 시각 또는 날짜만 입력하는 방식도 직접 선택한다. 날짜만 아는 외부 흐름은 관련 기간의 Dietz를 보류한다. 서머타임의 23/25시간 날짜를 위해 실제 다음 현지 자정과 양쪽 UTC 오프셋을 보존한다. 이것은 기기/사용자가 선언한 날짜 경계이지 독립적으로 검증한 거래 시각이나 모든 시간대에 대한 보증은 아니다. 이전 날짜-only 형식은 원문을 유지하고 더 넓은 불확실성 구간을 사용한다.

기존 행의 값·필드·순서를 유지하며 임의로 입금/매수 유형을 붙이지 않는다. 실제 새 기록 저장 시 JSON 컨테이너 공백은 달라질 수 있다. 저장은 `v5_deposits` 한 키에 제한하고 전체 `save()`는 부르지 않는다. 취소, 반복 클릭, 오래된 대화상자, 저장 실패, 다른 창의 수정, 사후 확인 불확실성을 시험했다. 기존 삭제 기능은 확인 후 선택한 한 행만 대상으로 하며 같은 타임스탬프의 모든 행을 지우지 않는다.

**실제 사용자 기록을 읽거나 추가·삭제·복원한 것은 없다.** localStorage의 비교 후 쓰기는 원자적 교차 탭 트랜잭션이 아니며, 확인 이후 수정까지 완전히 막는다고 주장하지 않는다.

### 3. 지수 날짜별 충돌과 출처

기존 `v5_benchHist` 바이트는 그대로 두고 새 `v5_benchHistV2`에 관측·수신시각·원천·충돌 대안을 저장한다. 레거시 원문 지문은 결합 관계를 확인하는 용도이며 원천 진위나 독립 검증을 증명하지 않는다.

- 0.5% 허용치 제안은 사용하지 않는다. 다른 값은 정정 후보로 분리하고 이전 값을 덮어쓰거나 누락 날짜를 소급 채우지 않는다.
- 충돌 없는 새 날짜는 추가할 수 있다. 충돌 날짜를 선택하는 비교는 보류한다.
- 당일 값은 미확정이다. 명시적으로 당일 미확정으로 저장된 값의 다음날 같은 원천 후속 관측은 원본을 보존한 대안으로 남기며, 공식 final 종가로 승격하지 않는다.
- 날짜만 있는 자료에 임의 장 마감 시각을 만들지 않는다. 일별 관측 선택은 해당 거래소의 이전 날짜까지만 사용하며 당시 이용 가능했던 데이터라는 점을 입증하지 않는다.
- JSON 중복 키, 비유한 수, 크기/깊이 한도, 잘못된 심볼·통화·시간대·ETF 식별, 상속된 프로퍼티 ID, 위조 후보를 거부한다. 네트워크 응답 경로도 크기 제한 스트림과 중복 키 검사에 통과해야 한다.
- 기존 Yahoo query1/query2 및 프록시 경로를 유지·복원했다. 기존 키를 가진 명시적 새로고침에만 Alpha Vantage 직접 fallback을 허용하도록 코드로 보존했다. 키를 프록시로 보내지 않는다. 합성 요청 시험만 수행했고 실제 연결 성공, 요금/무료 잔여량, 제공 권리를 확인하지 않았다.
- GAS 시세 경로는 보존했다. GAS history와 KIS 실호출은 활성화하지 않았다.

### 4. 백업 v7과 재현 가능한 보호 시험

새 유형을 구형 앱이 모두 외부 입금으로 오해하지 않게 새 export는 v7이다. v4/v5/v6 import는 계속 지원하지만 v6 껍데기에 새로운 활동/지수 의미를 넣어 우회하는 자료는 거부한다.

일반계좌, 일일 이전 관측, 기존 활동, 레거시 지수 원문, 새 충돌 증거를 합성 왕복 시험했다. 백업의 두 지수 자료가 같은 원문에 결합되어야 복원할 수 있다. 일부 그룹 생략·다른 원문·검토 후 변경은 검사 후 쓰기 전에 거부하고 자동 재결합이나 원본 삭제를 하지 않는다. 오래된 백업이 sidecar를 생략하면 기존 sidecar를 조용히 버리지 않고 결합 불일치 경고/보류를 유지한다.

오프라인 복원 리허설 화면의 정책 스크립트 순서도 보완했다. CSP와 실제 저장소 비접근 원칙은 유지했다. 별도 `mobile-lab`의 기존 내장 v6 번들은 재생성하지 않았으며 v7을 거부한다. v7 자료를 그 구형 번들에서 열 수 있다고 안내하면 안 된다.

기존 KIS 독립 시험이 특정 로컬 Git 커밋을 요구하던 문제는 167개 보호 파일의 이식 가능한 해시 검증으로 바꿨다. 이번에 명시적으로 변경한 부분만 정확히 역적용하면 이전 해시가 일치해야 한다. 이전 보호 해시는 바꾸지 않았다. 코드가 바뀌었는데 시험 기대값만 무조건 새 해시로 교체한 방식이 아니다.

## 검증

최종 실행 수치는 `VALIDATION.json`과 원본 로그를 함께 참조한다.

- 허용된 106개 시험 파일, 1,807개 사례: UTC/서울은 각각 1,805 통과 + 뉴욕 DST 전용 2개 조건부 생략, 뉴욕은 1,807 통과. 실패 0. 같은 사례를 시간대별 반복한 것이며 합산해 고유 시험 수로 부풀리지 않는다.
- 새 6개 시험 파일은 235개 사례. 독립 검토 42개는 세 시간대 모두 생략 없이 통과했다. 구현 과정에서 11개 구체적 반례를 찾고 재검증했다.
- 구형 수동가격 시험 2개는 뉴욕에서 고정된 현지 10시가 시험 시계의 미래가 되는 시험 자료 오류였다. 변경 전 기준본에서도 재현했고, 미래 시각 차단을 없애지 않고 세 시간대에 모두 과거인 합성 입력으로 수정했다. 금현물 가격 기능 개발은 하지 않았다.
- 실제 HTML을 사용한 JSDOM/VM, 합성 저장소와 로컬 바이트 스트림을 사용했다. 외부 네트워크 접근 시도 0, 신뢰 가능한 현재 시세를 받았다는 주장은 없음.
- HTML 인라인 2개와 변경 JS 5개 구문, whitespace, 비밀 형태 검사를 통과했다. `.git` 없는 전체 소스 사본에서도 허용된 1,807개 사례가 모두 통과했다. 패키지 소스/패치 재현 결과는 `RELEASE.json`에 기록한다.
- 제외된 기존 5개 파일은 그대로: `network-guard-stage19.test.cjs`, `kis-runner-stage21.test.cjs`, `us-pilot-stage18.test.cjs`, `krx-runner-cli.test.cjs`, `kr-krx-stage13.test.cjs`. 전체 `npm test` 통과라고 부르지 않는다.
- 실제 모바일 브라우저/레이아웃/터치/로그인·브라우저 저장 quota는 미검증. 기존 브라우저 소켓 실행이 환경에서 거부되어 이번 작업에서는 우회·재시도하지 않았다. DOM 시험은 실기기 검증을 대체하지 않는다.

## 다음 검토와 남은 한계

1. 클로는 변경 소스, 이번 보고서, 독립 보고서, 원문 로그를 함께 확인한다. 특히 기존 기록 불변, v7 호환 경계, 지수 sidecar 결합, 날짜-only 활동의 계산 보류를 검토한다.
2. 매매 때문에 수량이 바뀌는 정상 상황을 완전히 구분하려면 현금/수량/시간/계좌별 전환 근거와 대사 입력 화면이 필요하다. 현재 순수 모듈의 제한적인 증거 계약은 화면에 연결하지 않았다. 임의로 ‘정상 매매이므로 수익률 확정’하지 않는다.
3. 지수는 ETF 대용치다. 배당/보수/환율/조정 방식, 공식 거래소 달력·종가 확정, 정정 승인 UI 및 실제 제공 권리는 추가 확인 대상이다. 지문/스키마 검사는 자료 출처의 독립성을 증명하지 않는다.
4. 사용자가 요청한 실제 KIS 조회 준비는 이후 별도 우선 과제다. 현재 후보는 기본 거부 상태이며 실제 키·실호출·클라우드 생성/변경·운영 배포 전 승인이 필요하다. 주문·자동매매는 구현하지 않는다.
5. 운영 도입 전에 사용자 데이터가 아닌 복제 합성 자료로 실제 모바일 리허설을 진행하고, 기존 원본의 별도 보관/중단·되돌림 기준/호환성 검토 후 도입 여부를 정한다. 여기서는 실제 데이터 마이그레이션을 실행하지 않았다.
