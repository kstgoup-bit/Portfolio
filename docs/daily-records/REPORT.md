## 핵심 변경

### 같은 날 평가 갱신과 이전 버전

같은 날 첫 점을 무조건 고정하는 대신 달라진 완전한 평가를 갱신한다. 이전 점은 변경 이유와 함께 보존한다. 수신시각만 달라진 반복은 새 버전을 만들지 않으며, 수신시각을 시장 가격 기준시각으로 해석하지 않는다. 알려진 가격 기준시각의 후퇴·소실, 손상 자료와 보존 한도 초과는 변경 없이 거절한다. 과거 날짜의 누락 점을 만들어 채우지 않는다.

자산 구성·수량·원가 또는 구형 기록의 근거가 바뀌면 성과 비교를 보류한다. 자산 제외 전후 총액 감소를 투자손실이라고 단정하지 않는다. 정확한 저장 구조·한도·반례는 `SNAPSHOT-REVISIONS.md`와 집중 시험을 참조한다. 실제 사용자 자료의 이전이나 복원은 하지 않는다.

### 저장 기록만 그리는 차트

기존 차트에는 저장된 오늘 점을 현재 화면의 평가액으로 바꿔 그리거나, 오늘 기록이 없으면 표시용 점을 추가하는 경로가 있었다. 새 작업본은 이 경로를 제거한다. 과거 원가가 없는 점에도 현재 원가를 끼워 넣지 않는다. 저장 점의 원문은 그대로 두며, 알려진 범위 변경이나 근거 부족 구간의 수익률·알파·지수 비교선은 보류한다. 당일 이력은 접어서 볼 수 있게 표시한다.

### 지수 최신성의 정직한 표시

기준 ETF 자료의 관측 날짜와 수신시각을 구분한다. 공식 거래일 달력과 확정 종가 근거가 없는 상태에서 단순히 3일 또는 4일이 지났다고 시장 자료가 오래됐다고 단정하거나, 반대로 최신 확인 완료라고 표시하지 않는다. 지수 자체와 추종 ETF 대용값도 구분한다. GAS 날짜 전용 일봉의 연결 준비는 합성 계약 시험까지이며, 실제 GAS 호출·활성화·배포는 하지 않는다. 날짜만 있는 자료에 임의의 장 마감시각을 만들지 않는다. 자세한 제한은 `BENCHMARK-HISTORY.md`를 따른다.

### 모바일 안내

직전 추가한 상태 안내 5곳과 수동 가격 설명 1곳의 11px를 12px로 고친다. 새 이력 열기 영역은 최소 44px 높이를 둔다. 이는 DOM·정적 점검 범위이며 실제 폰과 브라우저 레이아웃 통과를 뜻하지 않는다. 기존 화면 전체의 작은 글자 문제를 모두 고쳤다는 주장도 하지 않는다.

## 검증 결과

수정 전 허용 회귀는 93개 파일, 1,408/1,408 통과했다. 최종 검증은 다음과 같다.

- 허용 회귀 97개 파일, **1,498/1,498 통과**, 실패·취소·건너뜀 0.
- 당일 기록·백업·지수 집중 시험 **204/204 통과**. 위 회귀에 포함된 수치이며 합산하지 않는다.
- 독립 검토 **36/36 통과**를 UTC·서울·뉴욕 시간대 각각 확인했다. 해당 사례도 회귀에 포함되며 시간대 반복을 새 시험 수로 합산하지 않는다.
- 기존 데이터 워크벤치·가치평가·조언 화면 DOM 시험 3종 통과.
- 변경 JS/CJS 12개와 HTML 인라인 스크립트 2개 구문 검사, 공백 검사 통과. 시험 중 외부 접속 시도 0.
- 비밀 형태 스캐너 발견 0건. 비밀 부재의 완전한 증명은 아니다.
- 기존 장부, 예전 앱, PWA manifest/service worker, 가치평가·참모·매매 점검·종가 근거·KIS 비교 모듈의 보존 대상 해시 일치. GAS history 서버 파일도 이번에는 변경하지 않았다.

당일 변경은 19개 명시적 HTML 구간을 역적용하면 클로 기준 HTML과 정확히 일치한다. 그 뒤 직전 기록 보완의 역검증과 과거 단계 회귀도 계속 수행한다. 백업 핵심 파일 변경은 이전 핀을 함께 남기고 새 검토 핀으로 명시했다. Alpha Vantage 이력 경로 제거로 URL 키 전달 지점은 5곳에서 4곳으로 줄었고 보안 문서·시험을 함께 바꿨다. 기존 재무 조회는 유지한다. 실제 키를 읽거나 호출한 것은 아니다.

독립 검토에서 손상 이력 표시 오류, 전달된 범위 비교 보류 표식을 제거해도 통과하던 검증, 손상 계좌 이력을 기록 가능으로 잘못 표시하던 경우를 재현하고 수정했다. 추가로 브라우저 스크립트 순서를 조정하여 백업 모듈이 이력 검증기를 먼저 확보하도록 했으며 실제 HTML 순서로 백업 왕복을 확인했다. 같은 날 지웠다 다시 추가한 자산의 과거 가격시각을 숨길 수 있는 경우도 보존된 근거 전체와 비교하도록 막았다.

최종 로그는 `logs/`에 포함한다. 검토 시작과 종료에 관련 원격 HEAD가 바뀌지 않았음을 확인했다.

## 남은 제한과 다음 확인

기존 v6 백업은 이미 일반계좌와 기준지수 이력을 포함했다. 이번에는 이력을 포함한 새 평가 메타데이터의 안전한 왕복을 검증하며, 누락 항목을 처음 구현했다고 주장하지 않는다. 이것은 모든 기기 설정·앱 자료를 보장하는 전체 기기 백업이 아니다. 복원 저널의 동시성 및 localStorage의 비원자성 제한도 남아 있다.

이 환경에서 앞서 제한된 Chromium 실행이나 다음 다섯 네트워크·runner 시험을 다시 시도하지 않았다: `network-guard-stage19.test.cjs`, `kis-runner-stage21.test.cjs`, `us-pilot-stage18.test.cjs`, `krx-runner-cli.test.cjs`, `kr-krx-stage13.test.cjs`. 전체 `npm test`, 실제 Android/PWA, 실제 Yahoo·GAS·KIS 응답, 제공 권리와 한도, 운영 자료는 미검증이다. 이번에 허용한 합성 시험만 실행한다. 사용자 자료 읽기·삭제·복원, 실제 API 키·실호출, 클라우드 변경, 유료 서비스, 원격 push·main 병합·운영 배포·GAS 재배포는 하지 않는다. 실제 주문·자동매매 기능은 구현하지 않는다.

후속 적용은 별도 승인 뒤 안전한 백업 보존, 실제 모바일 확인, 공급자 표본 계약 검증, 날짜형 이력의 저장·복원 설계 검토를 거쳐야 한다. 현재 배포된 운영 앱이 수정됐거나 코스피200 이력의 실시간 갱신이 해결됐다고 표현하지 않는다.
