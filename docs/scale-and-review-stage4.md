# 200종목 확대 준비와 증분 검증

현재 universe.json은 이전 16개 보류 후보를 그대로 유지한다. 숫자를 200개로 채우지 않았고 활성/제외로 바꾸지 않았다. eligibility.json은 해당 universe 버전과 일대일인 별도 검증 기록이다. 모든 편입 체크는 unknown이다. 일부 회사 식별 문서 링크는 부가 자료이며 편입 체크 통과로 쓰지 않는다.

## 검증 절차

1. 공식 상장 상태·시총 기준(원칙 50억 달러 이상)·재무건전성·사업 경쟁력·업종·데이터 사용권을 항목별로 검토한다. sourceURL·원자료 asOf·checkedAt·검토 사유를 기록하고 재무/경쟁력에는 반대 시나리오도 기록한다.
2. checkedAt은 30일 이내여야 한다. 상장/시총/업종 원자료 asOf도 30일 이내, 재무/경쟁력 원자료는 450일 이내라는 이번 준비 단계의 보수적 기본 정책을 둔다. 라이선스는 유효 권리의 재확인일을 기록한다. 이 정책은 가격/100점 임계치 변경이 아니며 산업·공시 주기에 맞춘 후속 검토가 필요하다.
3. 금융기업은 자본적정성·자산건전성·조달, 고성장기업은 현금 소진 기간·희석·단위 경제성의 별도 근거를 요구한다. 위험 플래그는 점수나 적격 판정보다 우선해 보류한다.
4. 확인 불가/근거 부족/기준일 지연은 hold, 최근 근거로 기준 미달이 확인되면 excluded, 모든 조건을 충족해야 active로 판정한다. 데이터 이용권 실패는 기업 부적격과 구분해 hold로 둔다. 과거 시총 미달을 오늘 다시 읽었다는 이유로 현재 제외하지 않는다.
5. `createRevision()`에 expectedVersion/nextVersion과 검토 배치를 전달한다. 버전 충돌·중복·목록 밖 티커는 거절한다. 입력 파일은 바꾸지 않고 새 객체만 만들므로 검토 후 별도 개발 브랜치에서 사람이 저장/커밋한다. 무근거 활성/제외는 앱 로딩 audit에서도 거절한다. 원문 문서 내용이 사실인지 판단하고 승인하는 책임은 실제 검토자에게 있다.
6. 새 종목 추가는 신규 후보의 선정 근거·상태·필드를 포함한 universe 개정과 같은 범위의 registry 개정을 함께 검토한다. 현재 배치 함수는 기존 티커의 증분 재검증을 담당하며 목록 밖 티커를 임의 추가하지 않는다. 자동 200개 편입 기능은 없다.

읽기 전용 감사 명령:

```sh
node tools/review-universe.cjs 2026-10-29
```

현재 출력은 active 0 / hold 16 / excluded 0 / eligible 0이다. 앱은 검증 파일 버전/범위 불일치 시 실패 상태를 표시하고 정상 완료로 가정하지 않는다. 이 명령은 시세 API·저장소 원격·브라우저 저장 데이터를 읽거나 쓰지 않는다.

## 합성 부하 시험

실제 티커 대신 TEST0~TEST199만 받는 collectSynthetic()으로 200개를 시험했다. transport도 synthetic 표시가 있어야 하며 시험 구현은 로컬 고정 성공/실패와 setImmediate만 사용한다. 최대 동시성 4, 최대 시도 2회, 의도한 영구 실패 20개·첫 시도 실패 후 성공 20개를 포함했다.

결과: 요청 대상200, 성공180, 실패20, 총 시도240, peak 동시성4, 실제 시장 요청0. **서비스 성공률이나 실제 200종목 감시 결과가 아니다.** 단위 로그의 SYNTHETIC_LOAD와 전달 evidence/stage4-synthetic-load.json에 있다. 실제 API latency·라이선스·호출한도·비용·최신성은 이 시험으로 증명하지 않는다.

원래 100점 배점과 -20/-30/-35/-45%, SPY -15%p/업종 -10%p는 그대로다. 어댑터는 가격만으로 정성 점수를 생성하지 않고 assessments를 빈 배열로 둔다. 실제 수집 서버·스케줄·자동 매수·반복 알림은 만들지 않았다.
