# HAS 25단계 — AI 참모를 기존 앱에 연결한 방법

## 구조
- 앱 화면 변경은 **추가뿐**(10곳): 스타일 1줄, 스크립트 11줄, 서브탭 버튼 `🧭 AI 참모`(위험관리 그룹), `#panel-staff`, 홈 상단 브리핑 띠 `#hasBriefStrip`(내용 없으면 숨김), switchTab/renderAll 훅 호출 3곳, TAB_GROUPS·tabColors 항목. 이름·아이콘·manifest·서비스워커·백업 모듈 변경 없음.
- 읽기: `has/advisor-panel.js`가 앱 메모리의 종목 배열(JSON 복사본)·환율 입력칸·`localStorage.getItem('v5_cma_amount')` 한 키만 **읽어** `getter(key)`로 `portfolio-reader`에 전달 → `advisor-bridge` → `briefing-model`. 쓰기 호출(setItem 등)은 정적 시험이 금지.
- 모듈 하나가 없거나 오류여도 해당 패널만 "사용할 수 없음"으로 표시되고 앱은 정상(시험됨).
- 오늘의 투자 브리핑: ①상태(총자산·공격/방어·현금·집중) ②위험 ③매수 후보 ④의견(근거·반대 근거·미확인). 검증 시세가 없으면 모든 종목 **판단 보류**. "시장을 지속 감시"한다고 표시하지 않음.
- 실제/합성: 기본은 내 기록(실제). "합성 예시" 모드는 별도 배너로 구분.

## 역할 구분
| 구분 | 역할 | 데이터 전송 |
|---|---|---|
| 규칙 엔진(신규) | 검증된 데이터로 정량 점검·위험 신호 | 앱 안에서만 계산, 외부 전송 없음 |
| Gemini(기존) | 사용자가 직접 요청한 질문의 설명·분석 | 사용자가 실행할 때만. 참모 화면은 보유정보를 자동 전송하지 않음 |
| 최종 판단 | 사용자 | — |
충돌 비교: Gemini 답변을 사용자가 붙여넣으면 `opinion-conflict`가 로컬에서 규칙 엔진 의견과 대조해 일치/충돌과 근거 없는 숫자를 표시(네트워크 요청 0, 시험됨).

## 백업 v6
백업 모듈(backup/core.js, ui.js)은 24단계 커밋과 바이트 동일(정적 시험). AI 모듈 강제 오류·모듈 파일 로드 실패 상황에서도 백업 화면이 동작함을 시험. **실제 사용자 백업 파일을 확보하지 못해 실백업 복원 리허설은 하지 않았고 했다고 보고하지 않습니다.**
