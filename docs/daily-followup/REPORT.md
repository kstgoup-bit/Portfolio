## 1. 코스피200 ETF 이력

기존에 설정된 GAS 주소의 `type=history&tickers=069500&market=KR`를 KS200의 첫 경로로 연결했다. 새 서버나 키를 추가하지 않는다. GAS가 없거나 응답이 잘못됐거나 저장 이력보다 과거이면 기존 Yahoo 경로로 대체한다. QQQ/SPY와 명시적 새로고침 시 기존 키를 사용하는 직접 Alpha Vantage 대체 경로는 유지한다.

- 설정 주소는 HTTPS `script.google.com/macros/s/<deployment>/exec`만 허용하며 주소를 공개 프록시로 전달하지 않는다.
- 응답의 종목·통화·거래소·시간대·ETF 종류·출처·조정 상태·개수·날짜·가격을 검증한다.
- `{d,c}` 막대를 기존 `v5_benchHistV2`에 날짜 관측으로 저장한다. `providerBarTs:null`을 유지하고 임의 마감 시각을 만들지 않는다. 원본 `v5_benchHist`는 바꾸지 않는다.
- 출처는 `yahoo-chart-v8-via-gas`, 비공식/배당·분할 조정 미검증이다. 당일 막대는 잠정값이며 공식 종가나 최신성으로 인증하지 않는다. 과거 날짜값도 당시 가용성이 확인되지 않은 참고 관측이다.
- 8초 JSONP 제한, 오류·복원·중복 클릭·새 조회·전체 타임아웃 뒤 콜백/스크립트 정리, 늦은 응답의 중복 저장 방지를 시험했다.
- GAS는 기존 JSONP 계약이므로 설정된 서비스에서 실행 가능한 스크립트를 받는 구조다. 이 변경은 그 서비스의 신뢰성이나 데이터 이용 권리를 인증하지 않는다.

실제 069500 245봉·QQQ 251봉 응답은 검토 문서의 요약만 확인됐다. 전체 원문이 없으므로 **시험 고정값은 모두 합성 자료**다. 실제 표본 시험이라고 표시하지 않았고, 새 실호출도 하지 않았다.

## 2. 보유 수량 변화와 참고 수익률

보유 수량 변화만으로 기간 전체 Dietz·알파를 비우지 않는다. 기록된 평가액과 외부 입출금으로 계산 가능한 경우 **미검증 참고값**으로 표시한다.

- 각 수치 옆에 `미검증 참고값`을 붙인다. 표와 차트에 `보유 변화 미검증`, `예수금 지연 수정·자산 제외로 수치가 왜곡될 수 있음`, `기록된 외부 입출금만 반영 · 누락 여부 미검증`을 표시한다.
- 예수금은 며칠 뒤 수정될 수 있으므로 수량 변화와 예수금 증감의 상쇄를 매매 근거로 추정하지 않는다. 외부 입출금이나 거래 내역을 새로 만들지 않는다.
- 내부 매수/매도는 외부 자금 흐름에서 제외한다. 명시적으로 기록된 외부 입출금만 Dietz 분자와 가중 분모에 적용한다.
- 기록되지 않은 외부 입출금은 시스템이 알아낼 수 없다. 입출금 기록과 평가액/예수금이 불완전하면 표시값이 실제 성과와 크게 다를 수 있다. 0원 흐름을 확인했다는 뜻이 아니다.
- 명시적 흐름 배열 누락·손상·중복·시각 미확정, 잘못된 가격/환율/평가기록, 명시된 전환 근거 불일치, 알려진 추적범위 변경은 계속 보류한다. 통화·기간이 맞지 않거나 ETF 자료가 없으면 알파도 보류한다.
- `signalHold:true`, `quality:'unconfirmed'`를 유지한다. 수치 표시가 매매 신호를 승인하지 않는다.

추가로 기존 앱의 잘못된 입출금 JSON을 빈 배열로 바꾸는 메모리 초기화 경로가 수익률에 영향을 줄 수 있음을 확인했다. 이제 표·차트·호환 Dietz 함수는 **저장된 입출금 자료를 검증해 읽고**, 읽기/검증 실패를 0원 흐름으로 바꾸지 않는다. 저장 키 자체가 없으면 기록된 흐름 없음으로 처리하되 누락 여부 미검증 경고는 유지한다.

## 3. 원본과 되돌리기

실제 투자기록, 과거 누락 날짜, 예수금, 보유 내역을 수정·추정·소급 작성하지 않았다. 백업 버전 7과 저장 키 집합은 그대로다. 새 안내문 4곳의 밝은 회청색은 `#333`으로 바꿨다.

**운영 반영이 별도로 승인된다면, 반영 직전에 구형 운영 앱에서 v6 전체 백업을 내려받아 별도 보관해야 한다.** 파일이 생성·읽기 가능한지 확인하고 원래 앱 버전도 보존한다. 구형 앱은 v7을 읽지 못하므로 되돌릴 때는 구형 앱 + 그 v6 백업을 사용한다. 실제 복원은 별도 승인·미리보기·확인 절차로 진행하며 자동 복원을 수행하지 않는다. v6 백업 이후의 새 기록은 그 백업에 없으므로 복원 전 보존 계획이 필요하다.

## 5. 미검증과 정확한 차단 사유

1. 전체 `npm test`: 네트워크 가드를 붙여 시작했으나 구형 시험의 `api.tiingo.com` 요청 시도가 실행 검토기에서 차단됐다. 완료 결과가 없으므로 전체 통과로 주장하지 않는다. 재시도하지 않고 저장소가 기존부터 명시한 5개 네트워크/CLI 시험 제외 목록의 오프라인 회귀만 사용했다.
2. 실제 Chromium 레이아웃 시험: 합성 표 조각만 로드하는 스크립트를 준비했으나 환경에서 Unix socket이 허용되지 않아 브라우저가 시작 전에 종료됐다(`socket() failed: Operation not permitted`). JSDOM 동작 검증은 통과했지만 실제 렌더링·모바일 터치/화면 배치는 미검증이다. 별도 접근 권한이나 허용된 브라우저 환경에서 재검증해야 한다.
3. 실제 GAS 연결, 전체 실제 응답 계약, 제공자의 이용 권리, 실기기, 실제 투자자료 이관/복원은 미실시다.
4. push, PR, main 병합, 운영/GAS 배포, 실키 사용, 실제 외부 API 호출은 하지 않았다. 운영 반영과 실호출에는 필요한 승인이 별도로 남아 있다.
