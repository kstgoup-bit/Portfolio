## 결론

사용자가 선택한 ‘가’의 범위에서 **도구 코드가 원본을 손실·손상시키거나, 허용한 보존 범위의 값을 조용히 바꿔 내보내는 차단급 결함은 확인되지 않았다.** 현 v3를 사본 확보에 사용하는 데 코드 수정이 필수인 근거는 없다.

단, 사본 확보의 완료 조건은 녹색 체크만이 아니다. **4계좌 종목 수가 평소 앱과 같고, 재열기 결과가 ‘지금 폰 자료와 완전히 같습니다.’인 파일을 보관**해야 한다. ‘다릅니다’ 또는 읽기 실패이면 최신 사본 확보를 끝낸 것으로 보지 않고 다른 앱 탭을 닫은 뒤 도구를 새로 열어 다시 내려받는다. 이는 별도 장치 개발 없이 현재 화면으로 수행할 수 있는 확인이다.

## 재열기 문구의 정확한 의미

170~172행에서 파일 무결성과 현재 저장값의 일치는 별개다. 합성 시험에서 내려받은 뒤 `v5_ledger`를 바꿨을 때도 ‘✅ 파일 정상’과 ‘지금 폰 자료와 다릅니다’가 함께 표시됐다. 현재 저장소를 읽지 못해도 같은 ‘다릅니다’ 분기로 간다.

이것은 파일 바이트가 손상됐다는 뜻은 아니다. 다만 녹색 체크만으로 다음 반영을 시작하면 변경 전 파일을 최신 사본으로 오인할 수 있다. 위의 **‘완전히 같습니다’ 확인 조건**으로 이번 절차에서는 차단할 수 있다. UI를 추가 개선한다면 불일치·읽기 실패 때 녹색 완료 대신 재확인 경고를 주는 것이 최소 수정이며, 본 검토에서는 원격 코드를 바꾸지 않았다.

## 실행한 시험과 한계

- exact SHA의 기존 jsdom 시험: **7/7 통과**.
- 별도 독립 jsdom 시험: **17/17 통과**. 고정 28개 키+계산기 24개 총 52개 쌍 원문 일치, 한글·개행·특수 Unicode·추가 계좌 필드 보존, 제외 값 미읽기, 저장소 쓰기 0회, 손상·중복·정렬 오류·키 누락·수량 오류·현재 값 변경을 확인했다.

- 실제 Chromium은 실행 환경의 내부 소켓 제한으로 브라우저 시작 전에 실패했다. 따라서 이번 검토에서 Chromium·모바일 화면 재검증이 통과했다고 주장하지 않는다. Space 보고서의 Chromium 및 전체 1926개 시험 결과는 클로의 보고이며, 여기서 재실행한 결과와 구분한다.
- 서비스워커 경로·실기기 수집·실복원은 사용자 결정대로 이번 범위에서 제외했다. 해당 한계를 이유로 새 장치를 요구하거나 사본 도구의 차단급 결함으로 분류하지 않았다.

## 사본과 복원의 구분

이 파일은 선택한 저장값의 원문 보관 사본이다. 기기 출처 증명, 모든 원본 값의 업무적 정확성, 자동 복원 성공을 인증하지 않는다. API 키·비밀번호·GAS 주소·다른 앱 자료·현재 보유에서 제외된 계산기 값은 보존 범위 밖이다. 기존 백업 가져오기 버튼에 이 raw-v3 파일을 넣어 복원을 시도하지 않는다. 복원은 사용자 결정대로 필요 시 별도 승인·도구로 진행한다.

이 검토에서는 운영 반영, 원격 파일 수정, 실제 자료 열람·변경, 서비스워커 변경, 복원 작업을 수행하지 않았다.
