# KST 투자관리시스템 15단계 개발 지시서

작성일: 2026-10-29
상태: 개발 착수용 제안서 — 실제 구현·시험 완료를 의미하지 않음

## 1. 목표
KST를 단순 곡소리·환호성 종목 탐색기에서, 실제 투자기록의 정확성·집중투자 위험·신호의 사후 성과를 검증하는 개인 투자관리시스템으로 발전시킨다. 완성도를 유지하면서 개발 속도를 높이기 위해 서로 연관된 세 작업을 하나의 독립 개발 단계로 병행한다.

## 2. 선행 조건 및 작업 범위
- 14단계의 모바일 안전조회 및 회귀시험 결과를 확인한 후 그 **검증된 최신 개발 브랜치와 커밋**을 기준으로 새로운 독립 브랜치를 생성한다. 기준 SHA는 실제 확인 후 기록하며 추측하지 않는다.
- 이전 단계에서 독립 검증된 13단계 단위시험 450개 통과는 역사적 기준일 뿐, 15단계 통과를 보증하지 않는다. 14단계의 실제 기준 시험 수를 확인해 회귀시험한다.
- `main` 변경·병합, 운영 배포, 유료 시세 API 가입·호출, 자동매매, 실제 계좌 거래, 외부 전송, 사용자 원본 투자기록 변경·삭제는 금지한다.
- 실제 투자기록을 시험에 사용할 때는 별도 격리 사본과 가명·합성 데이터를 우선 사용한다. 백업·복원 호환성을 반드시 보존한다.
- API 키, 인증 토큰, 비밀번호, 원본 개인 거래내역을 GitHub/로그/보고서에 포함하지 않는다.

## 3. A 작업 — 투자기록 및 손익 계산 검증
1. 계좌별·통합 매수/매도, 수수료, 세금, 배당, 환율, 주식분할, 종목 변경 등 기록 구조를 점검한다.
2. 평균단가·보유수량·실현손익·평가손익·총수익률을 검증 가능한 순수 계산 모듈로 분리한다.
3. 국내·해외, 일반·연금저축·IRP 계좌의 과세·비용 차이를 구분한다. 세법이나 원천징수 정보가 불명확한 항목은 추정치로 표시하고 임의 확정하지 않는다.
4. 현금 입출금과 투자 성과를 구분하며, 필요 시 단순수익률과 현금흐름 반영 수익률(XIRR 또는 TWR)을 별도로 제시한다.
5. 과거 기록이 부족할 때는 수치를 만들어내지 말고 `계산 불가/자료 부족`으로 표시한다.
6. 수수료·세금·환율·배당·분할·부분매도·동일 종목 재매수·손익통산 등 경계 사례를 자동시험에 포함한다.

## 4. B 작업 — 집중투자 위험관리 화면
1. 전체 자산 및 계좌별 종목 비중, 산업·테마별 중복 노출을 표시한다. 동일 종목 직접 보유와 ETF 간접 노출은 데이터가 있을 때만 합산하며, 모르면 `미확인`으로 표시한다.
2. 사용자가 하락률을 입력하면 특정 종목/산업군/전체 자산의 예상 손실액과 비율을 계산한다. 가정·계산식을 화면에 명시한다.
3. 특정 종목 비중 경고 기준을 사용자 설정값으로 두고, 경고가 자동 매도 지시처럼 보이지 않도록 한다.
4. 매수 근거·반증 조건·실적 점검일·투자 판단 변경 이력을 사용자가 직접 기록하는 체크 기능을 제공한다.
5. 360/390/430px 모바일 화면에서 금액·단위·경고 문구·버튼을 확인한다.

## 5. C 작업 — 곡소리·환호성 백테스트 엔진 1차
1. 실제 과거 가격 데이터를 합법적으로 확보한 경우에만 `실데이터 백테스트`라고 표시한다. 데이터가 없으면 합성 자료로 계산기와 화면만 시험하며 성과를 주장하지 않는다.
2. 신호 발생 시점에 이용 가능했던 정보만 사용하여 미래정보 누출(look-ahead bias)을 방지한다.
3. 배당·주식분할·상장폐지·거래정지·생존편향, 매매 수수료·슬리피지·환전 비용 등 반영 여부를 메타데이터로 기록한다. 미반영 항목은 결과 화면에 경고한다.
4. 곡소리/환호성 각 규칙별 신호 발생 횟수, 1·3·6·12개월 후 수익률, 승률, 중앙값, 최대낙폭, S&P500 등 비교지표 대비 초과수익을 산출한다. 관찰 기간이 부족하면 제외·표기한다.
5. 훈련·검증 기간을 분리하고 매개변수 과최적화를 경계한다. 표본 수가 작거나 성과가 불충분하면 `검증 부족` 또는 `전략 재검토`를 명확히 표시한다.
6. 원시 데이터 출처·시점·조정 여부·규칙 버전·계산 설정을 저장해 같은 결과를 재현 가능하게 한다.
7. 백테스트 결과를 매수 추천이나 미래 수익 보장으로 표현하지 않는다.

## 6. 시세 공급자: 소규모 읽기 전용 파일럿 설계
- 후보 종목: MSFT, GOOGL, AVGO, VRT, JPM (실제 보유 여부와 무관한 검증용 예시).
- 1개월간 공급자 가격과 독립 기준값의 일치 여부, 결측·지연, 조정주가·배당·분할 처리, 호출량·예상 비용, 사용권·저장권을 점검하는 계획과 설정 화면까지만 구현한다.
- **실제 유료 API 개통·실호출·외부 전송은 별도 명시적 승인 후에만 수행한다.**
- KRX 종목 식별 조회는 가격 제공과 다르므로 두 기능을 혼동하지 않는다.
- 실제 활성 감시 종목 수와 합성·캐시·실조회 종목 수를 분리해 보고한다.

## 7. 품질·보안·시험 합격 기준
- 기존 테스트 전부 통과, 신규 계산·경계·복원 시험 추가, 실패 0건. 시험 수와 실제 실행 명령·환경을 기록한다.
- 거래기록 가져오기/내보내기/백업/복원 시 원본 무변경, 데이터 누락·중복 없음 검증.
- 가격 공급자 비활성 상태에서 앱 정상 작동, 네트워크 실패 시 기존 기록 안전 보장.
- 모바일 25묶음 또는 최신 기준의 동등·상위 시험을 재현하고, 실제 기기 시험과 자동화 시험을 구분한다.
- 실제 시세를 확인하지 않았으면 `실제 시세 검증 0건`, 실제 백테스트를 하지 않았으면 `실데이터 백테스트 0건`으로 명시한다.

## 8. 납품물
1. 전체 소스 ZIP 및 변경 패치, 새 브랜치명·커밋 SHA·Draft PR 링크(가능한 경우)
2. 개발 보고서: 구현 범위, 미구현 범위, 알려진 한계와 위험
3. 단위·회귀·모바일 시험 결과 및 재현 명령
4. 투자기록 계산 검증표와 합성 사례별 기대값/실제값
5. 위험 화면 스크린샷 또는 확인 가능한 UI 결과
6. 백테스트 데이터 계약·편향 방지 설계·합성 시험 결과
7. 공급자 파일럿 비용/권한/정확도 검증 계획
8. 실제 활성 감시 종목 수, 실데이터 백테스트 수, 미완료 항목

## 9. 실행 순서와 속도 원칙
- 1차: 현행 데이터 구조·백업·테스트 기준선 확인, 인터페이스 설계.
- 2차: A 계산 엔진과 B 위험 화면을 병행 개발, C 백테스트 데이터 계약·순수 계산 엔진 병행 개발.
- 3차: 합성 자료 기반 통합시험·모바일 회귀시험·보안 점검.
- 4차: 결과 보고 및 독립 검토. 검증된 작업만 완료 처리.

**완료 판정:** 투자기록 무결성·기존 기능 회귀시험·모바일 안전성·합성 백테스트 재현성이 모두 확인되어야 한다. 실데이터 연결이나 실제 투자 성과 검증은 별도 완료 조건으로 구분한다.
