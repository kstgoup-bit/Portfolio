# 실사용 앱 vs 별도 실험실 격차표 (17단계 작업 B)

**결론: 실험실(mobile-lab) 기능은 실사용 앱에 통합되지 않았다. "통합 완료"가 아니다.**

## 코드 수준 추적
- 실사용 진입점: `portfolio_v5.html`(start_url). 불러오는 스크립트: `radar/{providers,verification,core,ui}.js`, `backup/{core,ui}.js`, 인라인 2블록.
- `portfolio_v5.html`, `service-worker.js`, `manifest.json` 안에 `mobile-lab`·`invest/`·`kr-radar` 참조 **0건**(grep).
- 서비스워커 캐시 대상: 앱 HTML, 매니페스트, 아이콘 2개뿐 — 실험실은 캐시되지 않음(그래서 오프라인 새로 열기 불가).
- 저장: `v5_*` 키(계좌 4개 `v5_gen/dom/ov/pen` 등). 백업: `backup/core.js` 형식 `kst-portfolio-backup` v6, 허용 키 목록 방식(비밀키 제외).
- 주의: 앱에는 이미 `v5_ledger` 키가 있으나 **월별 가계부용**이다. 새 거래원장은 이 키를 쓰면 안 된다(충돌).

## 기능 격차
| 기능 | 실사용 앱 | 실험실 | 상태 |
|---|---|---|---|
| 포트폴리오 4계좌·배당·메모·백업 v6 | 있음 | 없음(읽지 않음) | 앱 전용 |
| 거래원장(평단·실현손익) | 없음(상태값 중심) | 있음(15단계, 합성) | 실험 |
| 집중투자 위험·최악 시나리오 | 부분(레이더 화면) | 있음 | 실험 |
| 곡소리·환호성 감시 | `radar/` 구형 화면 | `kr-radar` 신형, 정직 집계 | 둘 다 실가격 없음 |
| 초안 저장 | 없음 | 있음(별도 키) | 실험 |
| 이름 HAS | 반영(17단계) | 실험실 화면 문구는 KST 표기 유지 | 부분 |
| 실제 가격 | 구형 코드가 외부 시세 호출 시도(앱 기존 동작) | 호출 불가(CSP) | 별개 |

## 통합 순서 제안 (작은 단위, 각 단계 승인)
1. 실험실 계산 모듈의 **읽기 전용 보기**를 앱에 추가(앱 데이터 읽기만, 쓰기 없음).
2. 거래원장 입력/내보내기(별도 키 + 백업 확장은 승인 ②).
3. 위험 카드(최악 시나리오) 앱 상단 고정.
4. 감시 화면 교체(실가격 승인 ① 이후).

## 발견 사항 (수정하지 않음 — 보고만)
- 앱 CSS에 9~10px 글자·옅은 색(`rgba(…,0.55)` 등)이 다수 있어 "12px 이상·진한 색" 원칙에 어긋난다. 별도 승인 후 정리 권장.
- 소스에 기본 비밀번호 상수가 들어 있다(저장소 비공개 전제). 공개 저장소로 바꾸면 안 되며, 암호 방식 개선은 별도 승인 항목.
- 앱은 기존에 외부 시세/AI 호출 코드를 갖고 있다(앱 기존 기능, 17단계에서 호출하지 않음). API 키가 localStorage에 저장되는 구조이며 백업에서는 제외된다.
