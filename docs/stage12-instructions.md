## 3. 작업묶음 A — 공식 종목정보 조회와 73개 후보 검증

### A1. 설계·보안

- 기존 `kr-radar/krx-api.js`, `kr-radar/identity.js`, `tools/kr-krx-verify.cjs`를 우선 재사용한다. 구조를 먼저 파악하고 중복 어댑터를 만들지 않는다.
- 공공데이터포털 `GetKrxListedInfoService_V2/getItemInfo_V2` REST 조회: `https://apis.data.go.kr/1160100/GetKrxListedInfoService_V2/getItemInfo_V2`.
- 인증키는 **개인 PC 또는 비공개 실행 환경의 환경변수/비추적 로컬 설정**에서만 읽는다. 공개 웹앱 클라이언트에 키를 넣지 않는다. URL·예외·로그·덤프에 키가 남지 않게 마스킹한다. 키 없는 기본 실행은 fixture-only/OFF.
- 실제 호출은 `--live` 등 명시적 선택 + 사용자 별도 승인 + 본인이 로컬에 키 설정한 경우에만 가능하도록 한다. **이 지시서 자체는 실조회 승인이 아니다.** 이 대화나 클로에게 키를 보내라고 요청하지 않는다.
- 시간초과, 401/403/429/5xx, 일시적 실패와 영구적 실패, 재시도 횟수·백오프·호출 총량(초기 파일럿 최대 20회), 페이지 누락·중복·부분 실패, API `resultCode`, 비정상 JSON/XML, 빈 결과, 날짜(`basDt`)·조회시각 차이, 업데이트 지연을 처리한다. 1~3회 소규모 호출 계획을 먼저 준비하되 실제 실행은 승인 후.
- 원본 응답과 내부 정규화·검증 결과를 별도 보관하고 출처·기준일·조회시각·해시·검증 버전을 기록한다. 공개 GitHub에는 합성 fixture와 비식별 집계만 포함한다.

### A2. 종목 검증

- 11단계의 **국내 개별주 후보 73개**를 원본으로 고정하고, **ETF 5개**는 별도 집계한다. 나머지 27개를 임의로 채우지 않는다.
- `srtnCd`의 `A` 접두사 처리, 종목명, `mrktCtg`, `isinCd`, `basDt`의 비교 규칙과 우선순위, 다중 후보/중복 충돌 처리, 상장폐지·시장 이동·이름 변경, 우선주 미제공 등 예외를 명시한다.
- `VERIFIED / MISMATCH / PENDING / EXCLUDED`는 근거와 기준일이 있을 때만 산정한다. 실제 공식 응답을 조회하지 못하면 VERIFIED 0을 유지한다. 미검증 상태에서 매수·매도 신호를 활성화하지 않는다.
- 검증 결과는 로컬 비공개 산출물로 제공하고, **실제 주가 확인 종목 수 및 활성 감시 종목 수와 절대 혼동하지 않는다**.

## 4. 작업묶음 B — 실제 시세 공급자 선정과 파일럿의 실행 가능한 설계

- 필수 비교 항목: 개인 사용 가능 여부, 비상업/재배포/파생 지표 저장·표시 권리, 무료/유료 구간과 호출 한도, 미국·한국 종목 지원, 종가·OHLC·거래량, 수정주가(분할·배당), 거래소 휴장일/시간대, 데이터 지연·수정, 상장폐지/심볼 변경, 장애·SLA, 보안·비용 위험.

- 공급자 인터페이스·스키마를 합성 fixture로 구현/검증한다. 데이터 provenance(공급자·시각·세션·통화·수정여부), 오래된/누락/서로 다른 가격, 52주 최고가의 수정주가 기준, 분할·배당, 벤치마크와 비교 시점, 매수·매도 충돌 시 보류를 설계한다.
- 결과는 **권장 1순위/대안/선택 보류 사유**, 예상 월간 호출량·비용 범위, 최소 파일럿 승인 체크리스트로 제시한다. 데이터 접근이 없으면 설계만 완료라고 표시한다.
