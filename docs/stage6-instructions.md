## 2. 이번 단계의 목표 (작업 범위를 좁게 유지)
### A. 원격 소스 기준선 검증
1. GitHub의 개발 브랜치가 위 커밋인지 확인한다.
2. `delivery.json`의 `sourceSha256`와 원격 파일 내용을 가능한 범위에서 대조하고, 불일치·검증하지 못한 파일을 구분해 보고한다.
3. `npm ci`, `npm test`, `npm run test:mobile` 및 검증 도구를 실행해 기존 182개 단위시험·25개 모바일 묶음 기준선이 유지되는지 확인한다. 실제 실행하지 못한 시험은 통과로 표기하지 않는다.

### B. 실제 주가 연결에 필요한 최종 사전 점검
1. MSFT, GOOGL, AVGO, VRT, JPM 다섯 종목의 실제 정규장 종가·조정 52주 고가·기준 거래일·분할/배당 조정·비교 ETF(SPY/업종) 데이터에 필요한 필드와 출처를 명확히 정의한다.
2. Alpha Vantage, Twelve Data, Massive 중 본인 개인용 화면 표시, 가공·저장, 지연·호출한도, 무료/유료 여부와 200종목 확대 가능성을 **공식 약관·문서 기준으로** 비교한다. 불명확한 권리는 미확인으로 표시한다.
3. 승인된 이용권과 안전한 인증 주입이 없다면 실제 API를 호출하지 않는다. 기존 앱 localStorage의 API 키를 읽거나 재사용하지 않는다. 실제 데이터가 없으면 활성 감시 종목은 0개로 유지한다.
4. 기존 `radar/providers.js`와 `radar/vendor-massive.js`의 합성 계약 시험을 강화할 수 있으나, 합성값을 실데이터로 표시하지 않는다. 새로운 유료 서비스나 비밀값 저장 구조를 생성하지 않는다.

### C. 매수·매도 통합 투자관리시스템의 다음 설계
1. 계좌별 정책: 연금 장기 코어와 해외 직접투자 새틀라이트를 구분한다. 종목별 목표 비중, 고평가, 투자 논리 훼손, 집중 위험, 교체 기회는 **정보 제공/검토 신호**로만 다룬다.
2. +20/+30/+50/+100/+200% 상승률은 알림·검토 기준일 뿐 자동매도 기준이 아니다. 데이터 결측·오래된 가격·불확실한 기업 가치평가는 '평가 불가'로 표시한다.
3. 중기 목표는 5년 내 투자자산 10억 원이며, 그 후에도 장기 성장·안정적 노후 현금흐름을 추구한다. 목표 달성 가능성을 보장하거나 무리한 레버리지를 유도하지 않는다.
4. 실제 보유 계좌 연동, 세금 계산, 실데이터 신호 활성화는 이번 단계에서 하지 않는다. 합성 데이터 설계 및 테스트까지만 진행한다.
