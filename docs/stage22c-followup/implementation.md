# 기본 조회 처리 흐름 구현과 경계

신규 `kis-basic-policy-stage22c-followup.cjs`는 기본 개인 일시 조회를 진행 대상으로, 저장·장기 보존·재배포·독립 대조를 분리 보류로 분류한다. 이 분류는 문서 검토 결과이며 런타임 자격증명이나 법적 권한을 발급하지 않는다. 개발 허용을 실조회 준비 완료로 해석하지 않는다.

`kis-request-spec-stage22c-followup.cjs`는 기존 검증된10종목 계획으로부터 고정 HTTPS9443 목적지의 공개 요청 명세를 구성한다. 경로·TR·인자 변조, 주문·잔고 경로, 추가 키·토큰 필드는 거절한다. 인증 헤더 이름만 포함하며 값은 없다. 해외 AUTH 인자는 빈 값으로 고정된다. 중첩 계획까지 복제·동결하여 검사 후 변경을 막는다. 자동 리다이렉트·재시도·페이지 이동은 모두 금지로 명시한다.

`kis-fixture-runner-stage22c-followup.cjs`는 합성 전용 응답 콜백을 실행하는 처리 흐름이다. 실제 HTTPS 전송기·로그인·토큰 발급·키 입력·환경변수 읽기 기능을 추가하지 않았다. live 모드는 거부한다. 요청 전 장부 예약 → 합성 콜백 → 상태/응답 검증 → 완료 기록 순서이며 예약 실패 시 콜백을 실행하지 않는다. 실패·타임아웃도 차감하고 완료 기록 실패 시 가격 반환을 억제한다. 동시에 두 요청을 실행하지 않으며 401/403·리다이렉트·스키마 오류·미확인429는 세션을 중단한다. 재시도 조언은 호출이 아니고 명시적 재시도도 새 예약을 소모한다. 추가 페이지를 자동 호출하지 않는다.

타임아웃은 최대10초, AbortSignal을 합성 콜백에 전달한다. 콜백이 취소를 준수하는 실제 네트워크 전송기라는 보장은 없으므로 실전 연결·취소·소켓 정리는 별도 검증해야 한다. 합성 장부는 테스트 전용이며 실제 승인 예산을 사용하지 않는다. 실제 인증과 다른 공급자까지 추가할 때는 기존 전체 장부를 공유하고, 숨은 재시도/토큰 갱신을 포함하여 누락 없이 예약해야 한다.

정규화는 기존 합성 검증기를 이용한다. 모든 결과는 realVerified=false·held=true·signalEnabled=false를 유지한다. 원응답·오류 메시지·키·토큰을 결과나 장부에 복사하지 않는다. 가격은 합성 결과 메모리로만 반환하며 가격 디스크 저장·독립 대조를 호출하지 않는다. 기존 앱 HTML·저장소·백업·인증·PWA를 변경하지 않았다.

이 작업은 실제 전송기 완성 또는 실제 시세 연결 성공을 의미하지 않는다. 안전한 인증 수단이 준비됐을 때 이를 연결할 별도 전송 경계 구현·시험이 남는다. 사용자는 이미 무료·총40회 조건부 실조회를 승인했으므로 이 범위에 대해 고객센터 답변이나 반복 승인만을 일괄 요구하지 않는다. 다만 실제 인증·계정 무료 권한·네트워크 준비라는 기술적 조건은 확인해야 한다.
