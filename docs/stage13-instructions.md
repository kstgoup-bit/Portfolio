### 2. 작업 묶음 A — KRX 실증을 실제로 완료할 수 있는 상태로 만들기
1. 기존 `tools/krx-live-runner.cjs`와 `kr-radar/krx-run.js`, `krx-status.js`, `krx-api.js`의 호출 계획, `basDt`, 페이지네이션, 중복·결측·ISIN 불일치, 영업일 지연, 부분 재개, 응답 스키마를 코드 수준에서 재검토한다.
2. **실제 JSON/XML 응답을 아직 확인하지 못했다는 사실을 유지**하고, 형식 불일치·응답 오류·빈 응답·부분 수신·인증 실패·요청 제한 등 부정시험을 추가한다.
3. 사용자 PC에서 안전하게 실행할 수 있도록 **초보자용 Windows PowerShell 및 macOS/Linux 안내**를 작성한다. Windows 키 입력은 `Read-Host -AsSecureString` 등 화면 노출을 줄이는 방식을 검토하되, 실행기의 환경변수 요구와 호환성을 시험한다. 비밀값을 명령 기록·스크린샷·로그에 남기지 않는다.
4. 실행 전 점검 명령(기본 OFF), 1~3회 호출 제한 승인 파일 예시, 저장소 밖 출력 경로, 오류 시 중단·키 삭제·원본 비공개 보관/삭제 방법을 명확히 제공한다.
5. 사용자가 **별도 승인한 경우에만**, 본인 PC에서 로컬 실행하고 **비밀값이 제거된 상태 합계·출처·기준일·해시**만 공유하도록 안내한다. 승인 전에는 합성 응답으로 끝까지 리허설한다.
6. 국내 후보 73개와 ETF 5개를 분리하고 VERIFIED/MISMATCH/PENDING/EXCLUDED 상태를 산출한다. 실제 조회가 없으면 VERIFIED=0 유지; 100개 목표 부족 27개를 임의로 채우지 않는다. 우선주가 공식 API 범위에서 제외된다는 한계를 명시한다.
7. 공식 종목 신원 검증은 **주가 검증·매수 신호 활성화가 아님**을 코드와 보고서에 명시한다.

### 3. 작업 묶음 B — 미국·한국 실제 시세 연결의 검증 가능한 파일럿
1. 12단계 `docs/provider-selection-stage12.md`와 `kr-radar/pricefeed.js`를 출발점으로 공급자별 **공식 문서**에서 종가/시가/고가/저가, 수정주가, 분할·배당, 52주 고가, 거래소·휴장일, 과거 데이터 범위, 호출한도, 개인 사용 및 표시·저장 권리를 점검한다. 확인일·URL·불명확한 항목을 기록한다.
2. 미국 파일럿 후보 MSFT, GOOGL, AVGO, VRT, JPM. 한국 파일럿은 KRX에서 실제 VERIFIED된 후보 중 최대 5개로 제한한다(미검증이면 종목 확정 보류).
3. 공급자 인터페이스는 기본 OFF, 합성 fixtures 기반으로 구현·시험한다. 실제 시세 API 호출, 무료 키 발급도 자동 진행하지 않는다.
4. 기준일·시장시간대·휴장일·수정/비수정 혼합·액면분할·상장폐지·거래정지·누락봉·오래된 봉·이중 공급자 차이·환율·ETF/개별주 구분을 부정시험에 포함한다.
5. 공급자 데이터가 부족하거나 이용권이 불확실하면 `DATA_UNAVAILABLE` 또는 `HOLD`로 종료하고, 52주 고가나 매수·매도 점수를 꾸며내지 않는다.
6. 실거래 주문 인터페이스를 추가하지 않는다. 신호 점수는 **백테스트 미검증 가설**로 표기한다.

### 4. 작업 묶음 C — 개인 투자기록·백업·모바일 품질
1. 기존 **410/410 단위시험과 모바일 25묶음**을 기준 브랜치에서 재현한 뒤 신규 시험을 추가한다. 시험 수 증가보다 결함 발견과 재현성을 우선한다.
2. 개인 투자기록, 연금/IRP/해외계좌 구분, 매수·매도 이력, 백업·복원·롤백·구버전 호환을 **합성 계좌 데이터**로 검증한다. 실제 사용자 로컬스토리지를 열거나 수정하지 않는다.
3. 360/390/430px 모바일 자동시험을 유지하고, 실제 안드로이드 기기에서 사용자가 확인할 체크리스트(오프라인 진입, 홈 화면, 뒤로가기, 백업 복원, 업데이트 후 데이터 유지)를 만든다. 실제 기기 시험을 수행하지 않았으면 '미실시'라고 기록한다.
4. 시크릿 스캔, Git 변경 파일 범위, 공개 PWA로 데이터·키 유출 가능성, 네트워크 기본 OFF, 오류 로그 마스킹을 검사한다.
5. 기존 기능 해시 또는 동등한 변경 영향 증거를 남긴다.
