# HAS 24단계 — 모바일 KIS 시세 연결 설계 검토 (제4과제)

작성일: 2026-11-05 · 실제 서버 생성 0 · 실전 API 호출 0 · 실전 키 접촉 0 · 이전 설계: `docs/mobile-kis-design-stage23.md`, `docs/kis-openapi-design-stage21.md`

## 0. 이번 단계의 확인 한계(중요)
- KIS 공식 API 문서·공식 GitHub 예제는 이 작업 환경의 접속 허용 목록 밖이라 **열람하지 못했습니다**(공식 GitHub 주소 조회가 "허용 목록에 없음"으로 거부됨). 비공식 해설 글 열람도 실패했고, 검색 결과는 제목만 확인되어 내용으로 쓰지 않았습니다.
- 따라서 아래 "공식 확인됨"은 **사용자가 이전에 보내준 약관·FAQ 화면 캡처**에서 읽은 것만입니다. 나머지는 모두 **미확인**이며 추정으로 확정하지 않았습니다.

## 2. 보안 원칙 이행 현황
- 실전 키를 HTML·JS·localStorage·GitHub·백업에 저장: **하지 않음.** 백업 모듈은 허용 목록 키만 저장하며 키·비밀번호·GAS 주소를 제외(시험 통과). 저장소 비밀값 검사 findings 0.
- 주문·계좌조회·자동매매: **구현하지 않음.** 중계 정책은 주문·잔고·토큰·계좌 경로를 허용 목록에서 제외하고 키워드로도 차단.
- 실제 서버 생성·실전 호출: **0.**

## 3. 중계 서버 7개 조건 ↔ 구현·시험
정책 코어 `has/relay-policy.js`(순수 함수, 서버 아님)와 `tests/relay-policy-stage24.test.cjs`(7개 시험 통과)로 규칙을 먼저 고정했습니다. 나중에 서버를 만들면 모든 요청이 이 함수를 통과해야 합니다.
| 조건 | 설계 | 코드·시험 | 남은 일 |
|---|---|---|---|
| 1 사용자 인증 | 서버 전용 비밀값을 `x-has-auth`로 확인(상수시간 비교). 앱의 잠금 비밀번호와 **별개**여야 함 | `authenticate` 시험(없음/틀림/길이 다름/정상) | 앱이 이 비밀값을 어디에 두는지(기기 저장은 탈취 위험) — 방식 승인 필요 |
| 2 시세 조회 경로만 허용 | 허용 목록: 국내 시세, 미국 시세, 환율 3종만. 그 외 전부 403 | 주문·잔고·토큰·계좌·경로 조작·POST 등 14+ 사례 거부 | KIS 실제 경로와의 대응은 공식 문서 확인 후 |

## 4. 키 유출 시 대응 절차(초안, KIS 절차 확인 전)
1. 중계 서버 즉시 중지(또는 정책 코어의 차단 상태 유지) 2. KIS 앱키 폐기·재발급(방법은 공식 확인 필요) 3. 최근 주문·접근 내역 점검(KIS 이용내역) 4. 새 키는 서버 비밀 저장소에만 등록 5. 앱 인증 비밀값도 교체.

## 5. 앱 쪽 준비(구현됨, 합성)
- `has/quote-model.js`: 시세 계약. 중계가 어떤 값을 줘도 미검증·출처/기준일 없음·오래됨은 신호·조언에 쓰지 않음.
- `has/quote-crosscheck.js`(신규): 공급자 2곳 이상 대조. 차이 1% 초과·기준일 불일치는 "충돌"로 표시하고 판단 보류(시험 포함). 공급자 1곳뿐이면 "대조 불가"로 남기고 검증으로 올리지 않음.
- 조회 실패가 투자기록을 바꾸지 않음: 앱 화면 시험(시세 조회 실패 시뮬레이션)과 해시 비교로 확인.

## 6. 결론과 다음 승인
- **휴대폰 단독 시세 조회는 지금 구현에 착수하면 안 되는 단계**입니다. 공식 명세 대조(항목 1·2·5)와 KIS의 개인용 중계 허용 해석(항목 6)이 선행 조건입니다.
- 사용자가 할 수 있는 일(권장 순서): ① KIS Developers 포털의 시세 API·앱키 관리 화면 캡처 전달 ② KIS 고객센터에 항목 4·6 문의 ③ 그 뒤에 승인 C-cloud(중계 서버 생성)를 판단.
- 필요한 승인 목록은 완료보고서 11항 참조.
