모든 시험은 합성 복제 저장소에서만 실행했다(실제 기기 데이터 복사·수정 0).

| 요구 | 시험(파일) | 결과 |
|---|---|---|
| 4계좌 합성 왕복(백업→복원)이 정확하고 계좌 간 섞이지 않음 | `regression-stage12` 합성 4계좌 왕복, 연금만 편집 시 해외 불변 | 통과 |
| 복원 실패 시 전부 원상 복귀, 성공 후 되돌리기 | `regression-stage12` rollback | 통과 |
| v4/v5 구백업 복원, 비밀키·레이더 키 비포함 | `regression-stage12` older versions | 통과 |
| 백업 v6 상수 유지, 새 투자기록 키는 허용 목록에 없음(스키마 무변경) | `integration-stage15` | 통과 |
| 백업 생성→파싱→위험·손익: 저장소는 읽기만 | `integration-stage15` | 통과 |
| 거래기록 내보내기/가져오기: 입력 무변경, 중복·누락 없음, 충돌 덮어쓰기 안 함 | `integration-stage15` | 통과 |
| 실제 앱 복원 미리보기·취소·적용·되돌리기, 저장 한도 실패 시 키 불변 | `mobile.cjs` 백업 묶음(360/390/430) | 통과 |
| 이름 변경 후 저장 데이터 동일 | `mobile-stage17` | 통과 |
| 가계부 `v5_ledger` 보호(새 원장은 다른 키) | 설계 + 허용 목록 시험 | 통과(설계 준수) |

## 원장 기능 현황 (`invest/ledger.js`)
구현·시험됨: 매수·매도·배당 일부, 평단, 실현손익, 원가 검증 44항목. **미구현(그대로 미구현으로 표기):** 주식분할(SPLIT), 계좌 이전(TRANSFER), 현금 입출금, 환전, 외화 환산 기준일 처리, 거래 정정 이력.

## 새 저장 키 `has_ledger_v1` 충돌·호환 검증 계획 (실데이터 없이)
1. 앱 전체 소스에서 `has_ledger` 문자열 사용 0건 확인(충돌 없음).
2. 백업 허용 목록(`JSON_KEYS`,`TEXT_KEYS`)에 없으므로 현재 백업/복원에 **포함되지 않고, 복원이 건드리지도 않음** → 영구 저장 승인(가) 전에는 쓰지 않음.
3. 승인 후 순서: 시험 사본에서 키 추가 → v6 백업 파일 생성 → 구버전 앱으로 복원 시 무시되는지 → 신버전에서 왕복 일치 → 롤백(키 삭제) 시험.
4. 계좌별 원가법·수수료·환율 기준일·정정/중복·과거 백업 복원: 설계는 `docs/has-ledger-invariants-stage17.md`, `docs/backup-schema-extension-design-stage16.md` 참조.
**실사용 `portfolio_v5.html`에 시범 보기는 이번에 추가하지 않았다(미완료·승인 대기).**
